# 需求分析子链约束增强方案 — 四层防御体系

## 问题诊断

AI 偏离 30-31-32 开发计划的根本原因：**决策停留在"人读文档"层，没有下沉到"机器执行"层**。

| 层次 | 现状 | 缺口 |
|------|------|------|
| 文档层（25-32） | ✅ 决策详尽 | 但只在文档里 |
| 规则层（.claude/rules/） | ⚠️ fullchain-sprint 只引用 §0.11 | PM≥85/题型/禁代问等**具体决策未内联** |
| Hook 层（guard-write.mjs） | ⚠️ 只查 R4-R8 通用安全 | **完全不覆盖需求分析业务约束** |
| 变更管控 | ❌ **完全不存在** | AI 改关键业务方法无需事先申请 |
| xUnit 守卫 | ❌ **无先例** | 架构漂移无测试检测 |
| CI 分析器 | ⚠️ 已有 6 条通用规则 | 无需求分析专属规则 |

## 核心设计：四层防御（每层覆盖前层漏过的场景）

```
事前审批 → 写时拦截 → 编译检测 → 测试守卫
  L0         L1         L2         L3
变更申请CR   guard-write  Analyzer   xUnit
(规则+hook)  新增L10层    新增JNPF007+ 新增守卫测试
```

**最核心的创新**是 L0"变更申请审批"——填补当前体系最大的缺口。

## 组件 2：guard-write.mjs 新增 L10 — 关键文件变更管控 + 业务模式拦截

**扩展文件：** `.claude/hooks/guard-write.mjs`

这是拦截力最强的一层，分两部分：

### L10a：关键业务方法变更审批检查
- 检测 `filePath` 是否命中"关键业务方法保护清单"
- 若命中：读 `.claude/workflow-state.json` 的 `cr-approved` 字段
  - 有对应已批准 CR → 放行
  - 无 → **exit 2 阻断**，错误信息提示"MUST 先提交 CR"
  - 豁免：写内容含 `// cr-safe: <理由>` → 放行（纯格式/注释修改）
- 复用现有的 workflow-state.json 读取模式（guard-finish.mjs L0 已验证可行）

### L10b：需求分析业务模式静态检测（.cs 文件）
检测 7 条禁令中可静态识别的违规模式：

| 检测 | 正则模式 | 违反禁令 |
|------|----------|----------|
| 编排器直连出题 LLM | 在 `RequirementAnalysisOrchestrator.cs` 中 `_llm.ChatAsync.*[Cc]larif\|_llm.*[Qq]uestion` | 禁令1 |
| 普通 SINGLE 题型赋值 | `QuestionFormat\s*=\s*["']SINGLE["']`（排除 MATRIX_SINGLE） | 禁令2 |
| 新建废止模块 | `class\s+(ScannerValidator\|EventDependencyBuilder\|PSpecEnhancer\b)` | 禁令5 |
| 复活 sa_ddd 表 | DDL `CREATE TABLE sa_ddd` | 禁令5 |
| cascadeUpdate | `cascadeUpdate\|EventDependencyBuilder` | 禁令5 |

- 阻断方式：exit 2 + 详细错误（规则号 + 文档引用 + 修复建议）
- 豁免：`// cr-safe: <理由>`（同 L10a 复用）

### 测试扩展
`scripts/test-hooks.mjs` 追加 ≥6 个用例（违规→exit 2 / 正常→exit 0 / 豁免→exit 0）

## 组件 3：xUnit 架构守卫测试

**新建文件：** `backend/tests/JNPF.Tests.PhaseB/ReqAnalysisInvariantGuardTests.cs`

这是**首个经典架构守卫测试**（项目无先例，参照 `Sg2EnterpriseUsabilityTests.cs` 的原生 `[Fact]` 风格）。用反射断言生产代码不变量：

### 测试用例（每个对应一条铁律）

| 测试方法 | 断言 | 防御的铁律 |
|----------|------|-----------|
| `Orchestrator_ShouldNotHoldLlmChatForClarification` | `RequirementAnalysisOrchestrator` 构造函数参数不含直接出题用的 `LlmGatewayService`（或检查字段类型） | 禁令1 出题权 |
| `ClarificationQuestion_ShouldNotHavePlainSingleAsDefault` | 枚举/DTO 中 SINGLE 不能作为默认值（MULTI 为默认） | 禁令2 题型 |
| `DesignSkillOrchestrator_canRunDesign_ShouldCheckPmGate` | `GetStatusAsync` 的 canRunDesign 逻辑包含 pm≥85 门禁（反射检查或行为测试） | 禁令6 交用户门禁 |
| `NoProhibitedModuleClasses_ShouldExist` | 扫描程序集中不存在 ScannerValidator / EventDependencyBuilder / PSpecEnhancer 类型 | 禁令5 废止模块 |
| `QualityScoreCalculator_TotalScore_ShouldRespectGate` | 综合分 ≥60 门禁不被绕过 | 禁令6 |
| `AmendmentUnderstanding_ShouldHaveRequiredFields` | DTO 含 Features/Flows/EntitiesOrTables/SummaryMarkdown 字段 | 25 决策10 Amend 回显 |

### 运行
```bash
dotnet test backend/tests/JNPF.Tests.PhaseB/JNPF.Tests.PhaseB.csproj --filter "FullyQualifiedName~ReqAnalysisInvariant"
```

### 注册到 guard-finish.mjs
当前 guard-finish L2 跑 `JNPF.Tests.Gate`，**不跑 PhaseB**。将扩展 L2 在后端变更时也跑 PhaseB 的守卫测试（filter `Invariant|ArchInvariant`），确保 Stop 时自动执行。
