## 零步 · 修复 Pipeline 311（最高优先级）

### 根因

Pipeline 311 创建于 PM终评/CTA 特性之前，经旧单体 analyst 流程：
- `02-requirement-spec.md` 缺少 CTA 固定文本
- IR 中无 `RequirementSpecPmReviewed` 事件
- `AnalysisCompleted` 不带 `finalized=true`

E2E 测试对此做强制性断言（**正确 — CTA 和 PM终评 是设计文档规定的核心功能，不可弱化测试**）。

### 设计文档已预设的修复机制

`RequirementAnalysisOptions.ForceRefinalize`（`RequirementAnalysisOrchestrator.cs:88-92`）：

> "强制重跑 Round3 Finalize + PM 终评（用于历史 pipeline 回填 CTA/PmReviewed，或运维重生 02）。"

实现（`:218-242`）：
1. `ReviewRequirementSpecAsync` → 从 IR EventSpec 快照重建说明书 → PM 评分 → 写 `RequirementSpecPmReviewed` 事件
2. `RunRoundAnalystAsync(enableFinalization: true)` → analyst 最终化 → `SaveRequirementSpecAsync` 写含 CTA 的 02 到磁盘 + `AnalysisCompleted(finalized=true)`
3. 返回 `"completed"`（PM ≥85）或 `"pm-review-failed"`

### 操作

**0a.** 调用编排器回填：

```json
POST /api/studio/skills/requirement-analysis/311/run
{
  "forceRefinalize": true,
  "forceConfirm": true,
  "forceReason": "历史 pipeline 311 回填 CTA + PM终评"
}
```

**0b.** 验证：

```bash
E2E_PIPELINE_ID=311 pnpm test:api   # 预期 5/5 全绿
node scripts/jnpf-api.mjs GET "/api/studio/pipeline/execute/311/deliverables/content?relativePath=02-requirement-spec.md"
```

**预期结果**：5/5 测试通过。`02-requirement-spec.md` 含 CTA，IR 含 `RequirementSpecPmReviewed` 事件。

## 二步 A · 编排器接入 EvaluateMaturity（需 CR）

**文件**：`RequirementAnalysisOrchestrator.cs:789-796`（`GenerateRoundClarificationAsync`）

**现状**：直接委托 PM Skill 生成澄清题，未先评估需求成熟度。旧 `sa-gate` 端点中的 `EvaluateMaturity` 调用是唯一入口，编排器反而不接。

**修改**：注入 `RequirementGateService`，生成澄清题前先调用 `EvaluateMaturity`：
- `refine`（≥80）：跳过提问，返回空题集
- `confirm`（25-79）：生成 3-5 道深度题
- `explore`（<25）：生成 3-5 道广度题

**CR**：`CR-20260713-01`（受保护方法 — 禁令六），对照 25 号方案 ADR-005。

---

## 二步 B · 关闭 AllowSkipNonCritical 逃逸（需 CR）

**现状**：`PmSkillService.GenerateClarificationAsync` 总是设 `AllowSkipNonCritical = true`。

**方案**（编排器层处理）：在 `GenerateRoundClarificationAsync` 中根据 maturity mode 决定：
- refine → 可跳过
- confirm/explore → 不可跳过（必须回答才能推进深度）

**CR**：`CR-20260713-02`。
