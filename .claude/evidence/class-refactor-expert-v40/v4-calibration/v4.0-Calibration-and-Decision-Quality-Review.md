## 2. 六问逐项审计

### Q1 Finding Discovery Quality — 是否把味道误判为风险？

**证据：**
- F-L1 Schedule：经 `using var scoped` 实查关闭，未因“看到 scope”就报泄漏。✅ 有效反例：避免误判。
- F-A1：1469行未自动拆分，经“独立变化轴/独立依赖/独立生命周期”判定，仅4/7 职责有独立性且均为请求级，收益有限→Stop。✅ 防止因规模制造成 Finding。
- F-E2：扫描 `throw Oops.Oh` 全合规后关闭，未因“缺少日志”强行制造泄露。✅

**结论：** 未出现“最佳实践强行修改正确设计”；反例样本已具备纠偏能力。

**不足：** 初步 Inventory 阶段曾列 ~12 Finding，存在“发现偏差”风险，但 Gate 阶段已通过证据强度过滤。

### Q2 Technical-Type-Specific Gate — 是否套同一 checklist？

| 技术 | 实际证据标准 | 差异 |
|---|---|---|
| Exception | 静态语义 + 契约不变 + InnerException | 无需运行时 |
| Resource Lifetime | 三问 ownership + 正常/异常双路径确定性释放 | 需生命周期建模，非简单 pattern |
| Performance N+1 | 静态形态 + DB round-trip + N规模 + 批量方案 + 语义风险 + **受控实测** | 必须区分推算vs实测（F-P1 教训） |
| Transaction | AOP 注册实证 + async参与 + 嵌套/异常边界 + DB vs 外部副作用边界 | 需框架层追踪 |

**结论：** 当前 Skill 虽共用 6/10 框架，但各 Gate Pack 已使用**不同证据类型**（ownership追踪 vs 实测 vs AOP）。**风险**：若后续 Agent 仅机械勾选 checklist，可能退化为同一标准；需在 Skill 中显式标注“按技术性质选择证据类型”。

### Q3 STOP Quality — 是证据的 STOP 还是“暂时不想做”？

- **F-L3 正面样本：** `DownloadAll` 创建 → `DownloadFile` 异步消费 → 用户行为决定结束 → 不能用 `try/finally` 局部释放。STOP 建立在 **ownership跨层 + 异步边界 + 消费未结束** 三证据，非“暂时不做”。
- 其他 STOP：F-A1（收益不足）、F-P2（缺实测）均为证据充分的 STOP。

**检查：** 未发现滥用为“暂时不做”。

**沉淀规则：** `references/Resource-Lifetime-Ownership-Rule.md` 的 `Create→Who consumes→When end→Who owns→Who disposes` 流程是有效 STOP 依据。

### Q4 NEED EVIDENCE Semantics — STOP vs NEED EVIDENCE 是否正确区分？

- **F-P1 定义正确：**
  - STOP = 证据充分，当前不应做（例 F-L3）
  - NEED EVIDENCE = 可能真实存在，但证据不足以决定（例 F-P1：N+1形态成立，但收益需实测）
- **行为正确：** 未因任务压力将 NEED EVIDENCE 转 GO；`Need-Evidence-Pack.md` 诚实标记 `BLOCKED BY ENVIRONMENT`，测试程序 `PerformanceTest.cs` 已备但未伪造结果。

**风险：** Skill 早期文档对两者区分不够显式，需在门控定义中固化。

### Q5 Fix Budget Quality — namespace 事件

- **事件：** OrderService 的 `+2 [UnitOfWork]` 因缺 `using JNPF.DatabaseAccessor;` 编译失败 `CS0246`。
- **处理：** 未用丑陋 Fully Qualified，选择申请扩展为 `+3 (1 using+2 attributes)`，获批后 Build 0错。
- **结论：** 证实 **“Fix Budget 应定义为最小语义变更预算，而非僵硬物理行数”**。Skill 当前“最多2行”是行数预算，需升级为语义预算。

### Q6 Stopping Rule — 何时宣布“足够”？

**当前状态：**
- FileService：GO→GO→STOP 后已收敛，不再挖第三个资源 Finding。
- ScheduleService：GO(Gate)→NEED EVIDENCE 后收敛，未强行制造第四个 N+1。
- OrderService：GO 后暂停。

**缺失：** Skill 尚无显式 Stopping Rule。正确规则应为：
```
风险收益递减 + 剩余问题需更高层边界 + 证据不足 + 局部修改风险上升 → Class-level convergence
而不是 Finding→Fix→继续找Finding 循环
```

**当前已隐式执行，但未文档化。**
