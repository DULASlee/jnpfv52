## F-L3：临时目录生命周期

### 10 维度分析

| 维度 | 分析 |
|------|------|
| **真实问题** | `DownloadAll` 创建临时目录 `Directory.CreateDirectory(directoryPath)` 和压缩文件 `ZipFile.CreateFromDirectory`，但方法结束后未清理临时目录和 zip 文件，导致磁盘空间持续占用 |
| **证据** | ✅ 代码实查：244 行 `Directory.CreateDirectory`，258 行 `ZipFile.CreateFromDirectory`，无 `Directory.Delete` 或 `File.Delete` 清理逻辑 |
| **技术性质** | 资源生命周期（临时文件/目录） |
| **影响面** | 中等：每次批量下载都会残留临时目录，长期运行导致磁盘占满；影响所有使用 `DownloadAll` 的用户 |
| **修复收益** | 高：消除磁盘泄漏风险，改善系统长期稳定性 |
| **改造半径** | **单类单点**：可在 `DownloadAll` 方法内用 `try/finally` 清理临时目录，无需跨类 |
| **契约风险** | 低：对外行为（返回下载链接）不变，仅内部清理逻辑 |
| **验证成本** | 低：build + 单次批量下载后检查临时目录是否清理 |
| **当前门控** | **Go**（原 Stop 理由"需跨类策略"不成立，实际可单点修复） |
| **优先级** | **P1**（资源泄漏，影响系统稳定性，但非 Critical） |

### 重新评估 Stop 理由

**原 Stop 理由**："需要跨类策略（临时文件清理机制）"  
**重新评估**：❌ **不成立**。可在 `DownloadAll` 方法内用 `try/finally` 清理临时目录，无需引入全局临时文件清理机制。单点修复即可解决本方法的问题。

**结论**：F-L3 满足 6 要素准入，可进入实现。

## F-J1：路径越界

### 10 维度分析

| 维度 | 分析 |
|------|------|
| **真实问题** | `Path.Combine(dir, resolvedName)` 对 `fileName.Replace("@",".")` 未规范化+未校验是否越界 `dir`；虽用 `Path.Combine` 但仍可 `../` 越界，存在路径遍历风险 |
| **证据** | ✅ 代码实查：128 行 `Path.Combine(dir, resolvedName)`，`resolvedName` 来自用户输入 `fileName`，未校验是否含 `../` |
| **技术性质** | 安全（路径遍历） |
| **影响面** | 高：攻击者可通过 `../` 访问任意文件，存在安全风险 |
| **修复收益** | 高：消除路径遍历漏洞 |
| **改造半径** | **跨类**：需要统一路径白名单策略，涉及 `GetImg`、`GetScreenImg`、`FileDown`、`DownloadAll` 等多处，需引入路径规范化/校验工具方法 |
| **契约风险** | 中：可能改变某些合法路径的访问行为 |
| **验证成本** | 中：需要路径遍历测试用例 |
| **当前门控** | **Stop**（需跨类策略，非单类单点） |
| **优先级** | **P0**（安全漏洞，但改造半径大） |

### 重新评估 Stop 理由

**原 Stop 理由**："需要统一路径白名单策略，非单类"  
**重新评估**：✅ **仍然成立**。路径越界问题涉及多处 `Path.Combine`，需要统一的路径规范化/校验策略，不适合在 FileService 单类内修复。

**结论**：F-J1 维持 Stop，需跨类策略。

## 最终 Decision：**A — 批准 F-L3**

### 理由

1. **F-L3 满足 6 要素准入**：
   - Evidence 确认：代码实查有临时目录未清理
   - Contract violation：资源 Contract（创建方清理）
   - 单点边界：`DownloadAll` 单点 `try/finally`
   - 门控通过：Risk P1 + 非性能 + Budget 低成本
   - 回归路径：build + 单次批量下载后检查临时目录
   - 不扩 Contract：对外行为不变

2. **原 Stop 理由不成立**：
   - "需跨类策略" → 实际可单点修复（`try/finally` 清理）
   - 无需引入全局临时文件清理机制

3. **修复收益明确**：
   - 消除磁盘泄漏风险
   - 改善系统长期稳定性

4. **验证成本低**：
   - build + 单次批量下载后检查临时目录是否清理

5. **不违反"不为凑数量而连续修同类"原则**：
   - Golden #2/#3 是 FileStream 句柄生命周期
   - F-L3 是临时目录生命周期，属于 Resource Lifetime 的**子类别**，但场景不同（句柄 vs 目录）
   - 可作为 Resource Lifetime 的第三个场景样本（上传/下载/临时目录）

### 不批准其他 Finding 的理由

- **F-J1**：需跨类策略，非单类单点
- **F-J2**：低优先级，收益低，Golden #1 已覆盖异常语义
- **F-P**：无证据，Gate 7 问全未通过
