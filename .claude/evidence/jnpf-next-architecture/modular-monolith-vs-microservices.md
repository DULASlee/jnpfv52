# NG-0 证据 6/11 — Modular Monolith vs 微服务（三形态比较）

**原则**：以真实数据和事务边界决定，不预设「微服务一定最好」。数据来源：证据 1-5。

## 1. 决定性事实（来自 DB 证据）

| 事实 | 数据 | 指向 |
|------|------|------|
| 所有候选域事务边界都在**单库事务内** | 证据 5：D1-D12 无跨库事务需求 | Modular Monolith 无拆分阻力 |
| FK 仅 14（sa_* 家族），275 表零 FK | 证据 1/2 | 拆库无约束阻力，但也无关系保障 |
| base_user 被全域 Join | 证据 2/4 | 任何形态都需要 Identity 读取 API 化 |
| 权限评估在**每个列表查询**执行（三连查） | 证据 3 | 跨域同步调用会成为服务形态瓶颈 → 快照/缓存优先 |
| 动态表 mt*（运行时 DDL） | 证据 1/4 | 低代码域与服务边界天然冲突（共享库/共享 Schema） |
| AI 域自洽（FK+事件表） | 证据 1/5 | 独立服务唯一现实候选 |
| 审计日志三族写放大 | 证据 3 | 独立存储（与形态无关） |

## 2. 三形态对比

### A. Modular Monolith（模块化单体）
```
JNPF Next
 ├── Identity ──┐
 ├── Tenant     ├── 共享数据库（按 Schema/前缀分区）
 ├── Permission ┤
 ├── Workflow   │
 ├── Form/LC    │
 ├── AI         │
 ├── File       │（独立存储可先剥离）
 └── …          ┘
模块间：进程内调用 + 接口隔离（模块 = 程序集边界）
```
| 维度 | 评估 |
|------|------|
| 优点 | 事务天然单库；迁移分步可控；无网络开销；动态表共享 Schema 可行 |
| 缺点 | 模块纪律要求高（架构测试强制）；物理解耦有限 |
| 适配 | **首选**——现状所有事务边界都支持；D12 沙盘先验证 |

### B. Modular Monolith + Selective Services（模块化单体 + 选择性服务）
```
JNPF Next Core Monolith（Identity/Tenant/Permission/Workflow/Form/AI）
 ├── File Service（独立）——边界最清晰、无跨域 Join
 ├── Log Service（独立存储）——写放大隔离
 └── (后续) AI Service——自洽度最高（FK 家族+事件表）
```
| 维度 | 评估 |
|------|------|
| 优点 | 平台服务先独立（File/Log 零依赖）；AI 域可渐进剥离；核心单体保住事务 |
| 缺点 | 服务边界需要事件/API 契约先行 |
| 适配 | **NG-1 原型验证目标**——先做 File/Log 独立 + AI 域自治试点 |

### C. Full Microservices（全微服务）
```
Identity / Tenant / Permission / Workflow / Form / Data / File / Notification …
```
| 维度 | 评估 |
|------|------|
| 优点 | 独立扩缩容/独立发布 |
| 缺点 | **被证据否决为第一形态**：①权限评估每查询同步调用不可接受（需先快照化）；②base_user 全域 Join 需全面 API 化；③动态表 mt* 与 Form 服务边界冲突；④跨库事务需求为零却付分布式代价；⑤现状 289 表零 FK 的关系契约全部要重写 |
| 适配 | **远期演进目标**——Modular Monolith 稳定后按域逐个剥离（D10 AI 优先候选） |

## 3. 形态决策（本阶段结论）

1. **首选 A（Modular Monolith）**：数据与事务证据充分（全部单库事务）；
2. **NG-1 原型验证 B 的两个独立点**：File/Log 独立存储（零依赖证明）+ AI 域自治（样板参照）；
3. **C 是远期目标不是当前计划**：条件成熟信号 = 权限快照上线 + Identity API 化 + 动态表注册表完成；
4. **禁止**「一个 Service 一个微服务 + HTTP 包起来」——已列入 NG-0 设计禁令（领域边界按证据 5 重新聚类，不是按项目目录）。

## 4. 判定矩阵（形态×域）

| 域 | A 单体 | B 独立服务 | 条件 |
|----|:------:|:---------:|------|
| Identity | ✅ | 暂缓 | 权限快照+自身 API 化后 |
| Tenant | ✅ | 暂缓 | 注册表小，随时可拆 |
| Permission | ✅ | 暂缓 | 评估 API 化+快照后 |
| Workflow | ✅ | 暂缓 | 事件化后（任务事件先行） |
| Form/LC | ✅ | ⚠️ 冲突 | 动态表归属裁决后 |
| AI | ✅ | **候选** | 依赖 API 化后（NG-1 验证） |
| File | ✅ | **候选** | 零依赖，随时可拆 |
| Log | ✅ | **候选** | 独立存储（写放大） |
| Demo | ✅ | 沙盘 | D12 内拆分试点 |
