# NG-0 证据 9/11 — 迁移策略（Legacy → Next）

**原则**：渐进式迁移（Strangler Fig 变体），非大爆炸；以特征测试为等价判据（现有 483 用例 + P0-B 43 特征）。

## 1. 迁移前提顺序（依赖链）

```text
P0（已完成）：D1 复杂度 → P0-A 边界 → P0-B 路径 B 契约
  ↓
NG-1 原型：数据库反向工程深化（DMV/慢查询）→ 权限快照原型 → Identity API 化原型
  ↓
NG-2 骨架：Modular Monolith 骨架（12 域程序集边界 + 架构测试）
  ↓
NG-3 域迁移：按域替换（沙盘先行）
```

## 3. 数据迁移模式

| 模式 | 适用 | 说明 |
|------|------|------|
| **原地演进**（同库改 Schema） | W1-W4 | 表/列契约变更走迁移脚本，双跑验证 |
| **读双写**（影子读） | W3/W6 | Next 查询侧并行执行比对结果（特征快照） |
| **表级搬移**（新库） | W5/W7/W8 | 域独立后才物理搬库（先逻辑后物理） |
| **弃迁** | blade_*/备份表/text | DEPRECATE/REMOVE 项不迁移 |

## 4. 关键约束（不变量）

1. **Legacy 不停摆**：迁移期 Legacy 全功能运行；Next API 与 Legacy API 并存（网关/路由层分流）；
2. **特征测试为等价判据**：KEEP 项逐字等价；REDEFINE 项以「语义等价+新契约测试」双标；
3. **每波次独立可回滚**（与 D1 协议一致）；
4. **租户隔离为最高优先级不变量**（W8 前任何迁移不得破坏 f_tenant_id 过滤语义——P0-C 冻结区）；
5. **多库兼容不倒退**（私有化核心能力，DB-1 多库方言资产保留）。

## 5. 沙盘选择理由（D12）

- OrderService 是路径 B 唯一消费者 → 迁移 Order 域 = 完整验证权限评估 API；
- 依赖面全（Identity/Workflow/Permission）→ 一次验证三条 API 化链；
- 无平台级风险（演示业务）→ 失败可回滚。
