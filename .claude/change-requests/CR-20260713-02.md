# ✅ CR-20260713-02：PmSkillService 按成熟度控制 AllowSkipNonCritical（关闭无条件逃逸）

> **状态：IMPLEMENTED（已完成施工）** ✅
> **施工日期：** 2026-07-13
> **铁律触发：** 需求分析子链铁律第六条（保护方法修改前 MUST CR）+ 实现完整性禁令一（禁止给门控开逃逸通道）+ F3 铁律（旁路必须修）
> **保护方法：** `PmSkillService.GenerateClarificationAsync`（PM 专家出题唯一入口）
> **架构依据：** 25 号方案 决策 2（PM 必须自主出题，含判断是否该允许跳过；禁止编排器代行 PM 职责）

## 一、根因（运行时证据）

`PmSkillService.GenerateClarificationAsync` 两处无条件设 `AllowSkipNonCritical = true`：

**位置一（line 148-157 · 正常出题路径）：**

```csharp
var set = new ClarificationSet
{
    // ...
    AllowSkipNonCritical = true,  // ← 无条件 true
    Questions = questions,
};
```

**位置二（line 753-763 · LLM 失败降级 `BuildEmptyClarificationSet`）：**

```csharp
private static ClarificationSet BuildEmptyClarificationSet(string stage, int round, string title, string intro)
    => new()
    {
        // ...
        AllowSkipNonCritical = true,  // ← 无条件 true
        Questions = new List<ClarificationQuestion>(),
    };
```

`ClarificationSet.AllowSkipNonCritical` 的 DTO 默认值也是 `true`（ClarificationDtos.cs:40）。

**问题：** 无论需求成熟度如何，前端始终显示"跳过"按钮——用户可跳过非关键题（`required=false`），即使当前处于 explore 模式下急需信息补充。这形成了**门控逃逸通道**（禁令一）：CR-01 成熟度门控判定需求不完整、要求提问，但用户可以不答。

**对照旧实现：** 旧 `AIDevelopmentPipelineService.StreamLlmResponseAsync` 中也存在该问题——旧实现和编排器均缺失此门控。本 CR 是**新增安全防线**，非回归修复。

**为何应放在 PmSkillService 而非编排器（上一版 CR 的错误）：**

上一版 CR 将 `AllowSkipNonCritical` 覆盖逻辑放在编排器 `GenerateRoundClarificationAsync` 中。但 **25 号方案 决策 2** 规定：

> PM 必须"自主出题"（含判断题目关键性 + 是否允许跳过）；禁止"由编排器 `_llm` 冒充 PM 视角出题"；出题入口 = `PmSkillService.GenerateClarificationAsync`

**题目关键性判断属于 PM 领域知识——题目是 PM 出的，PM 最清楚哪些可以跳过、哪些必须回答。编排器在外部覆盖 `AllowSkipNonCritical` = 编排器替 PM 做业务判断，违反决策 2。**

## 三、变更内容

### 3.1 核心逻辑：GenerateClarificationAsync 中按 maturity mode 设置 AllowSkipNonCritical

**变更位置的完整上下文**（CR-01 + CR-02 合并后的方法骨架）：

```csharp
public async Task<ClarificationSet> GenerateClarificationAsync(
    int round, string stage, string tenantId, string projectId, long pipelineId,
    SaNineViewCompileResult compileResult, IReadOnlyList<string> warnings,
    string? previousAnswersText, CancellationToken ct)
{
    ct.ThrowIfCancellationRequested();

    // ── CR-01：成熟度评估 ──
    var chatHistory = BuildMaturityChatHistory(compileResult, previousAnswersText, tenantId, projectId, pipelineId);
    var maturityProvider = Llm.ResolveProvider("maturity");
    var maturity = await _gate.EvaluateMaturity(chatHistory, maturityProvider, ct);

    _logger.LogInformation(
        "pm-skill 第 {Round} 轮成熟度评估 score={Score} mode={Mode} | pipeline={PipelineId}",
        round, maturity.Score, maturity.Mode, pipelineId);

    if (maturity.Mode == "refine")
    {
        return BuildRefineEmptySet(stage, round, maturity);
        // BuildRefineEmptySet 已含 AllowSkipNonCritical=true，无需覆盖
    }

    // ── 现有出题逻辑（explore/confirm 模式）──
    var (title, intro, systemPrompt) = BuildRoundPrompt(round, compileResult, warnings, previousAnswersText);
    // ... BuildRoundUserPrompt + SelectTopSlots + RetrieveEvolutionSeeds + seedPrompt/slotsPrompt ...
    // ... ChatWithSchemaRetryAsync ...

    var response = await ChatWithSchemaRetryAsync(request, "clarification", ct);
    if (!response.IsSuccess || string.IsNullOrWhiteSpace(response.Content))
    {
        _logger.LogWarning("pm-skill 第 {Round} 轮出题 LLM 失败，降级为空题集: {Error}",
            round, response.Error);
        return BuildEmptyClarificationSet(stage, round, title, intro);
        // BuildEmptyClarificationSet 已含 AllowSkipNonCritical=true，无需覆盖
    }

    var questions = ParseQuestionsFromLlm(response.Content, round);
    ApplyMatrixFallback(questions, compileResult);
    EnsureEscapeHatch(questions);
    StampSlotHints(questions, selectedSlots);

    // ── CR-02 核心变更：PM 按成熟度 mode 决定是否允许跳过 ──
    // explore/confirm 模式有题时：不允许跳过——PM 出的每道题都有信息价值
    // refine 模式或 LLM 失败降级（0 题）：允许跳过——无实际题目
    bool allowSkip = questions.Count == 0;  // 仅 0 题时允许跳过

    var set = new ClarificationSet
    {
        SetId = Guid.NewGuid().ToString("N"),
        Stage = stage,
        Round = round,
        Title = title,
        Intro = intro,
        AllowSkipNonCritical = allowSkip,   // ← CR-02：替代原来的 true
        Questions = questions,
        TargetSlotIds = selectedSlots.Select(s => s.SlotId).ToList(),
    };

    _logger.LogInformation(
        "pm-skill 第 {Round} 轮出题完成 stage={Stage} mode={Mode} questions={Count} allowSkip={AllowSkip} | pipeline={PipelineId}",
        round, stage, maturity.Mode, questions.Count, allowSkip, pipelineId);
    return set;
}
```

**改动量：** 仅两行变更：
- Line ~155：`AllowSkipNonCritical = true` → `AllowSkipNonCritical = allowSkip`
- Line ~149 前：新增 `bool allowSkip = questions.Count == 0;`（一行声明）

**Log 增强：** 日志中追加 `mode={Mode}` 和 `allowSkip={AllowSkip}` 用于生产监控（可选）。

### 3.2 逻辑决策表（PM 自主判断）

| Maturity Mode | LLM 出题结果 | AllowSkipNonCritical | PM 判断理由 |
|---------------|-------------|---------------------|------------|
| `explore` | 正常出 3-5 题 | **`false`**（禁止跳过） | 需求信息严重不足，每道题都有关键信息增益——不可跳过 |
| `confirm` | 正常出 3-5 题 | **`false`**（禁止跳过） | 需求需逐条确认，跳过 = 未确认项残留，后续分析易出错 |
| `refine` | 不调用 LLM（CR-01 空题集） | `true`（N/A） | 需求已充分完整，无题可答——跳过无意义 |
| 任意 | LLM 失败降级，0 题 | `true`（允许跳过） | LLM 失败非用户过错，不应阻塞流程——允许绕过 |

**不变式：** `AllowSkipNonCritical = false` 当且仅当 `Questions.Count > 0`（PM 出题了，题题必答）。

## 四、影响范围

| 调用方 | 路径 | 影响 |
|--------|------|------|
| 编排器 `GenerateRoundClarificationAsync`（line 754-761） | `_pm.GenerateClarificationAsync(...)` | **零代码变更**——编排器纯委托，收到什么 ClarificationSet 就用什么 |
| `DesignSkillOrchestrator`（架构设计） | 架构设计 → `_pm.GenerateClarificationAsync(...)` | 当前架构设计不走此路径。若未来复用，PM 行为一致（有题必答） |

**下游影响：**
- `EmitClarificationRequestedAsync`：IR 事件 payload 中的 `AllowSkipNonCritical` 由 PM 设定，前端读取该字段控制"跳过"按钮显隐
- 前端：需读取 `ClarificationSet.AllowSkipNonCritical` 隐藏/禁用"跳过"按钮——**这是现有字段，前端已有实现**（非本次范围）
- 用户行为变化：explore/confirm 模式下前端不显示"跳过"按钮，但 escape hatch（每题末项"其他"+文本框）始终可用——用户可填"不知道"而非空白提交

**无影响：**
- 旧 `AIDevelopmentPipelineService.StreamLlmResponseAsync`：旧路径不改（自然淘汰）
- 架构设计/总体设计阶段：若其通过 PM 生成澄清题，默认行为一致（有题必答）

## 五、风险评估

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| 用户无法跳过 LLM 生成的垃圾题 | 低 | 体验退化，被无意义题目卡住 | `EnsureEscapeHatch`（PmSkillService:716-733）保证每道题末项为"其他"+文本框——用户始终可填"不知道"绕过；硬门控仅针对"跳过"按钮，不针对"作答"行为 |
| LLM 出题失败（Questions.Count=0），AllowSkipNonCritical 仍为 true | N/A | 无影响 | 已有逻辑覆盖（`questions.Count == 0 → true`） |
| 与 CR-01 refine 路径一致 | 无 | N/A | CR-01 的 `BuildRefineEmptySet` 返回 `AllowSkipNonCritical=true`，Questions.Count=0，一致 |
| Round 1 explore 阶段用户无充足信息作答 | 低 | 被迫选"其他" | "其他"+文本框始终可见（escape hatch），用户可表达"当前无法确定"，编排器据此 refine |

**回滚方案：** `git revert` 此提交。PmSkillService 恢复 `AllowSkipNonCritical = true`（常数），前端恢复"跳过"按钮在所有场景下可见。
