# CR-20260820-01 — RunService 上帝类拆分（战役 1 · 第 2 目标）

> **⚠️ 不可变前提（同 CR-20260819-01）：保留 IDynamicApiController + 保留 SqlSugar。**
> 依据施工包 v2.0 §三 目标清单第 2 项（Week 2 计划）；试点 CR-20260819-01（UsersService）三阶段已执行完毕并验收全绿，SOP 复用。

## 业务理由

`RunService`（`modularity/visualdev/JNPF.VisualDev/RunService.cs`）为战役 1 剩余目标中复杂度最高者：

| 度量 | 实测（2026-08-20 前置排查） |
|------|------|
| 行数 | **4157 行**（施工包登记 3734，已增长） |
| 方法 | 25 公共 + 34 私有，11 个 region |
| JNPF009 基线占用 | **8 条目，全仓最多**：`GetListQuerySql`(CC140，全仓最高)/`GetListResult`(96)/`SaveDataToDataByFId`(90)/`GetSuperQueryInput`(84)/`FieldBindDefaultValue`(82)/`GenerateFeilds`(81)/`DataTransferVerify`(74)/`GetQueryJson`(72) |
| 直接测试 | **无**（JNPF.Tests.VisualDev 仅 `VisualDevListRefIndexTests`） |

## 与 CR-01（UsersService）的关键差异（排查实证）

1. **非 API Controller**：`RunService : IRunService, ITransient, IDisposable`，**不实现 IDynamicApiController、零 Http 特性**。
   API 暴露面在委托方：`VisualDevModelDataService`(Name=OnlineDev)、`VisualDevService`(Name=Base)、`VisualdevShortLinkService`(Name=ShortLink)。
   → 路由契约由委托方间接承载，快照硬门控仍保留（全量 `api/visualdev` 过滤）。
2. **双通道消费**：
   - 跨模块经接口：`IRunService`（17 方法）被 WorkFlow 消费（`FlowTaskManager`/`FlowFormService`/`FlowTaskOtherUtil`）——对应依赖矩阵硬耦合 `WorkFlow→VisualDev`，本 CR **不动接口**（解耦属战役 2/F4）。
   - 模块内/跨模块经**具体类**注入 5 处：`VisualDevService`、`VisualDevModelDataService`、`VisualdevShortLinkService`、`VisualdevModelAppService`、`Common.CodeGen/ExportImportDataHelper`（跨模块，`Common.CodeGen→VisualDev` 硬耦合 F4 清单在册）。
3. **有状态**：`IDisposable` + `SqlSugarScope _sqlSugarClient` 字段（非 readonly）——拆分时状态归属需专项设计。
4. **Engine 耦合**：`using JNPF.VisualDev.Engine.Core` + `JNPF.Engine.Entity.Model`（施工包预警的 VisualDev.Engine 硬耦合，拆分仅移动不解除）。

## 变更范围（分阶段，每阶段独立审批）

### 阶段 0：安全网 + 深度剖析（本 CR 首个审批节点）

1. **路由快照基线**：harness `--mode routes --filter "api/visualdev"` 全量落盘（含 OnlineDev/Base/ShortLink 三委托方）。
2. **安全网测试**：为 `IRunService` 17 个契约方法补反射式契约特征测试（复用 CR-01 契约测试模式：签名/接口成员零变更），
   另补核心 Happy Path API 快测断言（`pnpm test:api` 增量或 xUnit）。
3. **方法级剖析**：4157 行逐 region 归类（查询/执行/SQL 生成/数据传输/字段绑定…），产出拆分分组表，
   标注每组依赖的字段状态（`_sqlSugarClient` 等）与私有辅助归属。

### 阶段 1+：按剖析结果分组迁移（绞杀者式纯移动，零改写）

- 候选分组（阶段 0 剖析后确认，预计 4-6 个新类，每个 <800 行）：
  运行查询（GetList*/GetQuery*）/ SQL 生成（GetListQuerySql/GetSuperQueryInput）/ 数据写入（SaveDataToData*）/ 字段与默认值（FieldBind*/GenerateFeilds）/ 数据传输与校验（Transfer*/DataTransferVerify）。
- **门面策略（降风险）**：`RunService` 保留为薄门面实现 `IRunService`，内部委托新类；5 处具体类注入点第一阶段不动，
  待门面稳定后再逐点切换注入类型（另行节点审批）。
- JNPF009 基线 8 条目仅随迁（file/symbol 路径更新，值不上调、不新增）；CC 降至 ≤30 需逻辑重构，**不在本 CR**。
