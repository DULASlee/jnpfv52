## 一、根因（运行时证据 + 用户反馈）

### 1.1 用户初衷（4 步）

```
① PM 用提示词+种子完善需求（过程中可追问用户关键点，对话式 0~N 次）
② SA 九步拆解（7 步 C# 确定性 + 2 步 PM 语义）
③ PM 分析九步数据反向完善需求（可追问 → 重跑②）
```

## 三、新流程设计（4 步 + 3 循环点）

```
用户提交比较完善的需求文本
         │
         ▼
┌─────────────────────────────────────────────┐
│ 步骤① EnhanceRequirement                    │
│  PM 提示词："你是企业通用管理系统专家，      │
│            运用行业知识完善需求"             │
│  输入：用户原始需求 + 种子（行业惯例）        │
│  LLM 动作：完善需求文本                      │
│  循环点①：LLM 发现关键不确定点 → 自然追问   │
│           用户（0~N 次，非固定 3 题）         │
│           → 用户回答 → 继续完善              │
│  产物：完善后的需求文本（EnhancedText）       │
│  IR：RequirementEnhanced 事件（stable）      │
└─────────────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────────────┐
│ 步骤② SaDecompose（九步拆解）               │
│  2a. C# 编译器 7 步（零 LLM，毫秒级）        │
│  2b. PM LLM 2 步（真语义，非占位）           │
│  产物：九步数据表（SaNineView）              │
│  IR：SaDecomposed 事件（stable）             │
│  ★ 此步不问用户，纯拆解                     │
└─────────────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────────────┐
│ 步骤③ RefineFromAnalysis（二次完善需求）     │
│  输入：九步数据 + EnhancedText + warnings    │
│  LLM 动作：分析九步发现遗漏，反向补进需求    │
│  循环点③：LLM 发现新不确定点 → 自然追问     │
│           → 用户回答 → 完善需求              │
│           → 【重跑步骤②】九步拆解           │
│  产物：二次完善需求文本（RefinedText）       │
│  IR：RequirementRefined 事件（stable）       │
└─────────────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────────────┐
│ 步骤④ GenerateSpec + 用户确认              │
│  渲染：RefinedText（用户预览）               │
│       + 九步数据表（系统存，用户不看）       │
│  用户确认 ✅ → 进入架构设计阶段              │
│  用户反馈 ❌ → 文字反馈给 PM                 │
│              → PM 改需求文本                 │
│              → 【重跑步骤②】九步拆解         │
│              → 回到步骤④                    │
└─────────────────────────────────────────────┘
```

### 关键设计决策

1. **追问是"对话式"，不是"结构化出题"** — PM 像顾问，自然语言追问关键点，0~N 次，不再固定 3 题 MULTI/MATRIX
2. **步骤②是纯执行，不问用户** — 7 步 C# + 2 步 PM 语义
3. **循环点在①③④** — ①③是 PM 主动追问，④是用户主动反馈
4. **最终产物 = 文本（用户看）+ 九步表（系统存）** — 九步表给后续二次开发/BUG 修复用

## 五、新增数据模型（接口契约 — P3 阶段定义，禁止方法体）

```csharp
// 步骤①产物
public sealed record RequirementEnhancedEvent(
    string EnhancedText,           // 完善后的需求文本
    IReadOnlyList<string> SeedIds, // 召回的种子 ID
    int ClarificationTurns);       // 追问轮次（0~N）

// 步骤②产物（复用现有 SaNineViewCompileResult，新增 2b 真语义）
// SaNineViewCompileResult 结构不变，但 IntegrationPoints/WorkflowSpec
// 从 Empty/模板拼接 → PM LLM 真语义产出

// 步骤③产物
public sealed record RequirementRefinedEvent(
    string RefinedText,            // 二次完善需求
    IReadOnlyList<string> Gaps,    // 发现的遗漏
    int RecompileCount);           // 重跑九步次数

// 步骤④产物
public sealed record RequirementSpecRenderedEvent(
    string SpecMarkdown,           // 用户预览的需求文本
    string NineViewFragmentId);    // 九步数据表 IR fragment 引用

// 对话式追问（替代 ClarificationSet 的结构化题）
public sealed record PmClarificationTurn(
    string TurnId,
    string Question,               // 自然语言问题
    string? UserAnswer,            // 用户回答（首轮为空）
    ClarificationSource Source);   // Step1Enhance | Step3Refine | Step4Feedback

public enum ClarificationSource { Step1Enhance, Step3Refine, Step4Feedback }
```

## 九、风险与回滚

### 风险
1. **删除三轮循环可能影响现有 E2E 测试** — 阶段 B 前先跑现有测试，确认依赖范围
2. **对话式追问的 LLM 成本** — 0~N 次，需设上限（建议 ≤5 次/步骤）
3. **步骤②2b PM LLM 产真语义会增加耗时** — 从毫秒级降到秒级，可接受

### 回滚
- 阶段 A 是新增方法，不改现有流程，可独立回滚
