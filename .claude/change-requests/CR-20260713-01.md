# ~~CR-20260713-01~~：PmSkillService 接入 EvaluateMaturity 成熟度门控（出题前评估，成熟度达标跳过提问）

> **状态：PERMANENTLY_DEPRECATED（永久废弃）** ⛔
> **废弃日期：** 2026-07-13
> **废弃原因：** 本 CR 的原设计方案（编排器→EvaluateMaturity→决定是否调 PM）与 PM 内建成熟度门控形成架构冗余。经对照分析确认：PM 已是成熟度决策的权威（掌握骨架完整度、领域知识、历史案例），编排器再加一层评估属重复 LLM 调用，且两个 LLM 可能因 prompt/temperature/provider 差异得出矛盾结论。最终采用"PM 唯一决策"方案——成熟度评估仅存在于 `PmSkillService.GenerateClarificationAsync` 内部（当前代码 `PmSkillService.cs:120-131`），编排器 `GenerateRoundClarificationAsync` 保持纯委托。
> **替代方案：** CR-20260713-02（AllowSkipNonCritical 动态化）— 已实现
> **原保护方法：** `PmSkillService.GenerateClarificationAsync`
> **原架构依据：** 25 号方案 决策 1+2
> **原前置依赖：** 无

## 一、根因（架构确证）

`RequirementGateService.EvaluateMaturity` 是 ADR-005 规定的唯一成熟度评估入口——具备 4 维度 LLM 评分（领域 0-30/实体 0-30/流程 0-20/约束 0-20）+ explore/confirm/refine 三模式判定 + fail-safe 降级 confirm。

**问题一：** 该方法的唯一调用方是旧 `AIDevelopmentPipelineService.StreamLlmResponseAsync`（旧 sa-gate SSE 流，line ~1240）。三轮编排器 → `PmSkillService.GenerateClarificationAsync` 从未做成熟度评估——这意味着：

1. PM 每轮无条件出 3 题，即使需求已充分完整（score ≥ 80 应进 refine 模式）
2. 用户被迫回答明知故问的问题，体验退化
3. 成熟度评估的最核心价值——"需求够了就跳过提问"——在 PM 出题链路中完全缺失

**问题二（架构错位——上一版 CR 的错误）：** 先前将成熟度评估放在编排器 `GenerateRoundClarificationAsync`（编排器注入 `RequirementGateService` + 调用 `EvaluateMaturity`），但 **25 号方案 决策 1+2 明确规定：**

> **决策 1：** 编排器 = "轻量 for 循环，**禁止自管出题 LLM**"
> **决策 2：** PM 必须"自主出题"（含判断是否该出题）；禁止"由编排器 `_llm` 冒充 PM 视角出题"；出题入口 = `PmSkillService.GenerateClarificationAsync`

**成熟度评估是 LLM 调用——属于 PM 专家判断能力范畴。放在编排器 = 编排器越权代行 PM 职责，违反决策 2。**

**这是 F3 铁律所指的「旧实现干扰」的反面：新实现缺少旧实现中已有的关键门控，形成功能降级。**

### 3.4 聊天历史构建（新增私有静态方法）

```csharp
/// <summary>
/// 为 EvaluateMaturity 构建聊天历史（从 SA 编译结果 + 上一轮答案提取领域摘要）。
/// 静态方法——不依赖 PmSkillService 实例状态，可独立测试。
/// </summary>
private static List<ChatMessage> BuildMaturityChatHistory(
    SaNineViewCompileResult compileResult,
    string? previousAnswersText,
    string tenantId,
    string projectId,
    long pipelineId)
{
    var messages = new List<ChatMessage>();
    var parts = new List<string> { $"项目 {projectId}，租户 {tenantId}" };

    if (compileResult.EventResults is { Count: > 0 })
    {
        var entities = compileResult.EventResults.Select(e => e.EventName).Take(15).ToList();
        parts.Add($"实体（{compileResult.EventResults.Count}）：{string.Join("、", entities)}"
            + (compileResult.EventResults.Count > 15 ? " …" : ""));
    }

    if (compileResult.Assumptions is { Count: > 0 })
    {
        var assumptions = compileResult.Assumptions.Take(10).Select(a => a.Text ?? a.ToString());
        parts.Add($"假设项（{compileResult.Assumptions.Count}）：{string.Join("；", assumptions)}");
    }

    messages.Add(new ChatMessage("user", string.Join("\n", parts)));

    if (!string.IsNullOrWhiteSpace(previousAnswersText))
        messages.Add(new ChatMessage("user", $"用户确认/澄清：{previousAnswersText}"));

    return messages;
}
```

### 3.5 Refine 模式空题集（新增私有静态方法）

```csharp
/// <summary>
/// 成熟度达 refine（≥80 分）时返回空题集。
/// Title/Intro 告知编排器和前端：需求已完整，无需额外提问。
/// </summary>
private static ClarificationSet BuildRefineEmptySet(string stage, int round, MaturityResult maturity)
    => new()
    {
        SetId = Guid.NewGuid().ToString("N"),
        Stage = stage,
        Round = round,
        Title = "需求已足够完整",
        Intro = $"成熟度 {maturity.Score}/100 — 将基于当前信息直接进行深度分析",
        AllowSkipNonCritical = true,   // 无题可答，跳过按钮无意义
        Questions = new List<ClarificationQuestion>(),
    };
```

## 五、风险评估

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| LLM 评估不准（score 虚高→误跳过提问） | 中 | 需求不完整直接进分析 | `EvaluateMaturity` prompt 含保守评分策略（refine=80 阈值）；fail-safe 降级 confirm（RequirementGateService:186-212）；`NormalizeMode` 一致性兜底 |
| 聊天历史信息不足（compileResult 为空或无实体） | 低 | LLM 收空上下文 | `BuildMaturityChatHistory` 至少含项目/租户标识；`EvaluateMaturity` fail-safe 降级 confirm（含 "conservative scoring" 策略） |
| LLM 调用超时（90s × 3 重试） | 低 | 阻塞 PM 出题 | `EvaluateMaturity` 自身 try-catch + 降级 confirm；编排器不受阻 |
| DI 容器解析失败（构造函数参数变更） | 极低 | 启动失败 | `RequirementGateService` 已是 `ITransient`；PmSkillService 也是 `ITransient`，DI 链自动解析 |
| 架构设计阶段误用 maturity gate | 低 | 不匹配的 compileResult 导致评估异常 | 当前架构设计不走此路径；评估自身有 fail-safe |

**回滚方案：** `git revert`。`PmSkillService` 恢复无条件调用 LLM 出题（移除 `_gate` 字段 + 成熟度评估代码块），编排器不受影响。
