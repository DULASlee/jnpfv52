# Risk / Impact Matrix Template（v4.0）

> **输入**：P0 Evidence Pack 的 Findings
> **输出**：决定哪些 P 进场、哪些被明确拒绝（防过度优化）

## 矩阵

| 影响面 ↓ \ 修复成本 → | 低成本（<2h） | 中成本（2–8h） | 高成本（>8h） |
|----------------------|--------------|---------------|--------------|
| **高影响（崩溃/泄漏/数据错乱/安全）** | **P0 立即** | **P0 立即** | **P0 立即** |
| **中影响（性能/死锁/资源）** | P1 本迭代 | P1 本迭代 | P2 下迭代 |
| **低影响（坏味道/可维护性）** | P2 下迭代 | P3 待观察 | P3 待观察 |

## JNPF P0 红线（命中即 Critical，无视成本）

- N1 多租户过滤缺失（R4）
- N2 SQL 注入（R7）
- N3 API 权限缺失（R8）
- N4 三元组完整性（R12）
- J6 多租户过滤缺失（= N1）

## 填写示例

| Finding | 维度 | 风险 | 影响 | 成本 | 决策 | 选用技术（最低复杂度） | 禁止技术 |
|---------|------|------|------|------|------|------------------------|----------|
| 事件订阅未退订 | A1 | High | 中 | 低 | P1 本迭代 | Dispose/Unsubscribe | 全量 WeakEvent |

## 三个安全阀（必须显式回答）

1. **没有证据，是否进行了高级优化？** 是/否（是 = 阻断）
2. **没有量化验证，是否宣称性能改善？** 是/否（是 = 阻断）
3. **发现问题是否自动修改了代码？** 是/否（是 = 阻断，Finding ≠ Fix）
