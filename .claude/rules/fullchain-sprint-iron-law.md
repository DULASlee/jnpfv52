# 全链条冲刺铁律（Full-Chain Sprint Iron Law）

> **层级：宪法级，与 Business First / 实现完整性 / 三元组铁律并列。**  
> **Cursor 镜像：** `.cursor/rules/fullchain-sprint-iron-law.mdc`（alwaysApply）  
> **施工细则：** `docs/AI原生开发/1、多用户多任务并行/30、全链条冲刺开发计划（最后一公里）.md`（**v2.3+ · §0.11 各阶段业务功能目标**）

## 核心宣言

**AI 原生全链条必须按阶段推进验收；不得用「全链冒烟绿了」顶替阶段正确性。**  
**任何阶段开工前必须先钉死该阶段业务功能（阶段 C 验收清单）；禁止开发目标不明、脱离业务功能去开发（错题本 M035）。**

## 四条铁律

1. **按阶段推进 + 业务功能正确完整 + 核心可单测（F1）** — 每 SG 先对照 **§0.11** 钉死业务功能再施工；Gate/投影/编译器等确定性核心必须有 xUnit（或 UT-GAP）；**禁止**用纠偏项/文案/单测绿顶替①。
2. **数据一致性保证（F2）** — IR = Write Model；`ai_entity_field` = 字段消费唯一源；`sa_*`/md = 投影；契约无漂移；三元组完整。
3. **排除并修订旧实现干扰（F3）** — 切断旧 Analyst/九步/parse-IR-当字段源/311 假绿；旁路必须修或隔离。
4. **全链条冒烟测试置后（F4）** — SG0–SG7 + SG-CONTRACT 全部节点审批通过后，才允许 W3 全链冒烟。

**对应 30 号四大支柱：** F1↔①+④ · F2↔② · F3↔③ · F4↔W3 最后。

## 强制顺序

`W0 → SG-CONTRACT → SG0…SG7 →（全绿）→ W3 全链冒烟`

## 禁止

- 跳 SG；仅 build/全链/test:api 声称阶段完成
- 311 假绿；改断言凑绿；字段第二源；门控逃逸
- 一期做数字员工/湖/垂直包或生成平台内核

## Agent

阶段结束必须按阶段 C 提交审批；未经用户「继续/通过」不得进下一节点。
