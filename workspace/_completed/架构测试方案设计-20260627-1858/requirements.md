# 架构测试方案设计 — JNPF 平台定制

## 背景

JNPF 作为 AI 原生低代码平台，项目结构、代码生成机制、模块边界与常规 Clean Architecture 有本质差异：
- 代码来源：手写 + 平台生成 + 运行时编译
- 模块化：插件热插拔、动态加载
- 分层模型：模块化而非经典四层

盲目套用标准架构测试规则必然水土不服。需先摸清项目基因，再出精准方案。

## 目标

设计一份**针对 JNPF 平台定制的架构测试方案**，而不是通用模板。

## 前置：需收集的知识图谱

### 一、项目工程结构
- 完整 .sln 结构树 + 所有 .csproj 依赖关系
- 根目录拓扑

### 二、代码分层机制
- 静态编译 vs 运行时动态编译（Roslyn）
- 生成代码 vs 手写代码的区分方式（命名空间/目录）
- 模块间通信方式（接口抽象/事件总线/直接引用）
- "禁止修改"区域 vs "自由开发"区域

### 三、命名空间约定
- 当前实际命名模式（分层式 vs 模块式）

### 四、技术栈确认
- ORM / DI / API 风格 / 模块化机制 / 前端 / 动态编译 / CI/CD

### 五、痛点与守卫目标
- 希望架构测试具体拦截什么违规

## 验收标准
- 产出架构测试设计文档，包含：约束规则清单、检查机制、与 JNPF 基因的适配说明
- 如果当前信息不足 → 产出结构化的"信息收集清单"而非猜测性方案
