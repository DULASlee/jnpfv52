## 一、项目启动分析

基于 JNPF 平台已有能力，先做一个 **"平台能力 vs 业务需求"** 的匹配分析：

| 智慧工地业务模块             | JNPF 平台已有能力                  | 实现方式                    |
| ---------------------------- | ---------------------------------- | --------------------------- |
| 人员管理（实名制/考勤/门禁） | 组织架构 + 表单设计 + 流程管理     | 低代码配置 + 少量二开       |
| 安全巡检                     | 表单设计 + 流程审批 + 任务调度     | 纯低代码配置                |
| 设备管理（塔吊/升降机监控）  | 需 IoT 数据接入                    | **二开新模块**              |
| 环境监测（扬尘/噪音）        | 需传感器数据接入                   | **二开新模块**              |
| 视频监控                     | 第三方集成                         | 对接海康/大华 SDK           |
| 质量管理                     | 表单 + 流程 + 附件上传             | 低代码配置                  |
| 进度管理                     | 可视化页面 + 表单                  | 低代码 + 少量前端           |
| 预警告警                     | EventBus + 消息中心（站内信/短信） | 二开事件处理 + 平台消息推送 |
| 数据大屏                     | 可视化数据模块                     | 低代码配置 + 自定义图表     |
| 劳务实名制对接               | 第三方集成                         | 对接住建局 API              |

## 二、推荐启动步骤（5 阶段）

```mermaid
graph LR
    A[需求梳理<br/>1-2周] --> B[环境搭建<br/>& 租户配置<br/>1周]
    B --> C[低代码配置<br/>表单/流程/权限<br/>2-3周]
    C --> D[二开模块<br/>IoT/告警/大屏<br/>3-4周]
    D --> E[联调部署<br/>& 交付<br/>1-2周]
```

### 阶段 1：需求梳理与模块规划

1. **梳理客户业务场景** → 输出功能清单
2. **分类标记**：哪些用低代码配置搞定、哪些必须二开
3. **数据模型设计** → 参考 002 文档的表设计规范（TenantCLDSEntityBase 继承体系）

### 阶段 2：环境搭建与租户隔离

```bash
# 按照 003 部署文档快速拉起
docker-compose up -d

# 数据库初始化（主库 + 调度库 + 事件库）
# 参考 002 文档三库架构
```

- 为客户创建**独立租户**（COLUMN 模式：`f_tenant_id` 字段隔离，适合 SaaS 交付）
- 配置组织架构：项目部 → 工区 → 班组 层级

### 阶段 3：低代码快速配置（占 60% 功能）

利用平台可视化能力直接配置：

| 功能       | 操作方式                                  |
| ---------- | ----------------------------------------- |
| 人员花名册 | 表单设计器 → 拖拽字段 → 关联组织架构      |
| 安全巡检单 | 表单 + 审批流程（巡检 → 整改 → 复查闭环） |
| 质量验收   | 表单 + 附件拍照 + 多级审批                |
| 材料进退场 | 表单 + 流程 + 出入库统计                  |
| 考勤汇总   | 定时任务（Sundial 调度）→ 每日汇总报表    |

### 阶段 4：二开新模块（IoT 数据接入 + 告警 + 大屏）

按照 004 开发指南的 **10 步新模块流程**：

```
modularity/smartsite/
├── JNPF.SmartSite/               (Services: 设备接入/环境监测/预警)
├── JNPF.SmartSite.Entitys/       (Entity: 设备/传感器/告警记录)
└── JNPF.SmartSite.Interfaces/    (接口定义)
```

**关键二开点：**

1. **IoT 数据接入 Service**：对接 MQTT/HTTP 协议设备，数据落库
2. **告警规则引擎**：结合 EventBus 发布告警事件 → 消息中心推送
3. **数据大屏**：利用 visualdata 模块 + 自定义 ECharts 组件
4. **视频监控接入**：对接海康 iSC / 大华 ICC 平台 OpenAPI

```csharp
// 示例：设备数据接入后触发告警
await _eventPublisher.PublishAsync("SmartSite:AlarmTriggered", new AlarmPayload
{
    DeviceId = device.Id,
    AlarmType = "dust_exceed",
    Value = currentPM25,
    Threshold = 150
});
```

### 阶段 5：联调部署与交付

- Docker/K8s 部署（参考 003 文档）
- 数据权限配置：项目经理看全部、工区长看本工区、班组长看本班组
- 对接住建局实名制平台（劳务工人信息上报）
