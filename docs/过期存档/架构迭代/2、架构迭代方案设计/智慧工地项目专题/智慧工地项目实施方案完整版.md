## 第一阶段：需求梳理与数据模型设计（第 2-3 天）

> **目标**：将业务需求转化为可执行的功能清单与数据库表结构，明确"配置/二开/对接"三类工作的边界。

### 步骤 1.1：客户业务场景梳理

**输入**：客户提供的智慧工地需求文档 / 招标文件 / 口头需求
**输出**：`智慧工地功能清单.xlsx`（按模块分类、标注优先级）

逐项与客户确认以下业务场景：

| 序号 | 业务场景 | 确认要点 | 产出 |
|------|---------|---------|------|
| 1 | 人员实名制管理 | 是否需要对接住建局实名制平台？班组层级几级？ | 人员管理功能清单 |
| 2 | 考勤管理 | 考勤方式（人脸/刷卡/指纹）？班次规则？ | 考勤功能清单 |
| 3 | 门禁管理 | 闸机品牌型号？开门协议（韦根/RS485/网络）？ | 门禁对接清单 |
| 4 | 安全巡检 | 巡检类型？整改闭环流程节点？ | 巡检流程草稿 |
| 5 | 质量管理 | 验收标准？多级审批层级？ | 质量流程草稿 |
| 6 | 设备监控 | 塔吊/升降机品牌？数据协议？监控指标？ | 设备清单+协议表 |
| 7 | 环境监测 | 扬尘/噪音传感器型号？数据上报协议？ | 传感器清单 |
| 8 | 视频监控 | 摄像头品牌（海康/大华）？NVR 地址？ | 视频对接清单 |
| 9 | 进度管理 | 进度填报粒度（日/周）？是否需要甘特图？ | 进度功能清单 |
| 10 | 数据大屏 | 大屏布局需求？关键指标？刷新频率？ | 大屏原型草稿 |
| 11 | 预警告警 | 告警规则？通知方式（短信/APP/大屏）？ | 告警规则清单 |

**执行方式**：与客户项目经理开 2-3 次需求调研会，每次 1-2 小时，会后 24 小时内输出会议纪要+功能清单更新。

### 步骤 1.2：功能分类标记（配置 / 二开 / 对接）

**输入**：步骤 1.1 产出的功能清单
**输出**：带分类标记的功能清单（`智慧工地功能清单.xlsx` 中增加"实现方式"列）

对照下表进行逐功能分类：

| 实现方式 | 判断标准 | 典型功能 | 工作量占比 |
|---------|---------|---------|-----------|
| **纯低代码配置** | 表单+列表+流程 可覆盖 | 人员花名册、安全巡检、质量验收、材料进退场 | 60% |
| **二开新模块** | 需要自定义 Service/IoT/实时能力 | 设备数据接入、告警引擎、数据大屏 | 30% |
| **三方平台对接** | 调用外部 SDK/API | 视频监控、住建局实名制、人脸识别终端 | 10% |

**关键动作**：
- 每个功能打上 `[配置]` / `[二开]` / `[对接]` 标签
- 二开功能进一步细分为"平台层增强"和"业务层新建"
- 三方对接功能标注 SDK/API 文档链接

### 步骤 1.3：数据模型设计

**输入**：功能清单 + 现有平台数据架构（参考 002 文档）
**输出**：数据库表结构设计文档（即本文 [附录 A](#附录-a核心数据库表结构设计)）

**设计原则**：
1. 所有实体继承 `TenantCLDSEntityBase`（含 CreatorTime / LastModifyTime / DeleteMark / SortCode + TenantId），实现多租户 COLUMN 模式隔离
2. 表名统一 `jnpf_smartsite_` 前缀，字段名 `f_` 前缀（平台强制约定）
3. 主键使用雪花 ID（`Yitter.IdGenerator`）
4. 与现有系统表通过 `f_organize_id`（项目部/工区/班组）关联

**产出表分为 5 个域**：

| 域 | 表数量 | 核心表 |
|----|--------|-------|
| 人员管理域 | 4 张 | `jnpf_smartsite_worker`、`jnpf_smartsite_attendance`、`jnpf_smartsite_access_record`、`jnpf_smartsite_worker_cert` |
| 安全质量域 | 3 张 | `jnpf_smartsite_inspection`、`jnpf_smartsite_quality_check`、`jnpf_smartsite_material_record` |
| 设备管理域 | 5 张 | `jnpf_smartsite_device`、`jnpf_smartsite_sensor`、`jnpf_smartsite_telemetry`、`jnpf_smartsite_alarm_rule`、`jnpf_smartsite_alarm_record` |
| 进度管理域 | 2 张 | `jnpf_smartsite_progress_plan`、`jnpf_smartsite_progress_report` |
| 视频监控域 | 2 张 | `jnpf_smartsite_camera`、`jnpf_smartsite_video_record` |

> 完整字段定义见 [附录 A](#附录-a核心数据库表结构设计)，表结构在步骤 2.3 中通过 SQL 脚本正式创建。

**4.3.2 创建 MqttBridgeService（服务端订阅+分发）**

创建 `modularity/smartsite/JNPF.SmartSite/Services/SmartSite/MqttBridgeService.cs`：

```csharp
public class MqttBridgeService : IMqttBridgeService, ISingleton
{
    private readonly IMqttClient _mqttClient;
    private readonly IEventPublisher _eventPublisher;

    public async Task StartAsync()
    {
        // 1. 连接 MQTT Broker（EMQX 或 MQTTnet Broker）
        // 2. 订阅 device/+/telemetry（通配所有设备遥测）
        // 3. 订阅 device/+/status（设备在线状态）
        // 4. 收到消息 → 解析 JSON → PublishAsync 内部事件
    }

    // 消息处理
    private async Task OnTelemetryReceived(string deviceId, string payload)
    {
        // 解析遥测 JSON → 发布事件
        await _eventPublisher.PublishAsync("SmartSite:TelemetryReceived",
            new TelemetryPayload { DeviceId = deviceId, Data = payload });
    }
}
```
