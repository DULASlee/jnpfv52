---------------------------------------------------------------------------
R1 — API自动生成（NEVER手写Controller）
---------------------------------------------------------------------------
执行层: L2（code-reviewer检测） | Hook: 无

规则: Service实现IDynamicApiController自动映射API。NEVER手写Controller类
理由: JNPF的路由、参数绑定、响应包装全部由框架自动生成。手写=路由重复、响应格式不一致
关联陷阱:
  - Trap 1: 重命名Service方法 = URL变更 = 全前端404
  - Trap 6: 方法名带Async后缀 → 路由含Async → 前端404
  - Trap 9: Service类public方法 = 公开API端点

---------------------------------------------------------------------------
R2 — 统一响应格式
---------------------------------------------------------------------------
执行层: L2（code-reviewer检测） | Hook: 无

规则: RESTfulResult<T>自动包装所有返回值
  - 业务异常: Oops.Bah("msg") → HTTP200 + {code:非200, msg} → 前端展示msg
  - 系统异常: Oops.Oh("msg") → HTTP500 + error log → 前端展示"Internal Server Error"
  - code:600 → JWT过期，前端自动跳转登录
NEVER: 手动new RESTfulResult<T>() 或 throw raw Exception
关联陷阱:
  - Trap 4: Oops.Bah vs Oops.Oh用错 = 用户看到错误信息
  - Trap 5: 手动new RESTfulResult<T>() → 双层data嵌套

---------------------------------------------------------------------------
R3 — 代码生成边界
---------------------------------------------------------------------------
执行层: L2（code-reviewer检测） | Hook: 无

规则: 生成代码有bug → 修.vm模板源码。NEVER直接改模板输出目录下的.cs/.vue文件
理由: 直接改输出→下次生成被覆盖→bug回归
关联陷阱:
  - Trap 12: .vm模板用Velocity语法(#if($x))，不是C#(if(x==null))

---------------------------------------------------------------------------
R5 — 模块边界
---------------------------------------------------------------------------
执行层: L0（Hook硬阻断） | Hook: guard-oa-module.mjs

规则:
  - JNPF.OA.API.Entry → 禁用，禁止写入
  - JNPF.IoT.* → 不存在，禁止创建
  - JNPF.MES.* → 不存在，禁止创建

Hook拦截: OA/IoT/MES路径下的文件写入

---------------------------------------------------------------------------
低代码准则1: 开发前先对齐（零代码优先）
---------------------------------------------------------------------------
执行层: L2 | 来源: low-code-principles.md

动作:
  1.1 接到需求先判断：是否可通过表单设计器/流程设计器/数据字典/权限配置实现 → 优先零代码
  1.2 确认官方扩展方式：代码生成器+分部类/自定义表单控件/插件/事件订阅
  1.3 涉及平台原生能力修改 → 必须先告知升级风险与替代方案
  1.4 需求有歧义 → 列出所有可行路径+优缺点，确认后再动手

---------------------------------------------------------------------------
低代码准则3: 非侵入式扩展
---------------------------------------------------------------------------
执行层: L2 + R5 Hook | 来源: low-code-principles.md

动作:
  3.1 严禁修改平台原生目录源码（framework/、系统服务、设计器核心逻辑）
  3.2 代码生成器输出 → 禁止直接修改；必须通过分部类/继承/事件订阅扩展
  3.3 仅修改用户自定义代码与配置，不调整平台原生配置项/表结构/接口定义
  3.4 自定义模块遵循平台目录结构与命名规范，不与原生命名空间冲突
  3.5 表单/流程配置仅改指定字段与节点

陷阱速查（架构相关，已在R1-R10中覆盖）
---------------------------------------------------------------------------
Trap 1: 方法重命名=URL变更 → 全前端404
Trap 6: Async后缀破坏路由 → GetPageListAsync ≠ GetPageList
Trap 9: public方法=公开API → helper方法也暴露
Trap 4: Oops.Bah vs Oops.Oh用错 → 用户看到错误信息
Trap 5: 手动new RESTfulResult → 双层嵌套
Trap 7: ITenantFilter子查询不生效 → 静默数据泄露
Trap 8: Updateable无Where → 跨租户修改
Trap 12: .vm模板用C#语法 → 生成无效代码
Trap 13: 自定义Filter覆盖TenantFilter → 静默泄露
