Core Principle: Evidence Over Assumption（禁止看源码猜测）
---------------------------------------------------------------------------
禁止通过阅读源码猜测问题。必须抓取运行时数据定位问题。
源码告诉你"代码意图"，运行时数据告诉你"代码行为"。不一致时数据是对的。

场景映射:
  前端无响应      → Playwright page.on('response')抓SSE响应体（禁止读.vue猜）
  API异常          → 浏览器Network面板看请求URL/状态码/响应体（禁止读Controller猜）
  数据错误         → SqlSugar ToSql()输出实际SQL（禁止读SQL拼装逻辑猜）
  Token/认证失败   → console.log输出token实际值+JWT payload解码（禁止读getToken()猜）
  编译通过功能异常  → 数据流边界加诊断日志（禁止再改源码再编译）

排除步骤: 问题>10min未解决→停止改源码→数据采集模式→追踪哪层输出偏离预期。
          猜3次不行就停手抓数据，不猜第4次

论断纪律（全输出强制）
---------------------------------------------------------------------------
来源: assertion-discipline.md

论断标签（所有技术论断/API说明/平台特性 MUST前置标注）:
  [KNOWN]     — 训练数据内已验证的JNPF既定事实
  [COMPUTED]  — 数值计算/代码执行结果
  [INFERRED]  — 基于官方文档推导的方案
  [COMMON]    — .NET/Vue/低代码领域通用常识
  [FRAME]     — 理论方案推演（置信度上限LOW）
  [GUESS]     — 无充分依据的推测（置信度上限LOW）

置信度分级:
  HIGH ≥80% / MED 50-80% / LOW 20-50% / VERYLOW <20% / UNKNOWN 完全未知

边界约束:
  - 禁止编造JNPF官方未公开的API/配置项/扩展方式
  - 禁止将未验证方案包装为官方标准实现
  - 未知内容首句直接声明"我不知道"

输出原则:
  1. 直言风险，不回避方案核心缺陷
  2. 多方案对比时标注各方案失效边界
  3. 不确定时直接声明"我无法确定"
  4. 保留有[KNOWN]/[COMPUTED]支撑的内容，删减无依据细节

事后归因: 若提前不知业务结果 → 标注 [INFERRED, post-hoc]

[RULES I BROKE]: Phase 7统一执行一次自审（不再每输出都追加）

---------------------------------------------------------------------------
反降级铁律（Anti-Degradation Rule）
---------------------------------------------------------------------------
来源: codegraph-exploration.md

遇到以下情况禁止简化/降级，MUST通过CodeGraph完整探索后完整实现:

  信号                     → 正确做法                    → 禁止
  跨模块调用               → impact查全部影响面逐文件适配 → 只改当前文件
  Entity/数据模型变更      → impact查所有引用方          → 只改Entity不管下游
  修改已有API签名          → callers查所有调用方保持兼容 → 直接改签名
  复杂业务逻辑             → explore查相似实现参照模式   → 简化成if-else
  Bug修复（多文件）        → callers+callees确认不引入新问题 → 只修报错那一行

---------------------------------------------------------------------------
工具选择铁律
---------------------------------------------------------------------------
来源: CLAUDE.md Agent Toolchain / codegraph-exploration.md

代码搜索路由:
  调用链/影响面/符号探索  → CodeGraph MCP（callers/callees/impact/explore）
  精确文本/字符串搜索      → Grep
  文件名校模式匹配          → Glob
  已知文件内容阅读          → Read
  不确定用什么工具时        → jnpf_tool_search MCP

禁止:
  - 用Grep查调用链（应用CodeGraph）
  - 用Read盲目扫文件找代码（应用Glob/grep先定位）
  - 跳过Phase 2.5探索直接编码
  - NEVER /opsx:apply改代码（绕过code review）

---------------------------------------------------------------------------
Technical Preferences（技术偏好）
---------------------------------------------------------------------------
  - 优先复用现有代码，不重复造轮子
  - 简单方案 > 过度工程
  - 改动前先评估影响面（Phase 2.5强制）
  - 明确commit message，最小变更集

---------------------------------------------------------------------------
Git Iron Law
---------------------------------------------------------------------------
任何操作前工作树必须 clean / committed / pushed。Stash不是长期存储。
