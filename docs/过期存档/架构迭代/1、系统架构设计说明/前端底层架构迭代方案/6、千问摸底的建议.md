### 第零部分：编译时与语义资产侦察（新增核心）

**目标**：不再关注“代码怎么跑”，而是关注“代码怎么变”。
**逻辑**：代码生成器需要输入（Schema）和输出（Target Code）的精确数据结构。没有这些，我们无法定义 IR，也无法编写 AST 转换器。

#### 任务 0.1：JSON Schema 的语义拓扑与“脏数据”扫描（IR 的原材料）

架构师让你扫 `eval`，但他没让你扫 **Eval 里到底写了什么**。代码生成器最怕的是 Schema 里混入了无法静态分析的“运行时私货”。

- **侦察重点**：提取真实的表单和大屏 JSON 配置，分析其中的**表达式（Expression）**到底有多复杂。

- 追加指令

  ：

  ```bash
  # 1. 提取真实业务的 Form Schema (至少3个复杂表单)
  # 请工程师在浏览器F12的Network中，找到表单设计页的save/load接口，导出Response Body
  # 保存路径：
  # ~/jnpf-survey/web/schema-form-complex-1.json
  # ~/jnpf-survey/web/schema-form-complex-2.json
  # ~/jnpf-survey/web/schema-form-complex-3.json
  
  # 2. 提取真实业务的大屏 Schema (至少2个)
  # 保存路径：
  # ~/jnpf-survey/screen/schema-screen-iot.json
  # ~/jnpf-survey/screen/schema-screen-stat.json
  
  # 3. 【关键】扫描 Schema 中的“表达式”语义（决定 IR 的复杂度）
  # 从上面导出的 JSON 中，提取所有的 visible, disabled, rule, formatter 字段的值
  # 目的：看里面是简单的 "formData.age > 18"，还是复杂的 "function(row) { ... }"
  grep -oP '(?<="visible":")[^"]*' ~/jnpf-survey/web/schema-form-*.json > ~/jnpf-survey/web/expr-visible-patterns.txt
  grep -oP '(?<="rules":")[^"]*' ~/jnpf-survey/web/schema-form-*.json > ~/jnpf-survey/web/expr-rules-patterns.txt
  grep -oP '(?<="formatter":")[^"]*' ~/jnpf-survey/web/schema-form-*.json >> ~/jnpf-survey/web/expr-formatter-patterns.txt
  ```

#### 任务 0.2：组件元数据与接口契约扫描（代码生成器的物料清单）

代码生成器不需要知道组件的 CSS 怎么写，但它必须知道组件的 **Props/Events/Slots** 契约。否则生成的代码全是报错。

- **侦察重点**：核心渲染器（Parser）和基础组件（BasicTable/BasicForm）的类型定义。

- 追加指令

  ：

  ```bash
  # 1. 扫描核心渲染组件的 Props 定义 (这是 IR 转 Vue/uvue 的映射依据)
  for f in $(find $WEB/src/components -iname "*parser*" -o -iname "*basic*table*" -o -iname "*basic*form*" | grep ".vue$"); do
    echo "===== [元数据] $f Props 定义 =====" >> ~/jnpf-survey/web/component-contracts.txt
    # 提取 defineProps 或 props: {} 的核心片段
    sed -n '/defineProps\|props:/,/}/p' "$f" | head -50 >> ~/jnpf-survey/web/component-contracts.txt
    echo -e "\n\n" >> ~/jnpf-survey/web/component-contracts.txt
  done
  
  # 2. 扫描组件库的导出注册 (JnpfComponentLibrary)
  # 看看 index.ts 里到底 export 了什么
  find $WEB/src/components -name "index.ts" -o -name "index.js" | head -5
  ```
