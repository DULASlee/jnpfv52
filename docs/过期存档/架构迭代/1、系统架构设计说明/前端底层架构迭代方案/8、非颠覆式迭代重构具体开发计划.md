### 2.4 风险与应对

```

  应对：F-1 的表达式分类器设计了 4 级分级
        empty/simple 直接处理

  应对：mobileConfig 是独立的 IR 字段

        第一批只验证 PC 端，App 端在后续编译器中验证
```

## 三、F-2：安全表达式引擎（2 周）

### 3.1 目标

```
实现一个安全的、可扩展的表达式引擎，
替代所有 eval / new Function，
为渲染引擎和编译器提供统一的表达式求值能力。

这不是一个通用的 JS 解释器，
而是针对 JNPF 表达式模式的专用求值器。
```

### 3.2 表达式语法子集

```
基于 Phase 0 的真实数据，引擎需要支持以下语法：

字面量：数字、字符串、布尔值、null、undefined
属性访问：formData.name、data[0].value
比较运算：==、!=、>、<、>=、<=
逻辑运算：&&、||、!
三元表达式：condition ? a : b
算术运算：+、-、*、/、%
空值合并：value ?? defaultValue
白名单函数：
  字符串：LEN UPPER LOWER TRIM CONTAINS REPLACE
  数学：  ROUND CEIL FLOOR ABS MAX MIN
  条件：  IF IF_EMPTY IF_NULL
  日期：  TODAY NOW FORMAT_DATE
  格式化：FORMAT_MONEY MASK_PHONE MASK_ID_CARD
赋值表达式：formData.xxx = value（表单联动场景）
属性读取：formData.xxx（数据绑定场景）

不支持（安全红线）：
  ❌ 函数定义
  ❌ 类定义
  ❌ import / require
  ❌ this / window / document / globalThis
  ❌ eval / new Function
  ❌ __proto__ / constructor / prototype
  ❌ fetch / axios / XMLHttpRequest
  ❌ setTimeout / setInterval
```

### 3.3 交付物

```
F-2.1  表达式引擎核心
  文件：src/core/expression/engine.ts
  内容：
    ExpressionEngine 类
      evaluate(expr, context) → unknown     — 求值
      evaluateBatch(exprs, context) → unknown[] — 批量求值
      extractDependencies(expr) → string[]  — 依赖提取
      validate(expr) → { valid, error }     — 语法校验
    内部管线：
      tokenize(expr) → Token[]              — 词法分析
      parse(tokens) → AST                   — 语法分析
      securityCheck(ast) → void             — 安全检查（抛异常 if 危险）
      compile(ast) → CompiledExpr           — 编译（生成可执行函数）
    缓存：同一表达式只编译一次
    安全：所有危险操作在 parse 阶段拒绝，不是在 execute 阶段拦截

F-2.2  白名单函数库
  文件：src/core/expression/functions.ts
  内容：
    所有可被表达式调用的内置函数
    每个函数有明确的参数类型和返回类型
    新增函数必须显式注册（不允许动态扩展）

F-2.3  沙箱上下文
  文件：src/core/expression/context.ts
  内容：
    createEvalContext(data) → EvalContext
    将用户的 formData 等数据包装为安全的上下文对象
    使用 Proxy 拦截所有属性访问，禁止访问危险属性

F-2.4  兼容层
  文件：src/core/expression/compat.ts
  内容：
    safeEval(expression, data) → unknown      — 兼容 eval 的签名
    safeFunction(body, ...params) → Function  — 兼容 new Function 的签名
    这两个函数内部调用 ExpressionEngine
    现有代码替换 eval 时只需改一行 import

F-2.5  单元测试
  文件：src/core/expression/__tests__/engine.test.ts
  测试用例：
    ✅ 字面量求值
    ✅ 属性访问（单层、嵌套、数组索引）
    ✅ 比较运算（所有操作符）
    ✅ 逻辑运算（短路求值）
    ✅ 三元表达式
    ✅ 算术运算
    ✅ 白名单函数（每个函数至少 1 个用例）
    ✅ 安全拒绝（this/window/document/fetch/eval/__proto__）
    ✅ 缓存命中（第二次求值不重新编译）
    ✅ 批量求值
    ✅ 依赖提取
    ✅ 语法错误处理（不崩溃，返回 undefined + console.warn）
```

## 五、F-4：Vue3 单表 CRUD 编译器（3 周）

### 5.1 目标

```
实现第一个编译器——将 IR 编译为可独立运行的 Vue 3 单表 CRUD 代码。

"可独立运行"的定义：
  技术独立：npm install && npm run dev 能启动
  不依赖 JNPF 平台运行时（不依赖 jnpfParser / BasicForm）
  使用标准 npm 包（ant-design-vue / axios / lodash-es）
  默认对接 JNPF 后端 API（通过 @jnpf/shared 或独立的 API 层）

"可读可改"的定义：
  标准 Vue 3 Composition API（任何 Vue 开发者都能看懂）
  标准 Ant Design Vue 组件（不是自定义封装）
  每个函数职责单一，10-20 行
  TypeScript 类型完整
  带生成标记（@jnpf-generated + hash）
```

```
    IR fields → TypeScript interface
    生成 types/{entity}.ts
    包含实体接口 + 列表查询参数接口 + 创建/更新参数接口

F-4.3  API 生成器（Stage 2）
  文件：src/core/compiler/vue3/api-gen.ts
  内容：
    IR → api/{entity}.ts
    生成标准 RESTful 函数：getList / getDetail / create / update / delete
    使用 axios 或 @jnpf/shared/http
    包含请求参数类型和响应类型

F-4.4  列表页生成器（Stage 3）
  文件：src/core/compiler/vue3/list-gen.ts
  内容：
    IR + listConfig → views/{entity}/index.vue
    生成内容：
      搜索表单（从 listConfig.searchFields 生成）
      操作按钮（从 IR 的权限配置生成，带 v-permission）
      数据表格（从 listConfig.columns 生成）
      分页组件
      新增/编辑弹窗引用
    生成 views/{entity}/columns.ts（列配置，与视图分离）
    生成 views/{entity}/search.ts（搜索配置，与视图分离）
    生成标记：@jnpf-generated v1.0.0 hash=xxx

F-4.5  表单页生成器（Stage 4）
  文件：src/core/compiler/vue3/form-gen.ts
  内容：
    IR + fields → views/{entity}/form.vue
    生成内容：
      表单字段（从 IR fields 生成，使用组件映射）
      校验规则（从 IR validation 生成）
      联动逻辑（从 IR expressions 中 field-event 类型生成）
      提交逻辑（从 IR expressions 中 form-lifecycle 类型生成）
    expression level 为 complex 的代码块标记为 TODO

F-4.6  Hook 生成器（Stage 5）
  文件：src/core/compiler/vue3/hook-gen.ts
  内容：
    IR → composables/use{Entity}.ts
    生成内容：
      use{Entity}List() — 列表查询 composable
      use{Entity}Form() — 表单操作 composable
    封装 loading / data / pagination / search / CRUD 逻辑

F-4.7  生成标记注入器
  文件：src/core/compiler/vue3/marker.ts
  内容：
    在每个生成的文件头部注入标记：
      // @jnpf-generated v1.0.0 entity={entityName} hash={irHash}
      // 生成时间：{timestamp}
      // 此文件由 JNPF 代码生成器生成，可手动修改
      // 重新生成时，hash 变化的部分将被覆盖
    在可扩展的代码块注入 insert-point：
      // @jnpf-gen:insert-point=custom-actions
      // @jnpf-gen:insert-point=custom-logic
    hash 基于 IR 片段计算——IR 不变则 hash 不变

F-4.8  编译器测试
  文件：src/core/compiler/__tests__/vue3-compiler.test.ts
  测试用例：
    ✅ 生成的文件数量正确

    ✅ 生成的 Vue SFC 语法正确
    ✅ 生成的 API 函数覆盖所有 CRUD 操作
    ✅ 生成的表格列与 IR columns 一致
    ✅ 生成的表单字段与 IR fields 一致
    ✅ 生成标记正确注入
    ✅ empty 级别的表达式被忽略
    ✅ simple 级别的表达式正确编译
    ✅ complex 级别的表达式标记为 TODO

F-4.9  代码质量验证
```
