## 一、Stage 1 骨架预分析（如何产出“催化级骨架”）

这是整个系统的“任督二脉”，不能靠一个简单的 prompt 搞定，需要用一个**专门的骨架提取 Agent**。

### 1.1 骨架提取 Agent 的设计

**System Prompt 核心片段**：

```text
你是一个企业管理系统业务架构师。你的任务是从用户提供的原始需求材料中，
提取出精准、结构化的“业务与数据骨架”，为后续深度分析提供催化剂。

请严格遵循以下输出格式（JSON），不得遗漏、不得模糊：

{
  "business_events": [
    {
      "event_id": "EVT001",
      "event_name": "<业务术语，如：车间工人提交工序报工>",
      "trigger": "<触发条件>",
      "primary_actor": "<角色>",
      "involved_roles": ["<角色1>","<角色2>"],
      "brief_description": "<一句话描述>",
      "related_entities": ["<实体1>","<实体2>"]
    }
  ],
  "role_matrix": [
    {
      "role": "<角色名称>",
      "responsibilities": ["<职责1>","<职责2>"],
      "permissions_boundary": "<权限边界描述>"
    }
  ],
  "core_business_flows": [
    {
      "flow_name": "<流程名，如：报工流程>",
      "steps": [
        { "step": 1, "action": "<动作>", "by": "<角色>" },
        ...
      ],
      "exception_branches": [
        { "condition": "<异常条件>", "handling": "<处理方式>" }
      ]
    }
  ],
  "database_schema_draft": {
    "tables": [
      {
        "table_name": "work_order",
        "fields": [
          { "name": "work_order_id", "type": "INT", "constraints": "PRIMARY KEY" },
          { "name": "part_id", "type": "INT", "constraints": "FOREIGN KEY → part.part_id" },
          { "name": "quantity", "type": "INT" },
          { "name": "status", "type": "NVARCHAR(20)" }
        ]
      }
    ],
    "relationships": [
      { "from": "work_order.part_id", "to": "part.part_id", "type": "N:1" }
    ]
  }
}
```

**关键约束**：
- 事件必须用业务术语，不能写“新增报工记录”，要写“工人提交工序报工”
- 角色不能写“管理员”，要具体到“车间工人”“质检员”“车间主任”
- 表结构必须有主外键关系，哪怕是初步推测

### 1.2 骨架产物的质量门禁

在骨架进入 Stage 2 之前，加一道轻量校验（不是之前的 7 重校验，就是几个 if）：

```typescript
function validateSkeleton(skeleton: any): void {
  // 必须有至少 1 个业务事件
  if (!skeleton.business_events?.length) throw new Error('骨架缺少业务事件');
  // 每个事件必须有主角色
  skeleton.business_events.forEach((evt, i) => {
    if (!evt.primary_actor) throw new Error(`事件 ${i+1} 缺少 primary_actor`);
  });
  // 必须有数据库表结构草案，至少 1 张表
  if (!skeleton.database_schema_draft?.tables?.length) throw new Error('骨架缺少数据库表结构');
  // 表必须有主键
  skeleton.database_schema_draft.tables.forEach((t, i) => {
    const hasPK = t.fields.some(f => f.constraints?.includes('PRIMARY KEY'));
    if (!hasPK) throw new Error(`表 ${t.table_name} 缺少主键`);
  });
}
```

只有通过门禁的骨架才能进入 Stage 2，否则返回给用户要求补充材料。

## 二、Stage 2 事件精炼 Agent（拿着骨架对账，产生井喷）

### 2.1 事件精炼 Agent 的 System Prompt 设计

```text
你是一个制造业需求分析专家。你的任务是针对单个业务事件，与用户进行深度需求确认。

你已经拿到以下“业务与数据骨架”片段，只针对当前事件：
- 事件名称：{event.event_name}
- 触发条件：{event.trigger}
- 相关角色：{event.involved_roles}
- 相关流程：{event相关流程步骤}
- 涉及的数据表及字段（含主外键）：
  {相关表结构，带字段和主外键}

请按照以下策略进行多轮对话，每轮最多问 2 个问题，逐步深入：

1. 第一轮：确认流程完整性。
   根据流程步骤，询问“是否有遗漏步骤？异常情况如何处理？”
   例如：“流程中‘工人提交报工’后，如果质检不合格，是直接通知工人还是生成返工单？”

2. 第二轮：根据主外键关系追问业务规则。
   重点关注外键指向的实体，问出隐含的业务逻辑。
   例如：“work_order.part_id 关联了零件表。当工单关联的零件有多个版本时，报工时是否需要指定零件版本？”
   或者：“operation_report.worker_id 关联员工表。报工记录的工人是否必须与工单指派的工人一致？如果代班如何处理？”

3. 第三轮：根据字段类型追问数据细节。
   例如：“defective_qty 字段记录不合格数。是否需要区分不合格原因？比如设备故障、操作失误、来料不良？”
   这会触发增加字段或新实体。

4. 最终轮：汇总该事件的需求确认结果，生成《事件需求规格》，
   并询问：“以上确认是否完整？如完整则进入下一事件，否则继续补充。”
```

### 2.2 事件精炼的实现（代码框架）

```typescript
// stage2_eventRefinement.ts
export async function refineEvent(
  event: BusinessEvent,
  skeleton: Skeleton,
  conversationHistory: Message[] = []
): Promise<EventSpecification> {
  
  // 1. 从骨架中裁剪出本事件相关的上下文
  const eventContext = {
    event,
    relatedFlow: skeleton.core_business_flows.filter(f => 
      f.steps.some(s => s.by === event.primary_actor)),
    relatedTables: findRelatedTables(skeleton.database_schema_draft, event.related_entities),
    relatedRoles: event.involved_roles.map(r => 
      skeleton.role_matrix.find(rm => rm.role === r)).filter(Boolean)
  };

  // 2. 构建 system prompt（注入催化骨架）
  const systemPrompt = buildEventSystemPrompt(eventContext);

  // 3. 多轮对话循环，直到用户确认
  let confirmed = false;
  let rounds = 0;
  const maxRounds = 10;
  let accumulatedSpec: Partial<EventSpecification> = {};

  while (!confirmed && rounds < maxRounds) {
    const response = await callLLM(systemPrompt, {
      conversation: conversationHistory,
      currentSpec: accumulatedSpec,
    });

    // 展示给用户，获取用户反馈
    const userFeedback = await presentToUser(response);
    conversationHistory.push({ role: 'assistant', content: response.question });
    conversationHistory.push({ role: 'user', content: userFeedback });

    // 更新累积的规格
    accumulatedSpec = mergeSpec(accumulatedSpec, response.updatedSpec);

    if (response.isComplete) {
      confirmed = true;
    }
    rounds++;
  }

  // 4. 保存《事件需求规格》
  const specId = await saveEventSpec(event.event_id, accumulatedSpec);
  return accumulatedSpec;
}
```

export async function runSA(req: SARequest): Promise<SAOutput> {
  // 幂等检查...
  return withTransaction(async (trx) => {
    
    // Step 1: Scope 全局跑
    const scope = guardScope(await callLLM(SCOPE_PROMPT, req.requirementText));
    const scopeId = await saveScope(scope, req.userId, trx);

    // Step 2-3: DFD 和判定表按事件跑，再汇总
    const events = req.eventSpecs; // 从 Stage 2 产出传入
    let globalDFD: DFD = { processes: [], dataFlows: [], externalEntities: [] };
    const decisionTables: DecisionTable[] = [];

    for (const event of events) {
      // 为每个事件生成独立 DFD
      const dfd = guardDFD(await callLLM(DFD_PROMPT, {
        requirement: event.specification,
        scope: scope
      }));
      globalDFD = mergeDFD(globalDFD, dfd);

      // 为每个事件生成判定表
      const dt = guardDecisionTable(await callLLM(DECISION_TABLE_PROMPT, {
        event: event.specification,
        dfd: dfd
      }));
      decisionTables.push(dt);
    }

    const dfdId = await saveDFD(globalDFD, scopeId, req.userId, trx);
    const dtIds = [];
    for (const dt of decisionTables) {
      dtIds.push(await saveDecisionTable(dt, scopeId, req.userId, trx));
    }

    // Step 4-9: 基于汇总数据执行
    const dataDict = guardDataDict(await callLLM(DATA_DICT_PROMPT, {
      requirement: req.requirementText,
      events: events
    }));
    const dataDictId = await saveDataDict(dataDict, scopeId, req.userId, trx);
    // ...其余步骤类似

    // 组装快照，记录版本
    const snapshot = buildSnapshot({ scope, globalDFD, decisionTables, dataDict, /*...*/ });
    await recordAnalysisRun(req.tenantId, req.projectId, reqHash, version, snapshot, trx);

    return { snapshot, doc: generateMarkdownDoc(snapshot) };
