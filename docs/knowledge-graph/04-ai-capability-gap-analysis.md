### 2.1 低代码赛道

| 能力 | 简道云 | 明道云 | 宜搭 | 轻流 | JNPF |
|------|--------|--------|------|------|------|

| AI 业务流程推荐 | ❌ | ❌ | ❌ | ✅ | ❌ |
| AI 代码生成 | ❌ | ❌ | ❌ | ❌ | ⚠️ 模板式 (.vm) |

### 2.2 AI 原生工具（"小白 AI"）

| 工具 | 核心能力 | 对 JNPF 的冲击 |
|------|----------|----------------|
| **Cursor** | AI 代码编辑器，自然语言→全栈应用 | 高 — "5 分钟生成 CRUD 应用" |
| **Bolt.new** | 浏览器内 AI 全栈应用生成 | 高 — 零部署成本的完整应用 |
| **v0.dev** | AI 前端 UI 生成 (Vercel) | 中 — 仅前端，无业务逻辑 |
| **Lovable** | AI 全栈应用生成 | 高 — 完整 SaaS 应用生成 |
| **Replit Agent** | 在线 AI 编程环境 | 中 — 偏开发环境 |
| **GPT Engineer** | 自然语言 → 完整代码库 | 高 — 直接竞品 |

### 2.3 "小白 AI"具体冲击分析

```
场景：客户说"我要一个客户管理系统"

Cursor/Bolt/Lovable:
  5 分钟 → 完整 CRUD 应用 + 数据库 + 登录 + 部署链接
  JNPF:
    步骤 1: 登录 JNPF 后台
    步骤 2: 在线设计器创建模型
    步骤 3: 配置表单字段
    步骤 4: 配置列表列
    步骤 5: 配置搜索条件
    步骤 6: 生成代码
    步骤 7: 部署
    总耗时: 30 分钟 - 2 小时（取决于复杂度）

结论：在"简单 CRUD 应用"维度，AI 原生工具已在速度上完胜 JNPF。
```

**但这恰恰证明了 JNPF 的优势在别处：**

| 维度 | AI 原生工具 | JNPF |
|------|-----------|------|
| 简单 CRUD | ✅ 5 分钟 | ⚠️ 30 分钟 |
| 复杂业务规则 | ❌ 无法理解 | ✅ 工作流引擎 + 条件表达式 |
| 企业级安全 | ❌ 无 RBAC | ✅ 租户隔离 + 数据权限 |
| 多系统集成 | ❌ 无 | ✅ OpenAPI Gateway + EventBus |
| 流程审批 | ❌ 无 | ✅ 7 态状态机工作流 |
| 跨表关联 | ❌ 需要手动编码 | ✅ 在线设计器 RelationForm |
| 领域知识沉淀 | ❌ 每次从零开始 | ✅ .vm 模板 + DKEE（计划中） |
| 可审计性 | ❌ AI 生成不可预测 | ✅ 确定性编译器 |

**JNPF 的护城河不在"快速生成 CRUD"，而在"管理企业复杂业务规则"。**

## 3. 差异化方向

### 3.1 AI 业务规则推理 — 无竞品做到

```
当前：用户手动在工作流中绘制审批节点、配置条件分支

AI 增强后：
  自然语言输入："金额超过 10000 元的采购申请需要部门总监审批，
  超过 50000 元需要财务总监审批，紧急采购走绿色通道"

  → AI 解析业务规则
  → 生成工作流节点 + 条件分支
  → 用户确认 → 部署到 FlowEngine

这与 AI 原生工具的区别：
  - AI 原生工具生成的是"通用逻辑"
  - JNPF 理解的是"企业特定业务规则"
  - 关键差异：领域知识图谱（DKEE）提供上下文
```

### 3.2 自博弈进化 — 无竞品尝试

```
传统低代码：用户设计 → 系统执行 → 用户发现缺陷 → 手动修改 → 重新发布

自博弈引擎：
  用户设计 → 系统执行 → AI 模拟 10000 次使用场景
  → 发现边缘情况（如"当金额为负数时审批流程断裂"）
  → 自动建议修复 → 修复后再次自博弈
  → 只到 "dry run" 无新问题 → 才能发布

关键基础设施需求（已确认）：
  - 沙箱容器：单体 Docker 30 秒启动（ADR-016 确认不使用微服务）
  - DKEE：存储领域规则和约束
  - EAB：逻辑边界确保自博弈不破坏真实数据
```

### 3.3 顾问式 AI — 差异化体验

```
传统低代码用户：独自面对空白画布，不知道从哪开始

顾问式 AI：
  "我看到你选了'采购管理'模板，这个行业通常需要以下字段：
    采购单号（自动生成）、供应商、商品明细（子表）、
    单价、数量、总价（自动计算）、申请部门、
    审批流程（金额分级）。需要我帮你预填吗？"

  核心技术：
    - DKEE：存储"采购管理"的领域知识
    - IR + aiHints：理解当前表单的语义结构
    - 大模型网关：生成自然语言建议
    - 自博弈引擎：验证建议的合理性
```
