### 1. 物理隔离：每次调用都是全新会话
- 外部状态机通过 API 为每个阶段发起一个**独立的、无历史消息的对话**。
- 每次仅注入本角色的灵魂文件（`soul.md`）和该阶段专属规则，历史包袱为零。
- 会话完成后立即销毁，不保留任何记忆残留，从根本上杜绝角色污染。

### 2. 文件级交接：结构化的“契约文本”
- 每个角色将产出写入约定文件（如 `architect_output.json`）。
- 交接格式是**严格 Schema 的 JSON**，不包含自然语言闲聊。例：
  ```json
  {
    "requirements": [...],
    "options": [{"name":"A", "pros":["..."]}, {"name":"B", ...}],
    "recommendation": "方案B",
    "failure_boundary": "若第三方库存接口超时>2s，降级为人工创建"
  }
  ```
- 下一阶段只读取这些 JSON 文件作为输入，绝不阅读上一阶段的完整聊天记录。

### 3. 阶段性会话重建：按需拼装最小上下文
- 状态机在进入新阶段前，重新构建本次会话的消息列表：
  ```
  系统: {角色soul.md + 专属规则}
  用户: “当前任务输入见 @/task/current.json，上一阶段产出见 @/output/architect.json，请开始本阶段。”
  ```
- 如果需要引用更早的决策，通过决策追溯文件（`decisions.md`）按关键词检索，而非堆积长上下文。
- 每个角色只看见“自己眼前的这一棒”，不承担传递全部历史的使命。

### 实施后的直接收益
- **无角色污染**：架构师从未见过开发者的实现细节，开发者从不知晓审查员的挑剔习惯。
- **上下文极致纯净**：单次调用有效 Token 近乎 100% 投向业务内容。
- **可自由重试与分支**：任何阶段失败，只需重跑该阶段的一次独立调用，而不会污染其他阶段。实现“上下文物理隔离 + 文件级交接 + 阶段性会话重建”的核心在于：将 LLM 从“流程控制者”降级为“无状态的计算函数”，由外部代码（状态机）接管流程。

以下是简略的工程实现方案：

核心架构：外部状态机调度
不要让 LLM 决定下一步做什么。使用 Python/Node.js 编写一个外部调度脚本（Orchestrator），通过硬编码的状态机（如 Phase 1 -> Phase 2 -> Phase 3）来驱动流程。

定义文件级交接契约（IPC）
为每个阶段定义严格的输入文件和输出文件，作为阶段间唯一的通信桥梁。
Phase 2 (架构师)：输入 requirements.md ➔ 输出 workspace/architecture.json
Phase 3 (规划师)：输入 architecture.json ➔ 输出 workspace/plan.json (DAG任务图)
Phase 4 (开发者)：输入 plan.json 中的单个节点 + 相关代码 ➔ 输出 workspace/code_diff.patch

阶段性会话重建（生命周期管理）
每个阶段执行时，严格遵循以下 4 个步骤：

初始化（清空）：启动一个全新的 LLM API 请求/会话，绝不携带上一阶段的 messages 历史。
注入（组装 Prompt）：
    读取当前阶段的专属 System Prompt（如 architect_prompt.txt）。
    读取前置阶段产出的交接文件内容，作为 User Prompt 的一部分注入。
执行与提取（约束输出）：要求 LLM 以结构化格式（如 JSON 或特定代码块）输出结果。外部脚本通过正则或 JSON 解析，提取核心产物。
持久化与销毁（落盘）：将提取的产物写入下一阶段的输入文件，然后彻底销毁当前 LLM 会话。

class FuguPipeline:
    # 定义阶段及其对应的失败回退目标
    transitions = {
        "brainstorm": {"next": "explore", "fail": "brainstorm"},
        "explore": {"next": "decompose", "fail": "brainstorm"},
        "decompose": {"next": "build", "fail": "explore"},
        "build": {"next": "verify", "fail": "build"}, # 开发失败，重做开发
        "verify": {"next": "review", "fail": "build"}, # 测试失败，打回重写
        "review": {"next": "report", "fail": "build"}, # 审查失败，打回重写
        "report": {"next": "END", "fail": "END"}
    }
    def run_task(self, task_id):
        state = self.load_state(task_id) # 从 state.json 读取上次断点
        while state['phase'] != 'END':
            current_phase = state['phase']
            # 1. 组装最小上下文 (角色灵魂 + 阶段输入)
            prompt = self.assemble_prompt(current_phase, state)
            # 2. 调用 LLM (强制 JSON 输出)
            llm_output = call_claude(prompt, force_json=True)
            # 3. 执行确定性质量门 (安全守卫/编译/测试)
            qg_result = self.run_quality_gates(current_phase, llm_output)
            if qg_result['passed']:
                # 保存产出物到文件系统
                self.persist_output(task_id, current_phase, llm_output)
                # 推进状态
                state['phase'] = self.transitions[current_phase]['next']
            else:
                # 注入失败原因，准备重试
                state['error_context'] = qg_result['errors']
                state['phase'] = self.transitions[current_phase]['fail']
                # 如果连续失败3次，熔断并报警
                if self.retry_count(task_id, current_phase) >= 3:
                    self.alert_human_intervention(task_id)
                    break
            self.save_state(task_id, state)
