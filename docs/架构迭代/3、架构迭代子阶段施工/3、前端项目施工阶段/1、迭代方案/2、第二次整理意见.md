## 二、关键决策变更：water 整体移除

你做了正确的判断。water 没有后端代码，意味着：

```
water 的完整存在状态：
├── 前端页面：仅存在于 dist_v1.1 编译产物中
├── 后端服务：不存在（ZX_Water 6条API路径无对应Service）
├── 数据库表：不存在
└── 结论：这是一个"前端孤岛"，没有后端支撑 = 不可能正常使用

因此：
├── 不是"dist有所以源码要补"→ 因为补了前端也跑不通
├── 而是"从dist中清除water残留"→ 因为它是无效代码
└── 这改变了GAP-01的性质：从"待补"变为"待清"
```

**处置方式：** 不是在源码中补water页面，而是在以下位置清除water关联：

```
需要清除water关联的位置（确认清单）：

1. 后端数据库
   ├── BASE_MODULE 表中 → 查找 urlAddress 包含 water 的菜单节点 → 禁用/删除
   └── BASE_AUTHORIZE 表中 → 查找关联的按钮权限 → 清理

2. 前端 dist_v1.1 中的 water chunk
   └── 不需要手动清理 —— 新构建的源码中本来就没有water，
       新dist自然不会有water的chunk

3. 后端API路由
   └── ZX_Water 相关的6条API路径 → 如果后端没有对应Controller，
       本身就是死路由，无需处理（或者加一条路由黑名单防止404噪音）
```
