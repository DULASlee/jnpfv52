### 为什么 UniApp 是核心

```
v5.2 低代码的价值闭环：

  可视化设计器（拖拽表单）
       ↓
  发布为 Web 页面（主 WEB 中运行）
       ↓
  生成 UniApp 移动端页面 ← 这是 v5.2 独有的能力
       ↓
  移动端直接访问

如果 UniApp 代码生成跑通：
  → 一个表单设计，同时产出 Web + 移动端
  → 这是选择 v5.2 而非继续用 v3.6 的核心理由
```

### 第一步：UniApp 项目现状确认

工程师需要先摸清 UniApp 项目的启动状态和与后端的对接方式。

```
需要确认的 5 个问题：

Q1: UniApp 项目路径
    d:\JNPF-v52\jnpf-app-vue3\
    确认目录存在、package.json 或 manifest.json 存在

Q2: 项目类型和启动方式
    → 是 Vue3 + uni-app CLI 项目？
    → 还是 HBuilderX 项目（无 package.json，有 manifest.json）？
    → 启动命令是什么？（npm run dev:h5 / pnpm dev:h5 / 其他）

Q3: 后端 API 地址配置
    → manifest.json 或 .env 文件中的 API 地址是什么？
    → 需要改为 http://localhost:30000

Q4: H5 模式是否可用
    → H5 模式可以在浏览器预览，不需要真机
    → 如果有 dev:h5 script → 直接启动
    → 如果没有 → 需要 HBuilderX 或 uni-cli

Q5: 与主 WEB 的关系
    → UniApp 是否完全独立运行？
    → 还是需要从主 WEB 跳转过来（SSO/Token 传递）？
    → 登录是否独立？
```

### 第二步：低代码→UniApp 的完整链路验证

这是核心验证目标。需要走通从表单设计到移动端访问的完整链路。

```
验证链路（10 步）：

[1] 低代码：创建数据模型
    路径：主 WEB → 在线开发 → 可视化设计（或数据建模）
    操作：
      → 新建数据表/模型
      → 名称：移动端测试表单
      → 添加字段：
        - 姓名（单行文本，必填）
        - 性别（下拉选择，选项：男/女）
        - 手机号（单行文本）
        - 备注（多行文本）
      → 保存
    预期：模型创建成功，数据库中出现对应表

[2] 低代码：设计表单界面
    路径：可视化设计器
    操作：
      → 拖入"单行文本"组件 → 绑定"姓名"字段
      → 拖入"下拉选择"组件 → 绑定"性别"字段
      → 拖入"单行文本"组件 → 绑定"手机号"字段
      → 拖入"多行文本"组件 → 绑定"备注"字段
      → 拖入"按钮"组件 → 类型"提交"
      → 保存
    预期：表单设计保存成功

[3] 低代码：生成 Web 页面
    操作：
      → 点击"生成页面"或"发布"
      → 确认生成了一个菜单/页面入口
    预期：左侧菜单出现新页面

[4] Web 端验证
    操作：
      → 点击新生成的菜单
      → 填写表单：姓名=测试用户，性别=男，手机号=13800138000，备注=测试
      → 提交
    预期：数据保存成功，列表中出现记录

[5] 低代码：生成 UniApp 页面（关键步骤）
    路径：可视化设计器 → 找到"生成移动端"或"UniApp"相关选项
    操作：
      → 点击"生成App页面"或类似按钮
      → 确认生成了移动端页面配置
    预期：生成成功，有明确的成功提示
    
    ⚠ 这一步可能的位置：
      a. 设计器顶部工具栏中的"生成App"按钮
      b. 发布设置中勾选"同步到App"
      c. 在线开发 → UniApp配置 或 App发布 中操作
      d. 需要先在"应用管理"中创建一个 App 类型的应用
    → 如果找不到入口，截图设计器完整界面发来

[6] 确认 UniApp 端数据
    操作：
      → 打开 UniApp（H5 模式或 HBuilderX 预览）
      → 确认移动端页面中能看到"移动端测试表单"
    预期：页面可访问

[7] UniApp 端填写并提交
    操作：
      → 在移动端页面填写表单
      → 提交
    预期：数据保存成功

[8] Web 端验证移动端提交的数据
    操作：
      → 回到主 WEB 的"移动端测试表单"页面
      → 刷新列表
    预期：能看到移动端提交的数据（步骤 7 的数据）

核心链路闭环：
  创建数据模型 → 设计表单 → 生成 Web 页面 → Web 端提交
  → 生成 UniApp 页面 → UniApp 端提交 → 数据互通
```

### 第三步：如果链路中某一步失败

```
最可能的卡点和处理方式：

卡点 A：找不到"生成 App 页面"入口
  → 可能需要先在"应用管理"中创建一个 App 类型的应用
  → 或者在项目设置中启用 UniApp 模块
  → 截图设计器完整界面 + 左侧菜单结构发来

卡点 B：UniApp 无法启动（H5 模式报错）
  → 可能需要安装 @dcloudio/uni-cli
  → 或者用 HBuilderX 的"运行到浏览器"功能
  → 贴出启动报错信息

卡点 C：UniApp 启动后页面空白
  → 检查 API 地址配置是否指向 :30000
  → 检查浏览器控制台是否有 CORS 错误或 404
  → 贴出控制台日志

卡点 D：UniApp 登录后看不到页面
  → 可能是 UniApp 的菜单/路由配置与后端不一致
  → 或者 UniApp 连接的是不同的 API 地址
  → 检查 UniApp 的网络请求（F12 或 HBuilderX 网络面板）

每个卡点：不要猜修，截图 + 错误信息 + 网络请求发来。
```
