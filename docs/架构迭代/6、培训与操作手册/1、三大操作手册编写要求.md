### 0. 背景与编写目的

v5.2 迁移项目的所有技术工作——编译、数据库迁移、API 打通、前端联调——都只是"让系统能跑"。但系统能跑不等于团队能用。

低代码设计器和大屏设计器中，每一个表单的每一个字段都有特定的格式要求、枚举值含义、关联关系。不理解代码的人面对这些下拉框和输入框，根本不知道选什么、填什么。自己摸索可能要一个月，而工程师看着代码几天就能写清楚。

三份手册的价值：

```
手册一（主 WEB）：低代码表单设计 → Web 页面生成 → CRUD 运行
  → 这是整个低代码体系的基础
  → 大屏和 UniApp 都建立在这个基础上

手册二（数字大屏）：数据源 → 数据集 → 组件 → 大屏设计 → 发布
  → 独立的数据可视化能力

手册三（UniApp）：低代码表单 → 移动端页面生成 → 数据互通
  → v5.2 最核心的价值——一个设计产出 Web + 移动端
```

技术迁移会结束，这三份手册会持续指导团队使用 v5.2 的核心功能。

**所有操作步骤都要写到以下颗粒度。**

```

操作入口：
  主 WEB → 在线开发 → 功能设计 → 新建

操作步骤：

  Step 1：基础信息填写
  
    字段：功能名称
    填法：自定义名称，如"巡检记录"
    
    字段：功能编码（F_EN_CODE）
    填法：英文+数字+下划线，如 inspectionRecord
    注意：不能用中文、不能有空格、不能有连字符
    来源：代码中 Regex 校验逻辑
    
    字段：数据表名
    填法：系统自动生成，格式为 mt{随机ID}
    不要手动修改
    
    字段：所属分类
    填法：选择"业务表单"或与业务匹配的分类
    来源：BASE_DICTIONARY 中的表单分类字典
    
    [截图：填写完成的 Step 0 表单]

  Step 2：表单设计
  
    左侧组件面板说明：
    ┌──────────────────────────────────────┐
    │ 基础组件                               │
    │   单行文本 → 对应数据库 nvarchar 列       │
    │   多行文本 → 对应 nvarchar(max) 列        │
    │   数字 → 对应 decimal/int 列             │
    │   下拉选择 → 对应 nvarchar 列             │
    │   日期选择 → 对应 datetime 列             │
    │   开关 → 对应 int 列（0/1）               │
    │ 高级组件                               │
    │   关联表 → 引用其他表的数据                │
    │   图片上传 → 存储路径                     │
    │   富文本 → 对应 nvarchar(max)             │
    └──────────────────────────────────────┘
    
    操作：拖入"单行文本"到画布
    右侧属性面板配置：
      字段名：fieldName（英文，数据库列名）
      标签名：显示名称（中文）
      必填：是/否
      默认值：空或自定义
      
    [截图：表单设计器界面 + 属性面板]
    
    ⚠ 踩坑：至少拖入一个组件，否则 step 2 会校验失败
    原因：Form.vue step 1 getData() 返回 errorList，阻止进入下一步

  Step 3：列表设计
  
    操作：拖入"列表列"组件，绑定 step 2 创建的字段
    
    ⚠ 踩坑：必须至少一个列表列，否则发布失败
    ⚠ 踩坑：列宽建议设为固定值（如 150px），否则移动端可能溢出
    
    [截图：列表设计器界面]

  Step 4：保存
  
    操作：点击"保存"
    预期：弹出"保存成功"
    
    ⚠ 踩坑：如果保存没有反应或报错
      → F12 检查 Network 是否发出了 POST 请求
      → 如果没有请求：step 2 的 getData() 校验失败
      → 如果有请求但 500：检查 formData 是否为空
      → 如果有请求但 200 但数据库无记录：检查 BASE_VISUAL_DEV 的 F_STATE
    
    验证 SQL：SELECT * FROM BASE_VISUAL_DEV WHERE F_FULL_NAME = '巡检记录'

  Step 5：发布
  
    操作：功能设计列表 → 找到记录 → 点击"发布"
    发布对话框中：

      ☑ 生成移动端菜单（如需要发布到 App）
        → App 上级菜单：必须选一个 App 目录（如"功能参考"）

    [截图：发布对话框]
    
    验证 SQL：
      -- Web 菜单
      SELECT * FROM BASE_MODULE WHERE F_URL_ADDRESS LIKE '%编码%';
      -- App 菜单（如发布了移动端）
      SELECT * FROM BASE_MODULE WHERE F_URL_ADDRESS LIKE '%pages/apply/dynamicModel%';
      -- 物理表
      SELECT * FROM mt{ID};
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

  3.6 保存操作详解
      保存触发逻辑：
        → Step 0 保存：直接 POST /api/visualdev/Base（创建基础记录）
        → Step 2 保存：PUT /api/visualdev/Base/{id}（更新 formData + columnData）
        → 三步向导必须全部走完才会触发 Step 2 的保存
      
      常见保存失败原因：
        → Step 1 有 errorList（组件配置不完整）
        → formData 为空（Step 1 没有拖入组件）
        → columnData 为空（Step 2 没有拖入列表列）
        → JSON 列长度不足（formData 超过 nvarchar(400) 被截断）
        → NOT NULL 字段未填（缺少必填基础信息）
      
      验证：
        → Network 中出现 POST /api/visualdev/Base → 200
        → 数据库：SELECT * FROM BASE_VISUAL_DEV WHERE F_ID = '{id}'

  3.7 数据模型
      物理表 mt{ID} 的生成规则：
        → 表名：mt + BASE_VISUAL_DEV.F_ID
        → 生成时机：首次发布时
        → 系统字段（自动生成，不需要设计）：
          F_ID：主键，Snowflake 18 位字符串
          F_CREATE_USER_ID：创建人 ID
          F_CREATE_TIME：创建时间
          F_MODIFY_USER_ID：修改人 ID
          F_MODIFY_TIME：修改时间
          F_TENANT_ID：租户 ID（单租户固定 '0'）
        → 业务字段：来自 Step 1 拖入的组件
      
      字段类型映射表（完整）：
        设计器组件      →  数据库列类型       →  说明
        单行文本        →  nvarchar(200)      →  短文本
        多行文本        →  nvarchar(max)      →  长文本
        数字            →  decimal(18,2)      →  小数

  ⚠ 填错会导致数据查不到（查询结果为空但不报错）

  Web 端：jnpf-origin: pc
  App 端：jnpf-origin: app

  新用户默认密码：查看 BASE_SYS_CONFIG 中的 newUserDefaultPassword

  COM1013 = formData 为空
