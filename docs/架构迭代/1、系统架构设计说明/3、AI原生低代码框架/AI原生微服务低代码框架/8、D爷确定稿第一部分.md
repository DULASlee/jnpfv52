**项目名称：** JNPF-AI Studio (Baobab-Studio) —— AI原生低代码平台  
**总架构师：** D爷  
**版本：** V1.0  
**日期：** 2026-06-12  
**依赖：** Baobab-Foundry（内部深度学习子系统）  
**基础设施：** 笔记本16G内存，Docker，5并发客户沙箱

## 一、项目概述

Baobab-Studio是面向企业客户的AI原生低代码开发平台，融合了五阶段AI角色协作流水线、多角色Web UI、混合多租户沙箱隔离、以及分级并行智能体调度。平台与内部绝密的Baobab-Foundry深度学习子系统物理分离，仅通过加密通道交换知识图谱增量包，确保核心自我博弈技术不被外界接触。

**核心价值：**
- 业务人员可通过自然语言多轮对话，完成需求分析、架构设计、总体设计，一键生成可运行的系统。
- 专业开发者可深度干预IR，利用手工轨道与AI轨道同构的特性，自由切换，避免被AI锁定。
- 平台自动实现多租户隔离，每客户独立沙箱开发测试，确保数据安全和过程隔离。
- 内部自博弈进化能力通过“创始人管理”菜单静默接入，只有创始人可感知和使用。

## 二、总体架构与设计原则

### 2.1 系统上下文

```
┌─────────────────────────────────┐
│         Baobab-Studio           │
│  (面向客户的SaaS低代码平台)      │
│  • 多角色Web UI                 │
│  • 五阶段AI流水线               │
│  • 混合多租户沙箱               │
│  • 顾问式AI智能体（轻量）       │
└──────────┬──────────────────────┘
           │ 加密通道（仅创始人可触发）
           ▼
┌─────────────────────────────────┐
│        Baobab-Foundry           │
│  (内部绝密深度学习子系统)        │
│  • 自博弈引擎                   │
│  • 强化学习训练                 │
│  • 知识蒸馏与图谱进化           │
│  • 仅创始人二次认证访问         │
└─────────────────────────────────┘
```

### 2.2 关键设计原则

- **IR通用性契约**：手工设计与AI生成均产生符合`IRLayer`接口的JSON，双向可转换。`types.ts`为唯一真源。
- **物理隔离**：Foundry独立部署，Studio通过“领域智能更新包”单向接收知识图谱，绝不直接操作Foundry内部。
- **多租户隔离**：智能交互层（需求分析、设计）逻辑隔离（TenantId）；开发测试层物理隔离（Docker沙箱），每客户独立容器，限制资源，最多5并发。
- **并行与分级响应**：简单Bug由极速微智能体池秒修；中等需求由顾问团并行分钟级响应；深度进化任务交由Foundry后台执行。
- **安全底线**：修复所有CRITICAL漏洞，JWT白名单，RBAC加固，创始人功能二次认证+硬编码身份。

## 三、功能模块与用户角色

### 3.1 用户角色矩阵

| 角色                        | 职责                                         | 可访问菜单                                                   |
| --------------------------- | -------------------------------------------- | ------------------------------------------------------------ |
| 业务专家（客户）            | 描述需求，确认设计，验收系统                 | 应用快速生成、业务规则顾问、数据异常解释、我的项目           |
| 开发者（集成商/内部工程师） | 深度定制IR，审核AI生成物，介入开发           | AI顾问、AI架构评审、知识图谱浏览器、IR手工设计器、沙箱监控   |
| 管理员（平台运营）          | 管理租户，审计日志，降智切换                 | 用户管理、AI调用审计、模型降智与切换、系统配置               |
| 创始人（唯一）              | 控制自博弈引擎，调整AI参数，管理知识图谱发布 | **创始人管理**（独立菜单，二次认证）：自博弈控制台、AI超参中心、平台核心参数、系统级审计日志 |

### 3.2 核心功能模块

1. **五阶段AI流水线**  
   - 阶段1：需求分析（多模态输入、多轮问答，输出《系统需求分析说明书》）  
   - 阶段2：架构设计（输出《系统架构设计说明书》）  
   - 阶段3：总体设计（总架构师协调多个子智能体，输出《系统总体设计说明书》）  
   - 阶段4：全自动开发与测试（IR消费→代码生成→单元/集成/安全测试→部署到客户沙箱）  
   - 阶段5：交付（提供测试URL，支持增量修改）

2. **多角色Web UI**  
   - 开发者视图：AI顾问对话、IR Diff审查、沙箱仪表盘、知识图谱浏览  
   - 业务专家视图：引导式应用创建、业务规则顾问、大屏数据解释  
   - 创始人视图：自博弈引擎控制、超参调整、知识图谱审核、审计日志  
   - 核心复用组件：`AiChatPanel.vue`（富媒体聊天）、`IrDiffViewer.vue`（IR差异对比）、`SelfPlayDashboard.vue`（博弈监控）、`KnowledgeGraphExplorer.vue`（图谱可视化）

3. **混合多租户沙箱**  
   - 智能交互层：共享DB，TenantId隔离  
   - 开发测试层：Docker沙箱，每客户独立容器，通过cgroup限制（1核/1G内存）  
   - 沙箱调度器：维护最大并发数5，支持排队、超时销毁、资源回收  
   - 支持客户代码导出或一键迁移至生产环境

4. **顾问式AI智能体（Studio内轻量版）**  
   - 需求分析师Agent、架构师Agent、OrchestratorAgent（调用子Agent）  
   - 每个Agent均基于LLM，输出结构化IR片段  
   - 与Foundry不同，Studio的Agent不执行自博弈，仅作推理和生成

5. **创始人管理菜单（绝密功能入口）**  
   - 自博弈控制台：全局开关、领域配置、任务调度（与Foundry交互）  
   - AI超参调优中心：MCTS/强化学习/攻击者参数调整，配置文件管理  
   - 平台核心参数：IR通用性契约开关、知识图谱管理模式（审核/强制固化）  
   - 系统级审计日志：所有创始人操作记录，不可删除

## 四、技术栈选型

- **前端：** Vue3 + Vite4 + Ant Design Vue + WindiCSS + ECharts/D3.js  
- **后端：** .NET (Core) + Furion + SqlSugar + 自研DynamicApi  
- **AI集成：** 大模型网关（支持DeepSeek/通义千问等），轻量级ML.NET用于本地意图分类  
- **数据库：** SQL Server（业务数据），Neo4j社区版（知识图谱，仅在Studio中存储对外版本）  
- **消息队列：** RabbitMQ (EventBus)  
- **容器编排：** Docker + Docker Compose，沙箱管理用Docker.DotNet SDK  
- **认证：** JWT + 二次认证（TOTP/HOTP），RBAC扩展系统级权限  
- **监控：** OpenTelemetry + Jaeger + MiniProfiler

## 六、详细任务分解（关键模块示例）

### 6.1 需求分析Agent流水线

- **前端：** 聊天界面支持文件上传（PDF/Word/图片/语音转文字），多轮对话，实时预览《系统需求分析说明书》草稿，支持确认和修改。
- **后端：** 实现`AnalystAgentService`，封装LLM调用，解析对话上下文，逐步生成用户故事、领域模型、业务流程（IR片段）。生成最终文档（Markdown/PDF）。
- **数据存储：** 每个会话关联`TenantId`，存储历史消息和生成的文档IR。

### 6.2 多租户沙箱调度器

- **调度器核心**：`SandboxScheduler`服务，维护`ConcurrentQueue<SandboxRequest>`，最大并行数5，使用`SemaphoreSlim`控制。
- **沙箱创建**：调用`Docker.DotNet`，基于预构建镜像创建容器，传入环境变量（TenantId, DB连接字符串等），挂载客户专属数据卷。
- **资源限制**：在容器创建时指定`HostConfig.CPUCount = 1`，`Memory = 1GB`。
- **生命周期**：创建后运行代码生成和测试脚本，完成后保留N小时供客户验收，超时自动销毁并回收资源。

### 6.3 创始人管理菜单安全实现

- **前端**：路由守卫判断当前用户是否为创始人，若是且通过二次认证，则显示“创始人管理”菜单。组件内请求携带特殊header。
- **后端**：`FounderGuardMiddleware`检查当前JWT是否包含`founder_auth`声明（由二次认证颁发），否则拒绝。所有`/api/founder/*`路由均由此中间件保护。
- **二次认证流程**：创始人进入菜单时，前端弹出独立认证框，输入TOTP码或硬件密钥签名。验证通过后，后端颁发一个短期（15分钟）的`founder_token`，存储于session或安全cookie，用于后续请求。

### 6.4 IR通用性契约保障

- **IR定义**：`jnpf-web-vue3/src/core/ir/types.ts` 作为唯一IR源，后端C#项目生成对应的`IrContract`类，通过T4模板或手动同步。
- **双向转换器**：实现`IRtoSchemaConverter`（IR→JNPF Schema），允许用户在手工设计器中修改AI生成的IR后继续编辑。
- **校验流水线**：无论AI还是手工轨道，最终IR都经过`schema-cleaner.ts`清洗和`validator.ts`验证，确保同构。

## 七、关键接口定义（Studio内部）

| 接口                         | 方法/路径                                    | 描述                               |
| ---------------------------- | -------------------------------------------- | ---------------------------------- |
| 启动需求分析会话             | `POST /api/analyst/session`                  | 创建新会话，返回sessionId          |
| 发送消息/文件                | `POST /api/analyst/{sessionId}/message`      | 多模态输入，返回AI回复及结构化数据 |
| 生成需求文档                 | `POST /api/analyst/{sessionId}/generate-doc` | 输出《系统需求分析说明书》         |
| 类似接口用于架构师、总体设计 | …                                            | …                                  |
| 启动代码生成                 | `POST /api/devengine/build`                  | 传入最终IR，触发代码生成和沙箱部署 |
| 查询沙箱状态                 | `GET /api/sandbox/{tenantId}/status`         | 返回沙箱URL、状态、剩余时间        |
| 创始人二次认证               | `POST /api/founder/auth/verify`              | 验证TOTP，返回founder_token        |
| 获取自博弈任务列表           | `GET /api/founder/selfplay/tasks`            | 与Foundry通信，需要founder_token   |

## 八、测试策略

- **单元测试**：覆盖核心IR处理、表达式分类、沙箱调度逻辑。
- **集成测试**：多Agent协作流程、沙箱创建/销毁、数据库迁移。

## 九、部署与运维

- **Studio自身部署**：可单机Docker运行（API + 前端静态文件），数据库和Redis共享服务。
- **沙箱节点**：与Studio宿主机共享Docker引擎，但通过网络隔离。
- **监控**：OpenTelemetry收集指标，Grafana看板展示沙箱并发、AI调用延迟。
- **灾备**：数据库定期备份，知识图谱可导出恢复。
