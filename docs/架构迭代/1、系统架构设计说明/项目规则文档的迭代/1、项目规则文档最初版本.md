## 工程铁律

### 第一条：禁止推诿
遇到 bug、失败、异常或相关问题时，无论是否在原始任务范围内，必须当场解决。
禁止以"不在范围内""遗留问题""建议另开 issue""这是已存在问题不是我引入的"
"理论上应该可以工作""我先这样后续再优化""这是边缘情况可以稍后处理"
等任何理由回避。不确定的问题可以讨论，但不能无视。

### 第二条：完成必须验证
代码改完不等于任务完成。必须实际运行测试/构建/服务并确认通过。
没有跑过测试 = 没有完成。禁止假设测试会通过，禁止声称通过但输出显示失败。
禁止说"我无法测试""我无法验证""需要人工测试"——能跑真服务就跑真服务。

### 第三条：诚实报告
不确定就说不确定，不编造。测试失败就报告失败，附上实际输出。
禁止为了让回答看起来完整而虚构内容。
发现相邻代码中的问题要主动说出来，不能假装没看见。

### 第四条：禁止偷懒
禁止 placeholder / TODO / 伪实现 / try-catch 吞异常。
禁止为了省事跳过边界情况（空值、并发、错误路径）。
禁止不验证就宣称修复。禁止不分析根因就"试一下别的方法"。
不做超出要求的"改进"。三行相似代码优于过早抽象。

## 调试纪律

遇到 bug 时必须按以下流程操作，不允许猜测：

1. **复现**：用最小用例稳定复现，记录复现步骤
2. **定位**：找到根因，不在根因之外打补丁
   - 后端：Serilog 日志 → IDE 断点 → SqlSugar SQL 日志（开启 .WithSqlFilter()）
   - 前端：浏览器 DevTools → Vue DevTools → Network 面板
   - API：Knife4jUI 在线测试 → 检查请求/响应体
   - 数据库：检查实际执行的 SQL → 验证数据状态
3. **修复**：针对根因修复，不是症状
4. **验证**：实际运行确认修复有效；有条件时写回归测试
5. **反思**：这个 bug 是怎么引入的？有没有同类问题？

JNPF 特有调试要点：
- API 未生成：检查 Service 是否继承 IDynamicApiController，方法签名是否公开
- 数据查询异常：检查 SqlSugar 多租户过滤器（ITenantFilter）是否正确生效
- 代码生成问题：修改 .vm 模板，不修改生成的代码
- 事件未送达：检查 EventBus 订阅/发布配置（Channel / RabbitMQ）
- 工作流异常：检查流程定义 + 节点配置 + FlowEngine 执行日志

## Architecture

Low-code platform (JNPF) on .NET 8 custom framework. Backend tiers under backend/:

- framework/ — Core: DynamicApiController, DI, ConfigurableOptions, Swagger/Knife4jUI, SqlSugar, Dapper, Mapster, JWT, Serilog
- infrastructure/ — Cross-cutting: event bus, OAuth, WebSockets, third-party integrations
- modularity/ — Business modules: system, oauth, workflow, visualdev, engine, codegen, message, taskscheduler, app, extend, common, visualdata, inteAssistant, zxdev, subdev
- application/ — Hosts: JNPF.API.Entry (main API), JNPF.OA.API.Entry (OA, disabled). Velocity templates under wwwroot/Template/

Module layer mapping:
API.Entry（入口，不暴露 API）→ API.Controller（路由，自动生成）→ Application.Service（业务逻辑，方法签名 → API 端点）→ Domain（领域模型）→ Infrastructure（数据访问）

Enabled modules: Base, Message, WorkFlow, DataVisualization.
OA module exists but disabled — do not modify without explicit instruction.
IoT/MES modules are planned but not yet created — do not scaffold unless asked.

Frontends:
- jnpf-web-vue3 — PC admin UI (Vue 3 + Vite + Ant Design Vue)
- jnpf-web-datascreen — Avue DataV designer
- jnpf-app-vue3 — UniApp mobile

## Key Patterns

- Dynamic API: Controllers auto-generated from IDynamicApiController services — 禁止手动创建 Controller。
- Unified Response: RESTfulResult<T> auto-wraps all API returns. Exceptions use Oops.Oh() (FriendlyException), not raw throw.
- Connection strings: backend/application/JNPF.API.Entry/Configurations/ConnectionStrings.json (gitignored; template: ConnectionStrings.example.json)
- Codegen: Apache Velocity .vm templates — 生成的代码有问题时修改模板，不修改生成产物。
- EventBus: Channel in-process (framework/JNPF/EventBus/) for lightweight decoupling; RabbitMQ (infrastructure/JNPF.Extras.EventBus.RabbitMQ/) for durable cross-process messaging
- Real-time: SignalR (framework/JNPF/InstantMessaging/, [MapHub] auto-scan); WebSocket (infrastructure/JNPF.Extras.WebSockets/)
- Multi-tenant: SqlSugar-level ITenantFilter / TenantOptions — 新增查询时必须确认租户过滤器生效

## JNPF Vue3 前端手工开发规范

本段仅指导代码引擎覆盖不到的手工自定义页面开发。自动生成页面由后端 .vm 模板管理。

铁律：先读后写
每次开发自定义页面必须按顺序执行：
1. Read docs/frontend/jnpf-taste-blueprint.md（黄金页面索引、骨架决策树、组件映射、布局规则）
2. 在 jnpf-web-vue3/src/views/ 下找同类成熟页面 Read 后作参照
3. 按蓝图骨架决策树选择正确的骨架模式
4. 再动手写代码

铁律：禁止 a-card 默认化
- 列表页：jnpf-content-wrapper + BasicTable
- 表单分区：a-divider orientation="left" 或 BasicForm GroupTitle
- 弹窗表单：BasicPopup/BasicModal + BasicForm(FormSchema)
- 仅 Dashboard/监控页允许 a-card 做 KPI 指标卡

铁律：禁止自造类名
样式只用 common.less 已有类名（jnpf-content-wrapper 系列）。禁止自造 .search-wrapper、.form-page-header 等不存在的类名。

技术栈锁定：
- UI: Ant Design Vue（a- 前缀）
- 样式: Less + WindiCSS 工具类，不用 SCSS
- 表格: BasicTable，不用原生 a-table
- 表单: BasicForm（schema 驱动）或手写 a-form
- 弹窗: BasicPopup 或 BasicModal
- 操作列: TableAction + #bodyCell slot
- 字典: baseStore.getDictionaryData 加载后通过 :options 传入 jnpf-select
- 自定义组件: 优先 jnpf-* 全局组件
- 路由: 后端菜单动态注入，前端不定义静态路由
- 路径别名: /@/ 指向 src，不用 /src/

视觉自检：
1. 本地 dev server 运行时用 Playwright MCP 截图检查
2. 无白屏、无双滚动条、无溢出、按钮层级主次分明、页面像 JNPF 原生页面
3. 发现问题立刻修改，重新截图

代码风格：
- Vue 3 <script setup> + Composition API
- <style lang="less" scoped>
- 禁止 inline style / !important / console.log
- 单文件不超过 300 行
