### 类别一：代码风格与构建基线

这些文件确保所有开发者（人和 AI）写出风格一致的代码，且构建行为可预测。

#### 1-1. `.editorconfig` 代码风格基线

**作用：** Visual Studio / Rider / VS Code 全自动读取，强制统一格式。
**耗时：** 15 分钟
**当前状态：** 未确认是否存在

**需要包含：**
```ini
# .editorconfig
root = true

[*]
indent_style = space
indent_size = 4
end_of_line = lf
charset = utf-8
trim_trailing_whitespace = true
insert_final_newline = true

[*.cs]
# 命名约定
dotnet_naming_rule.interface_should_begin_with_i.severity = error
dotnet_naming_rule.interface_should_begin_with_i.symbols = interface
dotnet_naming_rule.interface_should_begin_with_i.style = begins_with_i
dotnet_naming_symbols.interface.applicable_kinds = interface
dotnet_naming_style.begins_with_i.required_prefix = I
dotnet_naming_style.begins_with_i.capitalization = pascal_case

# 字段用 _camelCase（私有）
dotnet_naming_rule.private_fields_should_be_camel.severity = warning
dotnet_naming_rule.private_fields_should_be_camel.symbols = private_fields
dotnet_naming_rule.private_fields_should_be_camel.style = camel_with_underscore
dotnet_naming_symbols.private_fields.applicable_kinds = field
dotnet_naming_symbols.private_fields.applicable_accessibilities = private
dotnet_naming_style.camel_with_underscore.required_prefix = _
dotnet_naming_style.camel_with_underscore.capitalization = camel_case

# using 放在命名空间外
dotnet_sort_system_directives_first = true
csharp_using_directive_placement = outside_namespace:warning

# var 偏好
csharp_style_var_for_built_in_types = false:suggestion
csharp_style_var_when_type_is_apparent = true:suggestion
csharp_style_var_elsewhere = true:suggestion

# nullable
dotnet_diagnostic.CS8618.severity = warning

[*.vue]
indent_size = 2

[*.ts]
indent_size = 2

[*.{json,yml,yaml}]
indent_size = 2
```

**验收标准：** 打开任意 .cs 文件，保存时 IDE 自动按规则格式化。

#### 1-2. `Directory.Build.props` 集中构建配置

**作用：** 所有 .csproj 自动继承，无需每个项目重复配置。
**耗时：** 10 分钟
**路径：** `backend/Directory.Build.props`

```xml
<Project>
  <PropertyGroup>
    <TargetFramework>net6.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <TreatWarningsAsErrors>false</TreatWarningsAsErrors>
    <NoWarn>$(NoWarn);CS1591</NoWarn>
  </PropertyGroup>
</Project>
```

**验收标准：** 新建一个 .csproj，不写任何 `<PropertyGroup>`，`dotnet build` 仍然启用 nullable。

#### 1-3. `global.json` SDK 版本锁定

**作用：** 锁定 .NET SDK 版本，防止不同开发者用不同 SDK 导致构建行为差异。
**耗时：** 3 分钟

```json
{
  "sdk": {
    "version": "6.0.xxx",
    "rollForward": "latestPatch"
  }
}
```

**验收标准：** 用不同小版本的 .NET 6 SDK 构建，行为一致。

### 类别二：命名约定文档

这是 AI 和新开发者最容易踩的坑——不知道"这个东西该叫什么名字"。

#### 2-1. 项目命名约定文档

**作用：** 一次性定义所有命名规则，AI 生成代码时直接遵循。
**耗时：** 30 分钟
**路径：** `docs/conventions/naming.md`

```markdown
# JNPF V5.2 命名约定

## 数据库表名
- 格式：`{模块前缀}_{实体名}`，全小写，下划线分隔
- 示例：`iot_device`、`mes_work_order`、`sys_user`
- 模块前缀：`sys_`(系统)、`iot_`(物联网)、`mes_`(制造)、`wf_`(工作流)

## C# 类名
- 实体类：PascalCase，与表名对应（表 `iot_device` → 类 `IotDevice`）
- Service 类：`{实体}Service`（如 `IotDeviceService`）
- DTO：`{实体}{操作}Input/Output`（如 `IotDeviceAddInput`、`IotDeviceListOutput`）
- EventBus 事件：`{动作}Event`（如 `DeviceTelemetryReceivedEvent`）

## API 路径（DynamicApiController 自动生成）
- 格式：`/api/{模块}/{Service名去掉Service}/{方法名}`
- 示例：`/api/iot/IotDevice/Add`、`/api/mes/MesWorkOrder/GetPage`
- 注意：由 DynamicApiController 自动映射，不手动定义

## 前端
- 组件：PascalCase（`DevicePanel.vue`）
- Composable：`use{功能}`（`useDeviceSocket`）
- Store：`use{模块}Store`（`useDeviceStore`）
- API 文件：`src/api/{模块}/{文件}.ts`

## 文件夹结构
- 后端模块：`backend/modularity/{模块名}/JNPF.{模块名}.{层名}`
- 前端 IoT 组件：`src/iot/{功能域}/`
```

**验收标准：** AI 新建任何文件/类/表时，都能在本文档中找到命名规则，无歧义。

### 类别六：错误处理与日志约定

#### 6-1. 统一错误响应格式

**耗时：** 15 分钟
**路径：** `docs/conventions/error-response.md`

```markdown
# 统一 API 响应格式

## 成功
{
  "code": 200,
  "message": "操作成功",
  "data": { ... }
}

## 失败
{
  "code": 500,
  "message": "具体错误信息",
  "data": null
}

## 业务校验失败
{
  "code": 400,
  "message": "参数校验失败",
  "data": {
    "errors": [
      { "field": "deviceName", "message": "设备名称不能为空" }
    ]
  }
}

## 错误码约定
- 200: 成功
- 400: 参数/业务校验失败
- 401: 未认证
- 403: 无权限（含设备级权限不足）
- 404: 资源不存在
- 500: 服务器内部错误
```

#### 6-2. 日志级别使用约定

**耗时：** 10 分钟
**路径：** `docs/conventions/logging.md`

```markdown
# Serilog 日志级别约定

| 级别 | 用途 | 示例 |
|------|------|------|
| Fatal | 系统不可用 | 数据库连接池耗尽、MQTT Broker 不可达 |
| Error | 功能故障需关注 | 设备指令下发失败、工单状态跃迁异常 |
| Warning | 潜在问题 | 设备离线超时、Redis 缓存未命中率突增 |
| Information | 关键业务节点 | 设备上线/下线、工单状态变更、用户登录 |
| Debug | 开发调试 | Service 入参/出参、SQL 语句、EventBus 消息体 |
| Trace | 极细粒度 | MQTT 原始报文、HTTP 请求/响应头 |

> **规则：** 生产环境最低级别 Warning；开发环境 Debug。
> 设备遥测高频数据用 Debug 级别，不要用 Information（会淹没日志）。
```
