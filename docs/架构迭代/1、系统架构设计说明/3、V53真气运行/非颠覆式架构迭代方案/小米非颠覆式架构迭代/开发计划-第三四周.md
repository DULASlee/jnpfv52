**Startup.Security.cs：**

```csharp
using JNPF.API.Entry.Handlers;
using Microsoft.AspNetCore.Authentication.JwtBearer;

namespace JNPF.API.Entry;

public partial class Startup
{
    /// <summary>
    /// 认证授权相关服务注册
    /// </summary>
    public static void ConfigureSecurity(IServiceCollection services)
    {
        services.AddJwt<JwtHandler>(enableGlobalAuthorize: true, jwtBearerConfigure: options =>
        {
            options.Events = new JwtBearerEvents
            {
                OnMessageReceived = context =>
                {
                    var httpContext = context.HttpContext;
                    if (httpContext.Request.Query.ContainsKey("token"))
                    {
                        var token = httpContext.Request.Query["token"].ToString();
                        if (token.StartsWith("Bearer") || token.StartsWith("bearer"))
                            token = token.Replace("Bearer", string.Empty).Replace("bearer", string.Empty);
                        token = token.TrimStart();
                        if (token.StartsWith("%20"))
                            token = token.Replace("%20", string.Empty);
                        context.Token = token;
                    }
                    return Task.CompletedTask;
                },
                OnTokenValidated = context => Task.CompletedTask,
            };
        });
    }
}
```

**Startup.Messaging.cs：**

```csharp
using JNPF.Common.Core;
using JNPF.EventHandler;

namespace JNPF.API.Entry;

public partial class Startup
{
    /// <summary>
    /// 事件总线/MQ 相关服务注册
    /// </summary>
    public static void ConfigureMessaging(IServiceCollection services)
    {
        services.AddEventBus(options =>
        {
            var config = App.GetOptions<EventBusOptions>();
            if (config.EventBusType != EventBusType.Memory)
            {
                switch (config.EventBusType)
                {
                    case EventBusType.RabbitMQ:
                        var factory = new RabbitMQ.Client.ConnectionFactory
                        {
                            HostName = config.HostName,
                            UserName = config.UserName,
                            Password = config.Password,
                        };
                        var rbmqEventSourceStorer = new RabbitMQEventSourceStorer(factory, "eventbus", 3000);
                        options.ReplaceStorer(serviceProvider => rbmqEventSourceStorer);
                        break;
                }
            }
            options.UseUtcTimestamp = false;
            options.LogEnabled = true;
            options.AddExecutor<RetryEventHandlerExecutor>();
        });
    }
}
```

## T12：软删除全局过滤器

### 目标

引入 `ISoftDelete` 接口和全局过滤器，自动过滤已逻辑删除的数据。

### 现状分析

```
搜索 DeleteMark 字段使用情况：
- 多数实体有 F_DELETE_MARK 字段
- 但无全局过滤器，查询时需手动添加 .Where(x => x.DeleteMark == 0)
- 遗漏则会查到已删除数据
```

### 修改文件

| 文件 | 操作 | 说明 |
|------|------|------|
| `backend/framework/JNPF.Extras.DatabaseAccessor.SqlSugar/Models/ISoftDelete.cs` | 新增 | 软删除接口 |
| `backend/framework/JNPF.Extras.DatabaseAccessor.SqlSugar/Repositories/SqlSugarDbContextProvider.cs` | 修改 | 在 QueryFilter 中注册软删除过滤器 |
| `backend/modularity/*/Entitys/*.cs`（可选） | 修改 | 实体类添加 ISoftDelete 接口标记 |

### 代码实现

**新增 ISoftDelete.cs：**

```csharp
using SqlSugar;

namespace JNPF.Extras.DatabaseAccessor.SqlSugar.Models;

/// <summary>
/// 软删除标记接口
/// 实现此接口的实体在查询时会自动过滤 DeleteMark != 0 的记录
/// </summary>
public interface ISoftDelete
{
    /// <summary>
    /// 删除标记：0=正常, 1=已删除
    /// </summary>
    [SugarColumn(ColumnName = "F_DELETE_MARK")]
    int DeleteMark { get; set; }
}
```

**修改 SqlSugarDbContextProvider.cs — ResolveTenantConnection 方法中追加过滤器：**

```csharp
// 在租户过滤器注册之后，追加软删除过滤器
// 位置：ResolveTenantConnection 方法中，tenantCache.type == 1 的分支内

// 原代码
scopedContext.QueryFilter.Clear();
scopedContext.QueryFilter.AddTableFilter<ITenantFilter>(
    it => it.TenantId == _fieldIsolationTenantDbName);

// 改后 — 追加软删除过滤器
scopedContext.QueryFilter.Clear();
scopedContext.QueryFilter.AddTableFilter<ITenantFilter>(
    it => it.TenantId == _fieldIsolationTenantDbName);
scopedContext.QueryFilter.AddTableFilter<ISoftDelete>(
    it => it.DeleteMark == 0);
```

**同样在非多租户模式下也追加：**

```csharp
// ResolveTenantConnection 方法末尾，非多租户模式分支
// 原代码
return _rootScope.AsTenant().GetConnectionScope(tenantId);

// 改后 — 在返回前注册软删除过滤器
var scope = _rootScope.AsTenant().GetConnectionScope(tenantId);
scope.QueryFilter.AddTableFilter<ISoftDelete>(it => it.DeleteMark == 0);
return scope;
```

### 实体类标记（可选，逐步推进）

```csharp
// 示例：UserEntity.cs
[SugarTable("BASE_USER")]
public class UserEntity : ITenantFilter, ISoftDelete
{
    // ... 现有属性不变

    [SugarColumn(ColumnName = "F_DELETE_MARK")]
    public int DeleteMark { get; set; }
}
```

### 重要注意事项

1. **仅标记了 `ISoftDelete` 的实体才会被过滤** — 现有未标记的实体不受影响
2. **需逐步为实体类添加接口标记** — 先从核心实体（User, Department, Role）开始
3. **需要手动删除的场景**：使用 `context.QueryFilter.Clear<ISoftDelete>()` 临时绕过
4. **与现有 `.Where(x => x.DeleteMark == 0)` 的关系**：添加全局过滤器后，可逐步移除手动条件

### 验证方法

```bash
# 1. 编译验证
cd d:\JNPF-v52\backend && dotnet build

# 2. 为 UserEntity 添加 ISoftDelete 标记
# 3. 查询用户列表，确认不包含 DeleteMark=1 的记录
# 4. 临时绕过过滤器查询，确认可以查到已删除记录
```

### 影响面

- ISoftDelete 接口是新增文件，零侵入
- 全局过滤器仅对实现了 ISoftDelete 的实体生效
- 现有未标记 ISoftDelete 的实体查询行为完全不变
- 需要逐步为实体类添加接口标记（非强制，可选推进）

## T14：统一异常响应格式增强（补充）

### 目标

在 `Oops.Bah` 业务异常响应中也注入 TraceId（T10 仅处理了系统异常）。

### 修改文件

| 文件 | 操作 | 说明 |
|------|------|------|
| `backend/framework/JNPF/UnifyResult/Providers/RESTfulResultProvider.cs` | 修改 | 在业务异常响应中追加 TraceId |

### 代码变更

```csharp
// RESTfulResultProvider.cs — 找到 OnException 或 Oops.Bah 处理的位置
// 在 extras 字段中追加 traceId

// 改前
return new RESTfulResult<object>
{
    code = errorCode,
    msg = errorMessage,
    data = null,
    timestamp = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds()
};

// 改后
return new RESTfulResult<object>
{
    code = errorCode,
    msg = errorMessage,
    data = null,
    extras = new { traceId = httpContext.TraceIdentifier },
    timestamp = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds()
};
```

### 影响面

- 仅在异常响应的 extras 字段中追加 traceId
- 正常响应不受影响
- 前端可选择性展示 traceId

## 风险评估与回滚方案

| 风险 | 概率 | 影响 | 回滚方案 |
|------|------|------|----------|
| 部分类拆分后注册顺序变化 | 低 | 服务解析异常 | 严格按原代码顺序调用分组方法 |
| ISoftDelete 过滤器影响现有查询 | 中 | 部分数据查询结果变化 | 仅对已标记接口的实体生效，未标记的不受影响 |
| ISoftDelete 过滤器与租户过滤器冲突 | 低 | 过滤器叠加异常 | SqlSugar 支持多过滤器 AND 叠加 |
| CancellationToken 参数导致接口不匹配 | 极低 | 编译错误 | 默认参数向后兼容 |
| 软删除实体标记遗漏 | 中 | 部分实体未被过滤 | 标记为可选，逐步推进 |

**整体回滚方案：**
- 部分类拆分：`git revert` 拆分提交，恢复原 Startup.cs
- 软删除过滤器：移除 ISoftDelete 接口注册，恢复 SqlSugarDbContextProvider.cs
- CancellationToken：移除追加的参数（带默认值，移除不影响调用方）
