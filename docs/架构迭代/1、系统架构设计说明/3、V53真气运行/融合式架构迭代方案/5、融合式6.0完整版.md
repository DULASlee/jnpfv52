## 第一部分：架构决策记录（ADR）

> 以下所有决策经过五位专家六轮评审确认，工程师在执行过程中如遇分歧，以本记录为准。

### ADR-001：ISqlSugarClient 注册方式

**决策：** 强制 Singleton + CopyNew()，不可选 Scoped。

**理由：** SqlSugarScope 官方设计为单例，内部通过 AsyncLocal 实现上下文隔离。改为 Scoped 会导致：连接池无法复用、多租户 GetConnectionScope 失效、SqlSugarScope 构造函数重复执行导致内存暴涨。

**执行要求：** SqlSugarConfigureExtensions.cs 中 `services.AddSingleton<ISqlSugarClient>(sqlSugar)` 保持不变。Repository 构造函数中每次调用 `((SqlSugarScope)context).CopyNew()` 获取独立上下文。

---

### ADR-002：DataExecuting 实现策略

**决策：** 启动时一次性组装完整委托，运行时通过 Scoped 的 ITenantContext 读取当前租户/系统信息。禁止运行时动态修改委托链。

**理由：** 如果 ISqlSugarClient 为 Singleton（或 CopyNew 共享 AOP 配置），在请求管道中动态修改 DataExecuting 会引发竞态条件。

**前置验证：** 阶段 0 任务 0.6 必须验证 DataExecuting 属性的赋值行为（`=` 覆盖 vs `+=` 追加）以及 CopyNew 是否继承 AOP 配置。根据验证结果选择以下三种实现之一：
- 情况 A（支持 `+=`）：直接使用 `+=` 追加多维度过滤器回调
- 情况 B（仅 `=`，CopyNew 继承 AOP）：在 SetDbAop 中组装统一委托
- 情况 C（仅 `=`，CopyNew 不继承 AOP）：提供工厂方法，在 Repository CopyNew 后调用

---

### ADR-003：TenantContext 解析方式

**决策：** 同步属性读取 + AsyncLocal 传播 + 中间件预热。禁止异步构造函数。

**理由：** `.GetAwaiter().GetResult()` 在构造函数中是 .NET 社区公认的反模式，可能引发死锁。TenantContext 使用同步的 ICacheManager（底层 MemoryCache）读取租户连接配置，无需异步 I/O。AsyncLocal 保证跨 async/await 调用链的上下文传播。

---

### ADR-004：匿名端点降级策略

**决策：** 当 JWT Claims 中无 TenantId 时，FallbackTenantResolver 按以下优先级降级：
1. HTTP Header `X-Tenant-Id`
2. QueryString `tenantId`
3. 默认租户 `"default"`

Repository 构造函数中，如果租户连接配置为 null，降级为默认租户行为并记录警告日志。

---

### ADR-005：模块系统主从关系

**决策：** 新的 JnpfModule 系统为主，旧的 AppStartup 系统为从。所有新 JnpfModule 必须通过 `[DependsOn(typeof(LegacyModule))]` 声明对旧模块的依赖，确保旧模块先执行，新模块后执行，新服务不被旧模块覆盖。

---

### ADR-006：ISqlSugarClient 生命周期与 CopyNew 行为

**决策：** Singleton 注册不变。Repository 每次构造时调用 CopyNew() 获取独立上下文副本。

**前置验证：** 阶段 0 任务 0.7 必须验证：
- CopyNew 创建的实例与父实例是否共享 ADO.NET 连接
- CopyNew 后 AsTenant() 的连接字典是否独立
- CopyNew 的单次耗时是否 < 1ms
- CopyNew 的临时实例是否被 GC 正确回收

---

### ADR-007：Repository 构造函数目标行数

**决策：** 50-60 行，职责单一化。不追求过度压缩，可读性优先。

**理由：** 即使完全剥离租户解析和 AOP 配置，Repository 仍需保留：CopyNew、多租户连接切换、过滤器注册、连接验证等不可压缩的逻辑。

---

### ADR-008：Outbox 默认启用 + 极窄 Bypass 权限

**决策：** 所有业务事件默认走 Outbox 管道。仅系统心跳事件（`System:Heartbeat`）允许 `[BypassOutbox]`。LogEventSubscriber 禁止 Bypass，改用批量异步缓冲写入优化性能。

**理由：** 操作日志是审计追溯的关键证据，非低价值数据。BypassOutbox 如果泛滥会导致 Outbox 形同虚设。

---

### ADR-009：API 契约不可修改

**决策：** 以下内容在本次迭代中绝对不可修改：
- RESTful 路由规则 `api/{module}/{controller}/{action}`
- 统一返回格式 `RESTfulResult`
- 368 个代码生成模板的接口契约
- 前端 Vue3/UniApp/数据大屏的任何代码

**理由：** 修改任何一项都会导致前端和所有通过代码生成器产出的历史业务代码崩溃。

---

### ADR-010：业务冻结期与热补丁通道

**决策：** 阶段 1 至阶段 4（第 2 周至第 7 周）为架构冻结期，冻结对 5 个基础文件的业务 PR。生产紧急 Bug 修复通过 hotfix 通道进行，由架构师审批后合并到 main 并同步到重构分支。每周五架构师执行 rebase 同步。

### 任务 0.6 DataExecuting 属性行为验证

**目的：** 确认 SqlSugar 的 `Aop.DataExecuting` 是简单字段赋值还是事件模式，决定 ConfigureGlobalDataExecuting 的最终实现。

**执行内容（全部在独立测试项目中）：**

**验证 1：覆盖 vs 追加**
```
db.Aop.DataExecuting = Handler_A;
db.Aop.DataExecuting = Handler_B;
执行 Insert，观察：
  仅输出 Handler_B → 覆盖模式（=）
  输出 Handler_A 和 Handler_B → 追加模式（+=）
```

**验证 2：+= 语法是否编译通过**
```
db.Aop.DataExecuting = Handler_A;
db.Aop.DataExecuting += Handler_B;
编译是否通过？运行时行为？
```

**验证 3：CopyNew 是否继承 AOP**
```
db.Aop.DataExecuting = Handler_A;
var copy = db.CopyNew();
用 copy 执行 Insert，是否输出 Handler_A？
```

**验证 4：多线程赋值安全性**
```
10 个并发线程，各自为 CopyNew 实例设置不同 DataExecuting
验证各实例回调互不干扰
```

**决策输出表：**

| 验证结果                   | ConfigureGlobalDataExecuting 策略                          |
| -------------------------- | ---------------------------------------------------------- |
| 支持 `+=`                  | 直接 `+=` 追加多维度过滤器回调                             |
| 仅 `=`，CopyNew 继承 AOP   | 在 SetDbAop 中组装统一委托，一次性赋值                     |
| 仅 `=`，CopyNew 不继承 AOP | 提供工厂方法，Repository CopyNew 后调用 ApplyDataExecuting |

### 任务 0.8 JWT 权限校验紧急修复

**文件：** `JNPF.Extras.Authentication.JwtBearer` 项目中的 `JwtHandler.cs`

**这是"手术前的安全准备"。带着裸奔漏洞做架构重构是不负责任的。**

**修改内容：**

1. **恢复被注释的权限校验代码**——找到 JwtHandler 中被注释的权限验证逻辑，取消注释
2. **加上 Redis 缓存**——权限查询结果缓到 Redis，key 格式 `jnpf:auth:perm:{userId}`，TTL 5 分钟
3. **白名单配置**——在 appsettings.json 中声明不需要权限校验的端点列表：
   ```json
   {
     "Auth": {
       "AllowAnonymousPaths": [
         "/api/oauth/login",
         "/api/oauth/refresh",
         "/health",
         "/health/live",
         "/health/ready",
         "/swagger"
       ]
     }

**管道流程：**
```
业务代码发布事件
       ↓
[标记 BypassOutbox？] → 是 → 直接投递 EventBus（仅限系统心跳）
       ↓ 否
EventOutboxStore.WriteAsync() + NotifyNewMessage()
       ↓
EventOutboxDispatcher 收到 Channel 信号
       ↓
批量获取 Pending 消息
       ↓
PollyRetryHandlerExecutor 逐条投递（指数退避 + 熔断）
       ↓ 成功
IdempotentEventHandler 幂等检查 → 执行处理器 → 写入 ProcessedEvent
       ↓ 失败
回到 Outbox 标记失败 → RetryCount++
       ↓ 超过 MaxRetryCount
标记 DeadLetter
```

private readonly Channel<LogEventSource> _logChannel = Channel.CreateBounded<LogEventSource>(1000);

[EventSubscribe("Log:CreateReLog")]
[EventSubscribe("Log:CreateExLog")]
[EventSubscribe("Log:CreateVisLog")]
[EventSubscribe("Log:CreateOpLog")]
public async Task CreateLog(EventHandlerExecutingContext context)
{

    _logChannel.Writer.TryWrite(log);
}

// 后台批量刷新（在构造函数中启动后台任务）
private async Task FlushLogBatch(CancellationToken ct)
{
    while (!ct.IsCancellationRequested)
    {
        await Task.Delay(5000, ct);
        var batch = new List<LogEventSource>();
        while (_logChannel.Reader.TryRead(out var item) && batch.Count < 100)
            batch.Add(item);
        
        if (batch.Any())
        {
            var db = _sqlSugarClient.CopyNew();
            // 按租户分组写入
            foreach (var group in batch.GroupBy(b => b.TenantId))
            {
                if (!string.IsNullOrEmpty(group.Key))
                    await _tenantManager.ChangTenant(db, group.Key);
                await db.Fastest(group.ToList()).BulkCopyAsync();
            }
        }
    }
}
```
