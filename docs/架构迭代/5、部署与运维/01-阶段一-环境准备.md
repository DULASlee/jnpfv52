# 阶段一：环境准备

> **做完这个阶段，你会得到：** 已从项目配置文件读出数据库名/密码/缓存类型；本机软件与**项目配置一致**；全局变量已按源码设置。  
> **预计耗时：** 30–60 分钟  
> **前置条件：** 无（第一次部署从这里开始）

---

## 配置原则（全文适用）

> **部署文档的职责：读项目已有配置 → 搭建匹配的基础设施。不是编一套配置让项目去适配。**
>
> - 数据库名、用户名、缓存类型等：**以 `Configurations/*.json` 为准**  
> - 基础设施（SQL Server sa 密码、Redis 实例）：**必须与配置文件中的值一致**  
> - 仅当本机环境确实不同（如 Linux 上 Host 要改）时，才改配置文件，且改后须与基础设施同步

## 1.1 读取项目实际配置 [必选]

> **这一步做什么：** 打开项目里的 JSON 配置文件，读出数据库名、地址、密码、缓存类型。**不要自己编这些值。**

### 1.1.1 配置文件在哪里？

JNPF 后端**不在** `appsettings.json` 里写连接串。入口文件只声明扫描目录：

**文件 0：`application/JNPF.API.Entry/appsettings.json`（本仓库实测）**

```json
{
  "AllowedHosts": "*",
  "ConfigurationScanDirectories": [ "Configurations" ]
}
```

> 含义：所有业务配置在 `Configurations/` 目录下的独立 JSON 文件中。

---

用文本编辑器打开：

```

```

**本仓库当前内容（2026-05-26 源码实测，请与你本地文件核对）：**

```json
{
  "ConnectionStrings": {
    "ConnectionConfigs": [
      {
        "Domain": "dev_v1.",
        "ConfigId": "default",
        "DBName": "ZXAF_V1_DevTest1",
        "DBType": "SqlServer",
        "Host": "(local)\\SQLEXPRESS",
        "Port": "1433",
        "UserName": "sa",
        "Password": "1qazxsw2",
        "DBSchema": "public"
      },
      {
        "ConfigId": "JNPF-Job",
        "DBName": "jnpf_sundial",
        "DBType": "SqlServer",
        "Host": "(local)\\SQLEXPRESS",
        "Port": "1433",
        "UserName": "sa",
        "Password": "1qazxsw2",
        "DBSchema": "public"
      }
    ]
  }
}
```

**两个库的关系：**

| ConfigId | DBName | 用途 | 阶段二执行的 SQL 脚本 |
|----------|--------|------|----------------------|
| `default` | **ZXAF_V1_DevTest1** | 主业务库（用户、权限、低代码、工作流、大屏） | `web/主库脚本.sql` |
| `JNPF-Job` | **jnpf_sundial** | Sundial 定时任务调度库 | `web/jnpf_sundial_init_sqlserver.sql` |

**从文件中提取并填入下表：**

| 配置项 | JSON 字段 | 本仓库实测值 | 你本地文件中的值 |
|--------|-----------|-------------|----------------|
| 主库名 | `ConfigId=default` → `DBName` | `ZXAF_V1_DevTest1` | ________ |
| 调度库名 | `ConfigId=JNPF-Job` → `DBName` | `jnpf_sundial` | ________ |
| 服务器 | `Host` | `(local)\SQLEXPRESS` | ________ |
| 端口 | `Port` | `1433` | ________ |
| 用户名 | `UserName` | `sa` | ________ |
| 密码 | `Password` | `1qazxsw2` | ________ |

> ⚠️ **`Password` 必须与 SQL Server 的 sa 密码一致。**  
> - **方式 A（推荐）：** 安装 SQL Server 时，将 sa 密码设为配置文件中 `Password` 的值（本仓库为 `1qazxsw2`）  
> - **方式 B：** 已安装 SQL Server 且 sa 密码不同 → 修改 `ConnectionStrings.json` 中两处 `Password` 为你实际的 sa 密码  
> ⚠️ **生产环境必须更换默认密码**（阶段六）；更换后配置文件与 SQL Server 仍须一致。

🟢 **核对命令：**

```powershell
Get-Content "$JNPF_ROOT\application\JNPF.API.Entry\Configurations\ConnectionStrings.json"
```

### 1.1.3 缓存：Cache.json

打开：

```
$JNPF_ROOT/application/JNPF.API.Entry/Configurations/Cache.json
```

**本仓库当前内容：**

```json
{
  "Cache": {
    "CacheType": "MemoryCache",
    "ip": "127.0.0.1",
    "port": 6379,
    "RedisConnectionString": "{0}:{1}, poolsize=500,ssl=false,defaultDatabase=7"
  }
}
```

| 配置项 | 本仓库实测值 | 部署含义 |
|--------|-------------|----------|
| `CacheType` | **`MemoryCache`** | **本阶段 1.4 可跳过 Redis** |
| `ip` / `port` | `127.0.0.1` / `6379` | 仅当改为 `RedisCache` 时生效 |
| `RedisConnectionString` | 模板 `{0}:{1},...` | 无 `password=` 段 → 当前 Memory 模式不连 Redis |

> 若你将 `CacheType` 改为 **`RedisCache`**（阶段六生产建议）：  
> 1. 必须安装 Redis（步骤 1.4）  
> 2. `RedisConnectionString` 中的密码须与 Redis 实例 **完全一致**（改 Cache.json，不是随便设一个密码）

## 1.3 安装 SQL Server [必选]

> **SQL Server** 是关系型数据库，端口默认 **1433**。

### 安装时的关键设置

> ⚠️ **sa 密码必须与 1.1.2 中 `ConnectionStrings.json` 的 `Password` 一致。**  
> 本仓库配置值为 **`1qazxsw2`**（请打开你本地文件确认是否仍为该值）。

| 配置项 | 必须与 ConnectionStrings.json 一致 |
|--------|-----------------------------------|
| 实例名 | `(local)\SQLEXPRESS`（Windows Express 默认）或你 JSON 中的 `Host` |
| sa 密码 | `Password` 字段的值 |
| 身份验证 | 混合模式（启用 sa） |
| TCP/IP | 启用（SQL Server 配置管理器） |

**若 sa 密码不一致，二选一：**

- **方式 A（推荐）：** 安装/重置 SQL Server sa 密码 → 与 JSON 中 `Password` 相同  
- **方式 B：** 修改 `ConnectionStrings.json` 两处 `Password` → 与你已设置的 sa 密码相同

### 验证

🪟 **Windows 11**（[数据库管理员]）：

```powershell
sqlcmd -S $DB_HOST -U $DB_USER -P "$DB_PASS" -Q "SELECT 1"
```

🐧 **Linux**：

```bash
sqlcmd -S "$DB_HOST" -U "$DB_USER" -P "$DB_PASS" -Q "SELECT 1"
```

> **期望看到：**
> ```
> 1
> -----------
>           1
> (1 rows affected)
> ```

> **如果报 `Login failed`：**  
> 1. 打开 `ConnectionStrings.json` 看 `Password=` 实际值  
> 2. 用 SSMS 或 `sqlcmd` 确认 sa 实际密码  
> 3. 两者必须一致（见方式 A/B）

## 1.4 安装 Redis [条件必选]

> **先读 Cache.json 的 `CacheType`，再决定要不要装。**

| Cache.json 中 `CacheType` | 本阶段 1.4 |
|---------------------------|-----------|
| **`MemoryCache`**（本仓库默认） | **[跳过]** 无需 Redis |
| **`RedisCache`** | **[必选]** 必须安装，且密码与 `RedisConnectionString` 一致 |

本仓库默认为 **`MemoryCache`** → **跳过本节**，直接进入 1.5。

若已改为 `RedisCache`，安装 Redis 时：

1. 打开 `Cache.json`，查看 `RedisConnectionString` 是否含 `password=xxx`  
2. Docker 启动 Redis 时使用**相同**密码，例如：

```bash
docker run -d --name jnpf-redis -p 6379:6379 redis:7 redis-server --requirepass "与Cache.json中一致的密码"
```

> ❌ **禁止** 使用与 `Cache.json` 无关的随意密码（如文档臆造的 `redis@123`）。
