### 7.2.2 权限接口

登录后 F12 → Network，刷新页面，应看到带 `Authorization` 的请求返回 `code: 200`。

或使用脚本（仓库 `scripts/f2-smoke-test.ps1`，需把 `$base` 改为 `http://localhost:30000` 或 `http://localhost` 经 Nginx）：

🪟 **Windows 11**：

```powershell
# 经 Nginx 反代时部分路径为 /api/oauth/...
# 直连 API 时：
$base = "http://localhost:30000"
Invoke-RestMethod -Uri "$base/api/oauth/getLoginConfig" -Method Get
```

## 7.9 重启后恢复测试 [推荐·生产]

> **为什么要做：** 部署验收不能只做「刚启动立刻测」。服务器重启后，systemd / Windows 服务 / Docker `--restart` 必须能自动拉起进程。

| # | 验证什么 | 怎么验证 | 通过标准 | 失败怎么办 |
|---|----------|----------|----------|-----------|
| 11 | 重启后 API | 重启服务器 → 等待 2 分钟 → `curl http://localhost:30000/newapi/index.html` | HTTP 200，文档页可开 | 阶段三 3.5 检查自启服务 |
| 12 | 重启后 Nginx | 同上 → `curl -I http://localhost/` | HTTP 200 | 注册 Nginx 为系统服务 |
| 13 | 重启后登录 | 浏览器打开首页 → admin 登录 | 进入首页、菜单正常 | Redis/API/DB 自启顺序 |

🪟 **Windows 11**（不重启整机时的模拟）：

```powershell
# 停止后由 NSSM/IIS 自动拉起，或手动验证服务恢复命令
Restart-Service jnpf-api -ErrorAction SilentlyContinue
Start-Sleep -Seconds 30
Invoke-WebRequest -Uri "http://localhost:30000/newapi/index.html" -UseBasicParsing | Select-Object StatusCode
```

🐧 **Linux**：

```bash
sudo systemctl restart jnpf-api nginx
sleep 30
curl -s -o /dev/null -w "%{http_code}" http://localhost:30000/newapi/index.html
```

> **期望：** 状态码 `200`。

## 常见问题速查

| 现象 | 可能原因 | 回到哪一步 |
|------|----------|-----------|
| 登录 401 | Redis 未启且 MemoryCache 会话丢失；或 admin 不存在 | 阶段二 2.5 / 阶段六 6.2 |
| 页面空白 | 前端 API 地址错（仍指向 :5000） | 阶段四 4.1 |
| 接口 502 | 后端未运行或 Nginx upstream 错 | 阶段三 / 4.5 |
| 大屏 404 | 未加 VisualData 引用 | 阶段三 3.2 |
| 预览失败 | FileServer 未部署 | 阶段五 5.4 |

更多见 [附录-速查表与术语.md](./附录-速查表与术语.md)
