## 3.1 停掉占用 30000 端口的旧进程 [必选]

> **范围：** 只停止 JNPF 后端（`dotnet` + `JNPF.API.Entry`）。不影响数据库、Redis。

🪟 **Windows 11**（[管理员]）：

```powershell
netstat -ano | findstr ":30000"
# 若有 LISTENING，记下 PID：
# taskkill /PID <PID> /F
```

🐧 **Linux**：

```bash
pkill -f "JNPF.API.Entry" 2>/dev/null || true
ss -tlnp | grep 30000 || echo "[确认] 端口 30000 已空闲"
```

> **期望结果：** 无 LISTENING，或提示端口已空闲。

## 3.2 启用大屏后端模块 [必选]

> **这一步做什么：** JNPF 默认 **未编译**「数字大屏」后端模块（`JNPF.VisualData`）。不加引用则 `/api/blade-visual/*` 全部 404。

> **为什么要这么做：** 就像出厂没装天窗，要在 `JNPF.API.Entry.csproj` 里加一行 `ProjectReference` 才会编进 API。  
> **不做会怎样：** PC 前端、工作流、低代码 **不受影响**；仅大屏相关 API 404。

### 操作

用 VS Code / 记事本打开：

```
$JNPF_ROOT/application/JNPF.API.Entry/JNPF.API.Entry.csproj
```

在 `<ItemGroup>` 的 `ProjectReference` 区域（约第 322–334 行），在 `JNPF.WorkFlow` 一行 **下面** 增加：

```xml
<ProjectReference Include="..\..\modularity\visualdata\JNPF.VisualData\JNPF.VisualData.csproj" />
```

参考备份工程已含此行：`application/JNPF.API.Entry/JNPF - Backup.API.Entry.csproj` 第 331 行。

> `[可选]` **本步骤可跳过**  
> **跳过后会怎样：** 大屏设计与预览 API 不可用。  
> **什么时候需要做：** 需要数字大屏功能时回来做。

### 验证

保存后暂不单独编译；在 3.4 编译通过即表示路径正确。

> **如果你看到这个错误：**
> ```
> error : Unable to find project '..\..\modularity\visualdata\JNPF.VisualData\JNPF.VisualData.csproj'
> ```
> **原因**：`modularity/visualdata/` 目录缺失。  
> **解决**：确认源码完整；或暂时移除该行并跳过大屏。

## 3.3 核对配置文件与基础设施一致 [必选]

> **这一步做什么：** **不要重写** ConnectionStrings——打开项目已有 JSON，确认与阶段一安装的基础设施一致。  
> 配置加载：`appsettings.json` 声明扫描 `Configurations/` → 框架自动加载 `ConnectionStrings.json` 等。

### 3.3.1 ConnectionStrings.json（核对，非编造）

路径：`application/JNPF.API.Entry/Configurations/ConnectionStrings.json`

**本仓库实测完整内容：**

```json
{
  "ConnectionStrings": {
    "ConnectionConfigs": [
      {
        "Domain": "dev_v1.",
        "ConfigId": "default",
        "DBName": "ZXAF_V1_DevTest1",
        "DBType": "SqlServer",
        "Host": "(local)\\SQLEXPRESS",
        "Port": "1433",
        "UserName": "sa",
        "Password": "1qazxsw2",
        "DBSchema": "public"
      },
      {
        "ConfigId": "JNPF-Job",
        "DBName": "jnpf_sundial",
        "DBType": "SqlServer",
        "Host": "(local)\\SQLEXPRESS",
        "Port": "1433",
        "UserName": "sa",
        "Password": "1qazxsw2",
        "DBSchema": "public"
      }
    ]
  }
}
```

**核对清单：**

| JSON 字段 | 必须与谁一致 |
|-----------|-------------|
| `DBName`（default） | 阶段二创建的主库 `$MAIN_DB` |
| `DBName`（JNPF-Job） | 阶段二创建的调度库 `$JOB_DB` |
| `Host` / `UserName` / `Password` | 阶段一 1.3 验证通过的 `$DB_HOST` / `$DB_USER` / `$DB_PASS` |

> **仅当本机 SQL 实例与文件不同时才改 JSON**（如 Linux 上 `Host` 改为 `localhost`），改后重新执行：  
> `sqlcmd -S $DB_HOST -U $DB_USER -P "$DB_PASS" -Q "SELECT 1"`

### 3.3.2 Cache.json（按文件决定是否装 Redis）

**本仓库实测：**

```json
{
  "Cache": {
    "CacheType": "MemoryCache",
    "ip": "127.0.0.1",
    "port": 6379,
    "RedisConnectionString": "{0}:{1}, poolsize=500,ssl=false,defaultDatabase=7"
  }
}
```

| `CacheType` | 操作 |
|-------------|------|
| **`MemoryCache`**（当前） | **无需改、无需 Redis** |
| `RedisCache` | 须已装 Redis，且 `RedisConnectionString` 中 `password=` 与 Redis 实例一致 |

### 3.3.3 App.json — 文件预览（阶段五可选）

**本仓库实测 `KKFileDomain`：**

```json
"KKFileDomain": "http://127.0.0.1:30090/FileServer"
```

阶段五部署 kkFileView 后，若预览地址变化，**只改此 JSON 字段**与 Nginx 对齐。

| # | 验证什么 | 怎么验证 | 通过长什么样 | 失败长什么样 |
|---|----------|----------|-------------|-------------|
| 1 | 连接与 JSON 一致 | `sqlcmd -S $DB_HOST -U $DB_USER -P "$DB_PASS" -Q "SELECT 1"` | 返回 1 | Login failed → 1.1.2 方式 A/B |

## 3.4 编译并启动后端服务 [必选]

> **JWT Token** 是登录凭证，类似门禁卡；密钥在 `Configurations/JWT.json` 的 `IssuerSigningKey`，生产必须换成长随机串（≥32 字符）。

### 3.4.1 编译

🟢 **双系统通用**（[普通用户]）：

```bash
cd $JNPF_ROOT
dotnet build application/JNPF.API.Entry/JNPF.API.Entry.csproj -c Release
```

> **期望看到最后一行：**
> ```
> Build succeeded.
>     0 Error(s)
> ```

> **如果你看到这个错误：**
> ```
> error NU1101: Unable to find package xxx
> ```
> **原因**：NuGet 包下载失败。  
> **解决**：
> ```bash
> dotnet nuget add source https://nuget.cdn.azure.cn/v3/index.json -n azure-cn
> dotnet restore application/JNPF.API.Entry/JNPF.API.Entry.csproj
> ```

### 3.4.2 启动（端口 30000）

🪟 **Windows 11**（[普通用户]）：

```powershell
cd $JNPF_ROOT
$env:ASPNETCORE_ENVIRONMENT = "Production"
$env:ASPNETCORE_URLS = "http://localhost:30000"
dotnet run --project application/JNPF.API.Entry/JNPF.API.Entry.csproj -c Release --no-build --no-launch-profile
```

🐧 **Linux**：

```bash
cd "$JNPF_ROOT"
export ASPNETCORE_ENVIRONMENT=Production
export ASPNETCORE_URLS="http://localhost:30000"
dotnet run --project application/JNPF.API.Entry/JNPF.API.Entry.csproj -c Release --no-build --no-launch-profile
```

> **期望看到：** 终端输出进程保持运行；`netstat` 显示 **`:30000` LISTENING**（不要关窗口）。
>
> ⚠️ **必须加 `--no-launch-profile`**：否则 `launchSettings.json` 会把端口改回 **`:5000`**，后续 `:30000` 验证全部失败。
>
> **如果你发现监听的是 5000 而不是 30000：**
> ```
> netstat -ano | findstr ":5000"
> ```
> **原因**：未加 `--no-launch-profile`。  
> **解决**：停止进程，用上面带 `--no-launch-profile` 的命令重启。

> **如果你看到这个错误：**
> ```
> A network-related or instance-specific error occurred while establishing a connection to SQL Server
> ```
> **原因**：`ConnectionStrings.json` 连不上库。  
> **解决**：回到 3.3.1，用 `sqlcmd` 验证相同 Host/密码；确认 SQL TCP 已启用。

### 3.4.3 验证 API 文档

另开一个终端：

🪟 **Windows 11**：

```powershell
Invoke-WebRequest -Uri "http://localhost:30000/newapi/index.html" -UseBasicParsing | Select-Object StatusCode
```

🐧 **Linux**：

```bash
curl -s -o /dev/null -w "%{http_code}" http://localhost:30000/newapi/index.html
```

| # | 验证什么 | 怎么验证 | 通过长什么样 | 失败长什么样 |
|---|----------|----------|-------------|-------------|
| 1 | API 文档 | 浏览器打开 `http://localhost:30000/newapi/index.html` | 左侧有接口分组列表，标题含「智轩开发基础平台」或 JNPF | `无法访问` → 进程未起；`404` → 检查 URL 是否为 `/newapi` |
| 2 | 健康探测 | `curl http://localhost:30000/` | HTTP 响应（非连接拒绝） | `Connection refused` → 回到 3.4.2 |

**API 文档页长什么样：**

- 浏览器地址栏：`http://localhost:30000/newapi/index.html`
- 页面为 Knife4jUI 风格，左侧树形接口列表，右侧可展开 API 详情
- 顶部 Document 标题来自 `Configurations/Swagger.json`

## 3.5 注册为系统服务 [推荐·生产]

> **跳过说明：** 开发调试可每次手动 `dotnet run`。**生产**必须注册服务或容器，保证重启后自动拉起。

### Windows — 使用 NSSM 或 IIS

简要步骤（IIS）：

1. `dotnet publish application/JNPF.API.Entry/JNPF.API.Entry.csproj -c Release -o C:\JNPF\api`
2. 安装 .NET 6 Hosting Bundle  
3. IIS 新建站点，物理路径 `C:\JNPF\api`，绑定端口 30000  
4. 应用程序池：「无托管代码」

环境变量在 IIS「配置编辑器」或 `web.config` 中设置 `ASPNETCORE_URLS`。

### Linux — systemd 示例

```ini
# /etc/systemd/system/jnpf-api.service
[Unit]
Description=JNPF API
After=network.target

[Service]
WorkingDirectory=/opt/jnpf/api
ExecStart=/usr/bin/dotnet /opt/jnpf/api/JNPF.API.Entry.dll
Environment=ASPNETCORE_URLS=http://0.0.0.0:30000
Environment=ASPNETCORE_ENVIRONMENT=Production
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now jnpf-api
```
