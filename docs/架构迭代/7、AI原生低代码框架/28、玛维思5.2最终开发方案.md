# JNPF AI-Oriented 轻量数据湖(SaaS 版)第一阶段开发计划 v5.2

> **版本**: v5.2 最终版 · 2026-06-14
> **目标场景**: 100 个企业订阅用户 × 每企业 20-100 人 MES SaaS 软件
> **第一阶段范围**: 0-20 租户上线,10 周交付
> **设计原则**: 演进式架构、租户级隔离、成本可控、可平滑扩展
> **采纳专家意见**: D 爷(100%)、清言(78%)、KIMI(100%)

## 一、总体纲要

### 1.1 项目定位

> **在 10 周内交付一个面向 100 租户 SaaS MES 的"轻量级 AI 数据中台",支持业务数据(非传感器数据)的自然语言查询、口径治理、跨租户隔离、成本可控,具备 0→100 租户平滑演进能力。**

### 1.2 三大铁律

| 铁律         | 内容                                                        | 否决项                          |
| ------------ | ----------------------------------------------------------- | ------------------------------- |
| **轻量起步** | 阶段一用最小必要组件(SQL Server + Redis + Ollama + Channel) | 不引入 Hadoop/Spark/Kafka/Flink |
| **平滑演进** | 所有组件通过标准接口接入,阶段一应用代码不重写               | 不做"写死在代码里"的方案        |
| **成本可控** | 单租户月摊销 ≤ 3500 元,LLM 成本 ≤ 总运营 30%                | 不做"无限制 Token 消耗"的方案   |

### 1.3 范围与边界

**做**(第一阶段 10 周):
- ✅ 100 租户 SaaS 多租户架构(独立 Schema 同库)
- ✅ MES 业务数据(工单/报工/质检/设备主数据/物料主数据/人员主数据/排班/库存)
- ✅ 30 个 MES 核心指标(行业标准模板 + 仿真验证)
- ✅ 自然语言查询(AI 业务助手,LLM 4 级路由)
- ✅ 主动预警(简化版)
- ✅ 跨租户隔离 + 审计 + 二次授权工作流

**不做**(明确划清边界):
- ❌ 传感器数据接入(留给"工业智能事业部")
- ❌ 预测维修 / 设备健康度
- ❌ 生产流程优化 / 排产优化
- ❌ 电力损耗优化
- ❌ 数字孪生 / 3D 可视化
- ❌ 时序数据库 / 流处理 / ML 平台
- ❌ 流程/表单/报表引擎 AI 化(留给第二阶段)
- ❌ 移动端集成(留给第二阶段)

### 1.4 关键名词定义

| 名词            | 定义                                                         | 不包含                       |
| --------------- | ------------------------------------------------------------ | ---------------------------- |
| **轻量数据湖**  | 基于 SQL Server + Redis + 小模型的轻量化数据中台,服务 MES 业务数据 | 不包含时序库、Hadoop、Spark  |
| **AI 业务助手** | 基于自然语言的 MES 业务数据查询工具                          | 不包含控制设备执行、写入数据 |
| **业务数据**    | 来自 MES/ERP/OA 的离散业务数据                               | 不包含 IoT 传感器连续流数据  |
| **指标**        | 可量化的业务度量(良品率、OEE、计划达成率)                    | 不包含设备物理参数           |
| **AI 推理**     | 基于 LLM 的意图识别、结果解读                                | 不包含 ML 模型训练/部署      |

### 3.2 关键架构原则

1. **独立 Schema 隔离**:每租户一个 Schema,SqlSugar 动态表名切换
2. **弹性资源隔离**:共享 60% + 系统 30% + 突发 10%,允许借调
3. **数据四级分层**:热 6 个月 + 温 6-12 个月 + 冷 1-3 年 + 深冷 > 3 年
4. **预聚合优先**:AI 查询走预聚合指标表,明细走生产库只读副本
5. **LLM 4 级路由**:Simple/Standard/Complex/Unknown,安全优先走云端
6. **Schema RAG 混合检索**:Qdrant 向量(语义) + 倒排索引(精确)
7. **接口标准化**:所有组件通过标准接口(SQL/HTTP)接入,阶段二/三可平滑替换

## 五、多租户详细设计

### 5.1 弹性 Resource Governor 配置

```sql
-- ========================================
-- 第一阶段(0-20 租户)弹性资源池配置
-- ========================================

-- 1. 共享租户资源池(允许借调,但忙时严格限制)
CREATE RESOURCE POOL SharedTenantPool
WITH (
  MIN_CPU_PERCENT = 0,
  MAX_CPU_PERCENT = 60,        -- 所有共享租户合计不超过 60%
  CAP_CPU_PERCENT = 100,       -- 但允许短期突发
  MIN_MEMORY_PERCENT = 0,
  MAX_MEMORY_PERCENT = 60,
  CAP_MEMORY_PERCENT = 100
);

-- 2. 系统预留资源池(数据库自身 + 监控 + ETL)
CREATE RESOURCE POOL SystemReservedPool
WITH (
  MIN_CPU_PERCENT = 30,        -- 系统最低 30% CPU 保障
  MAX_CPU_PERCENT = 100,
  MIN_MEMORY_PERCENT = 30,
  MAX_MEMORY_PERCENT = 100
);

-- 3. 突发预留资源池(应对早高峰、批处理)
CREATE RESOURCE POOL BurstReservedPool
WITH (
  MIN_CPU_PERCENT = 10,
  MAX_CPU_PERCENT = 100,
  CAP_CPU_PERCENT = 100
);

-- 4. 分类器:按登录名路由
CREATE FUNCTION dbo.RG_TenantClassifier()
RETURNS SYSNAME
WITH SCHEMABINDING
AS
BEGIN
  DECLARE @group SYSNAME = 'default';
  DECLARE @login SYSNAME = SUSER_NAME();
  
  IF @login IN ('sa', 'sysadmin_user', 'monitor_user', 'etl_user')
    SET @group = 'SystemReservedGroup';
  
  IF @login LIKE 'burst_app_%'
    SET @group = 'BurstReservedGroup';
  
  IF @login LIKE 'tenant_user_%'
    SET @group = 'SharedTenantGroup';
  
  RETURN @group;
END;

ALTER RESOURCE GOVERNOR WITH (CLASSIFIER_FUNCTION = dbo.RG_TenantClassifier);
ALTER RESOURCE GOVERNOR RECONFIGURE;
```

### 5.3 独立 Schema 实现

```csharp
public class TenantAwareSqlSugarClient
{
    public ISqlSugarClient GetClient(string tenantId)
    {
        var db = new SqlSugarClient(new ConnectionConfig
        {
            ConnectionString = "主连接串", // 同一个 MES_ANALYTICS
            DbType = DbType.SqlServer,
            IsAutoCloseConnection = true
        });
        
        // AOP:自动注入 Schema 前缀
        db.Aop.DataExecuting = (oldValue, entityInfo) =>
        {
            if (entityInfo.OperationType == OperationType.Insert ||
                entityInfo.OperationType == OperationType.Update ||
                entityInfo.OperationType == OperationType.Query)
            {
                var tableName = entityInfo.EntityInfo.DbTableName;
                entityInfo.EntityInfo.DbTableName = $"tenant_{tenantId}.{tableName}";
            }
        };
        
        return db;
    }
}
```

### 5.4 Schema 自动创建

```sql
-- 租户 Schema 创建脚本(自动化执行)
DECLARE @TenantId NVARCHAR(50) = 'T001';
DECLARE @SchemaName NVARCHAR(50) = 'tenant_' + @TenantId;

-- 1. 创建 Schema
EXEC('CREATE SCHEMA ' + @SchemaName);

-- 2. 复制表结构(从模板 schema)
DECLARE @sql NVARCHAR(MAX) = '';
SELECT @sql = @sql + 
  'CREATE TABLE ' + @SchemaName + '.' + name + ' (LIKE dbo.template_' + name + ' INCLUDING ALL);'
FROM sys.tables 
WHERE schema_id = SCHEMA_ID('dbo') AND name LIKE 'template_%';
EXEC sp_executesql @sql;
```

### 5.5 Sentinel 限流配置

```csharp
var rules = new List<FlowRule>
{
    // 全局:总 QPS 上限
    new FlowRule("global_ai_query")
        .SetGrade(RuleConstant.FLOW_GRADE_QPS)
        .SetCount(200),  // 20 租户,共享 200 QPS
    
    // 租户级:单租户 QPS 上限
    new FlowRule($"tenant_{tenantId}_ai_query")
        .SetGrade(RuleConstant.FLOW_GRADE_QPS)
        .SetCount(20),  // 单租户 20 QPS
    
    // 慢查询熔断
    new DegradeRule($"tenant_{tenantId}_slow")
        .SetGrade(RuleConstant.DEGRADE_GRADE_RT)
        .SetCount(5000)  // 响应时间 > 5s 熔断
        .SetMinRequestAmount(10)
        .SetStatWindowMs(30000)
        .SetSlowRatioThreshold(0.5),
};
```

## 八、LLM 4 级分类器详细设计

### 8.1 分类规则

```csharp
public enum QueryComplexity 
{
    Simple,     // 单表 + 单维度 + 标准指标 → 本地 Qwen-7B
    Standard,   // 2-3 表 JOIN + 标准指标 → 本地 Qwen-7B(带 Schema 提示)
    Complex,    // 多表 + 自定义 + 归因 → 云端 DeepSeek-V3
    Unknown     // 置信度 < 0.8 → 默认云端(安全优先)
}

public class QueryClassifier
{
    public (QueryComplexity complexity, double confidence) Classify(NaturalLanguageQuery query)
    {
        int simpleScore = 0, standardScore = 0, complexScore = 0;
        
        // 1. 关键词规则
        if (ContainsAny(query.Text, new[] { "今天", "昨天", "本周", "本月" }))
            simpleScore += 2;
        if (ContainsAny(query.Text, new[] { "环比", "同比", "对比" }))
            standardScore += 1;
        if (ContainsAny(query.Text, new[] { "归因", "为什么", "原因", "怎么改善" }))
            complexScore += 3;
        
        // 2. 指标数规则
        if (query.MentionedMetrics.Count == 1) simpleScore += 2;
        else if (query.MentionedMetrics.Count <= 3) standardScore += 1;
        else complexScore += 2;
        
        // 3. 维度数规则
        if (query.MentionedDimensions.Count <= 1) simpleScore += 1;
        else if (query.MentionedDimensions.Count <= 3) standardScore += 2;
        else complexScore += 1;
        
        // 4. JOIN 需求
        if (query.RequiresJoin) complexScore += 3;
        
        // 5. 业务解读需求
        if (query.RequiresBusinessInsight) complexScore += 2;
        
        // 6. 综合判断
        int maxScore = Math.Max(simpleScore, Math.Max(standardScore, complexScore));
        if (maxScore == 0) return (QueryComplexity.Unknown, 0.5);
        
        int total = simpleScore + standardScore + complexScore;
        double confidence = (double)maxScore / total;
        
        if (confidence < 0.8) return (QueryComplexity.Unknown, confidence);
        
        if (maxScore == simpleScore) return (QueryComplexity.Simple, confidence);
        if (maxScore == standardScore) return (QueryComplexity.Standard, confidence);
        return (QueryComplexity.Complex, confidence);
    }
}
```

## 十二、演进路径(0 → 20 → 50 → 100 租户)

### 12.1 第一阶段(0-20 租户,本计划 10 周)

- **架构**: 独立 Schema(同库) + 弹性 RG + SQL Server + Redis + Ollama + Qdrant
- **能力**: 30 个标准指标 + 自然语言查询 + 主动预警 + 4 级 LLM 路由
- **数据保留**: 6 个月热 + 3 年归档
- **成本**: 6.25 万/月,单租户 3125 元/月
- **风险**: 中(独立 Schema 测试覆盖度决定)

### 12.2 第二阶段(20-50 租户,触发式演进,8-10 周)

**触发条件**(满足任一):
- 租户数 > 20
- 总日增量 > 1 亿行
- 单租户 QPS > 50
- 大租户(年付 > 50 万)> 3 个

**架构演进**:
- 大租户独立 OLAP 库(资源物理隔离)
- Redis Cluster(3 主 3 从)
- AlwaysOn 读写分离(只读副本承担分析查询)
- 凌晨预计算 + 早 7:00 增量预计算
- ClickHouse 集群(分析查询专用)

**成本**: ~10 万/月,单租户 ~2000 元/月

### 12.3 第三阶段(50-100 租户,触发式演进,8-10 周)

**触发条件**(满足任一):
- 租户数 > 50
- 大租户 > 10 个
- 任意租户数据 > 10 亿行
- 月 LLM 成本 > 5 万

**架构演进**:
- ShardingSphere 分库分表
- ClickHouse 集群(MPP 架构,水平扩展)
- Kafka 替换 Channel(分布式消息队列)
- 边缘 LLM 缓存 + 结果预计算
- 灰度发布平台 + 租户级 SLA 监控

**成本**: ~15 万/月,单租户 ~1500 元/月
