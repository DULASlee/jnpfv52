## I-04：状态标记语义混乱

### 怎么改

**全文档统一 7 种状态标记**，消除歧义：

| 状态         | 语义                | 触发条件           | 适用对象                  |
| ------------ | ------------------- | ------------------ | ------------------------- |
| ✅ **真完成** | 所有验收项全绿      | 7 状态标记自检全过 | 里程碑 / 子任务           |
| ⚠️ **部分**   | 部分完成 + 已知缺口 | 至少有 1 项 ⚠️      | 里程碑 / 子任务           |
| ⏳ **进行中** | 当前正在施工        | 验收未开始         | 子任务                    |
| 🔵 **已实现** | 代码库已合并        | PR merged          | 已实现项（§1.3.1 冻结项） |
| 🔶 **半实现** | 部分实现            | 前端有/后端无      | 增量项（§1.3.2 B 段）     |
| ⚪ **纸面**   | 仅文档存在          | 代码库无           | 规划项                    |
| ❌ **待验证** | 待评审验收          | 未触发评审         | 里程碑 / 子任务           |
| 🚧 **阻塞**   | 有 blocker          | blocker 未解除     | 任意                      |

**§12.1 改造**：每个里程碑 + 子任务的"状态"列**必须从这 7 选 1**，不允许混用文字描述（"待建"/"待验证"/"未完成"等模糊词）。

**§1.3.1 / §1.3.2 / §6.0.1 同步改造**：
- §1.3.1 冻结项：`✅ 已实现` → `🔵 已实现`
- §1.3.2 B 段增量：`⚠️ 已实现（前端）/ 待实现（后端）` → `🔶 半实现`
- §6.0.1 DDL 状态：`⚠️ DDL 字段多于 Entity` → `🔶 半实现`

**配套检查脚本**（避免下次评审又混乱）：

```python
           '🔶 半实现', '⚪ 纸面', '❌ 待验证', '🚧 阻塞'}

```

### 谁来改
