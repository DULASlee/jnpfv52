# 第三章 · AgentIR 体系架构

## 3.1 AgentIR 整体架构

### ARC-R2-3-001 AgentIR 与 FormPageIR 平级

**决策**：AgentIR 是独立的 IR 类型，与 FormPageIR / FlowIR / DashboardIR 平级，统一由 CompileGateway 编译。

**支撑**：
- 33 号裁定 3（AgentIR）
- 运行态架构设计说明书 ARC-RT-7-001

**架构含义**：
- AgentIR 有独立的 JSON Schema
- AgentIR 有独立的持久化表（BASE_AGENT_IR）
- AgentIR 有独立的 Studio（AgentIR Studio）
- AgentIR 通过 CompileGateway 编译为 agent-widget

### AgentIR 组成结构

```
AgentIR
  ├── PersonaIR（人设）
  │   ├── scope: 'role'（第二期固定）
  │   ├── roleCode: 'production_planner' | 'quality_engineer' | 'equipment_admin'
  │   ├── displayName: '生产计划员助手'
  │   ├── systemPrompt: '你是生产计划员的 AI 助手...'
  │   ├── allowedMetricCodes: ['oee', 'active_orders', ...]
  │   └── locale: 'zh-CN'
  ├── SkillIR[]（技能列表）
  │   ├── SkillIR[0]
  │   │   ├── mcpServer: 'data-mcp'
  │   │   ├── tools: ['query_metrics', 'list_metrics', 'explain_metric']
  │   │   └── config: { theme: 'light' }
  │   └── SkillIR[1]
  │       ├── mcpServer: 'report-mcp'
  │       ├── tools: ['render_chart', 'render_table']
  │       └── config: { defaultChartType: 'line' }
  ├── KnowledgeRef[]（知识引用）
  │   ├── KnowledgeRef[0]
  │   │   ├── nodeId: 'KNOW_NODE_001'
  │   │   ├── domainTag: 'mes.scheduling'
  │   │   └── sourceType: 'manual'
  │   └── KnowledgeRef[1]
  │       ├── nodeId: 'KNOW_NODE_002'
  │       ├── domainTag: 'mes.quality'
  │       └── sourceType: 'upload'
  ├── MountPointIR[]（挂载点）
  │   └── MountPointIR[0]
  │       ├── menuCode: 'MES_WORK_ORDER'
  │       └── position: 'sidebar'
  ├── version: 1（乐观锁版本号）
  └── status: 'draft' | 'published'
```

## 3.2 PersonaIR 架构

### ARC-R2-3-002 PersonaIR scope 固定为 role

**决策**：第二期 PersonaIR.scope 必须为 `role`，禁止 `enterprise`（第三期）。

**支撑**：
- 33 号 §0.5（目标二定义）
- 36 号施工计划 §2.2

**架构含义**：
- Studio UI 中 scope 字段锁定为 `role`
- 后端校验：scope !== 'role' → 拒绝保存
- 岗位 Agent 只管本岗，不跨模块统摄

### PersonaIR 字段定义

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `scope` | `'role'` | ✅ | 固定值，锁定 |
| `roleCode` | string | ✅ | 岗位代码，如 `production_planner` |
| `displayName` | string | ✅ | 显示名称，如「生产计划员助手」 |
| `systemPrompt` | string | ✅ | 系统提示词，定义人设边界 |
| `allowedMetricCodes` | string[] | ✅ | 白名单 MetricIR.code |
| `locale` | string | ❌ | 默认 `zh-CN` |

### 岗位角色配置矩阵

| 岗位 | roleCode | 绑定 MetricIR | KnowledgeIR 域标签 |
|------|----------|---------------|-------------------|
| **生产计划员** | `production_planner` | oee · active_orders · on_time_reporting_rate | mes.scheduling |
| **质量工程师** | `quality_engineer` | yield_rate · pending_quality_inspection · defect_rate | mes.quality |
| **设备管理员** | `equipment_admin` | equipment_failure_count · oee · average_repair_time | mes.equipment |

## 3.3 SkillIR 架构

**支撑**：

**架构含义**：
- 第二期仅支持 data-mcp + report-mcp

## 3.5 AgentIR 版本管理架构

### ARC-R2-3-003 IrDependencyGraph 依赖追踪

**决策**：MetricIR 变更时，IrDependencyGraph 自动标记依赖的 AlertRuleIR / AgentIR 为「需重新发布」。

**支撑**：
- 33 号裁定 9（IR 版本追踪）
- 36 号施工计划 R2-S0

**架构含义**：

```
MetricIR v2 发布
  ↓
IrDependencyGraph 查询
  ↓ 依赖的 AlertRuleIR
  ├── AlertRuleIR_001 → 标记 needs_republish
  └── AlertRuleIR_002 → 标记 needs_republish
  ↓ 依赖的 AgentIR
  └── AgentIR_001 → 标记 needs_republish
  ↓ 写入
IR_DEPENDENCY_LOG 表
```

### IrDependencyGraph 数据模型

| 字段 | 类型 | 说明 |
|------|------|------|
| `sourceIrType` | `'MetricIR' \| 'AgentIR'` | 源 IR 类型 |
| `sourceIrId` | string | 源 IR ID |
| `targetIrType` | `'AlertRuleIR' \| 'AgentIR'` | 目标 IR 类型 |
| `targetIrId` | string | 目标 IR ID |
| `relationType` | `'metric_dependency' \| 'skill_dependency'` | 依赖类型 |
| `status` | `'valid' \| 'needs_republish'` | 依赖状态 |

### 版本生命周期

```
草稿（draft）
  ↓ 仿真通过
内部测试（testing）
  ↓ 业务审核
业务审核（reviewing）
  ↓ 审核通过
发布（published）
  ↓ 废弃
deprecated
  ↓ 回滚
rollback → 任意历史版本
```

- Widget 持有 MES 业务 Store 引用
- Widget 直接访问数据库

```typescript
// 保存时传入 currentVersion（前端持有）
async saveAgentIR(ir: AgentIR, currentVersion: number): Promise<SaveResult> {
```

### 冲突处理流程

```
用户 A 编辑 AgentIR（version=1）
  ↓
用户 B 同时编辑同一 AgentIR（version=1）
  ↓
用户 A 保存（currentVersion=1）→ 成功 → version=2
  ↓
用户 B 保存（currentVersion=1）→ 冲突 → HTTP 409
  ↓
前端弹出 Modal
  ├─ 「xxx 在 HH:mm 已修改此 Agent」
  ├─ 「查看差异」（字段级对比）
  └─ 「强制覆盖（我的版本）」
```

**决策**：切断 LLM/Qdrant/MCP 后，CRUD/流程/AlertRuleIR Job/预聚合 Job 零 Exception。

**支撑**：

- 36 号验收清单 §13.2

**架构含义**：

| 组件失效 | 降级行为 | 用户感知 |
|----------|----------|----------|
| LLM API 不可用 | 规则引擎兜底 | 岗位 Agent 返回有限结果 |
| Qdrant 不可用 | 知识检索降级 | Agent 无知识上下文 |
| data-mcp 不可用 | 问数中断 | Agent 无法查询指标 |
| report-mcp 不可用 | 图表降级 | Agent 返回纯文本 |
| AI 全部关闭 | AlertRuleIR Job 正常 | 预警仍推送 |

### NL 四级降级路径

```
正常:   NL → 规则模板 → LLM(可选) → MQL → DataQueryGateway → 预聚合
降级一: NL → 规则模板 → MQL → SQL（LLM 不可用）
降级二: NL → MetricIR 全量元数据注入 → LLM（Qdrant 不可用）
降级三: MQL → 分析库只读副本（主分析库过载）
```
