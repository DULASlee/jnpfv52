# 第一章 · 文档概述

## 1.1 编写目的

本说明书是 JNPF 运行态智能层第一期在**架构层面**的单一真源。它承接《需求分析说明书》的需求条目（FR-* / NFR-*），为《系统详细设计说明书》提供架构级决策依据。

**与需求说明书的关系**：
- 需求说明书回答**"做什么 / 不做什么"**（FR 编号为唯一标识）
- 架构说明书回答**"为什么这么做 / 边界在哪"**（ARC-R1 编号为唯一标识）
- 详细设计说明书回答**"怎么做"**（DS 编号为唯一标识）

## 1.2 系统范围

**架构层范围**：
- L1→L5 轻量数据湖分层架构
- MetricIR 指标引擎架构
- DataQueryGateway(MQL) 查询网关架构
- data-mcp 三工具架构
- DashboardIR 单卡编译架构
- CDC 同步与 SchemaGovernor 架构

**架构层非范围**：
- AgentIR / AlertRuleIR（第二期）
- semantic 整页驾驶舱（第三期）
- TimeSeriesIR / IoT 时序（第四期）
- 单个接口的实现细节、单个表的字段定义（详细设计说明书）

| 约束编号 | 内容 | 架构含义 |
|---------|------|----------|
| **约束一 · JNPF 增量生存** | AI 挂时 VisualDev/流程/权限 100% 可用 | 预聚合 Job 独立于 LLM；AI-off 时 CRUD/流程/Job 零 Exception |
| **约束二 · 运行态红线** | 目标定义仅 33 号第二部分 §0.4 | 不做 Agent/Alert/IoT；仅交付 L1-L5 + MetricIR + MQL + data-mcp |

## 2.3 设计原则

### 2.3.1 架构原则

| 原则 | 内容 | 架构决策 |
|------|------|----------|
| **AP-R1-1 口径法律** | 同一 MetricIR.code → MQL → 预聚合 SQL 数值必须一致 | ARC-R1-3-001 |
| **AP-R1-2 禁止 LLM 直写 SQL** | 所有查询必须经 DataQueryGateway | ARC-R1-6-003 |

| 原则 | 含义 | 架构对应 |

## 3.2 核心架构决策

### ARC-R1-3-001 口径法律：MetricIR.code 全链路一致

**决策**：同一 MetricIR.code 在 Studio、MQL、预聚合 SQL、看板卡、Agent（第二期）中数值必须一致。

**支撑**：
- 33 号约束五（IR 互通）
- 需求 FR-021（指标定义完整性）

**架构含义**：
- MetricIR JSON Schema 是口径的唯一真源
- MqlTranslator 必须基于 MetricIR.sql_template 生成 SQL
- 预聚合 Job 必须基于 MetricIR.sql_template 计算
- 看板卡必须消费 METRIC_AGGREGATE_CACHE

### ARC-R1-3-002 CDC 同步架构：P0/P1/P2 分级

**决策**：CDC 同步采用 P0/P1/P2 三级策略，SQL Server Change Tracking 首选。

**支撑**：
- 33 号裁定 7（冷热同步）
- 需求 FR-005~FR-009（分级同步）

**架构含义**：

| 优先级 | 数据 | 频率 | 延迟目标 |
|--------|------|------|----------|
| P0 | 工单/报工/质检 | 每 30s | P95≤30s |
| P1 | 库存/排班 | 每 5min | P95≤5min |
| P2 | BOM/工艺 | 凌晨全量 | 当日完成 |

- P0 延迟>30s 持续 2min → 自动转 P1 + 告警
- 失败 3 次 → 入死信队列 DLQ
- 软删除同步：源表 F_DELETE_MARK=1 目标表同步标记

### ARC-R1-3-003 L4 语义层：Qdrant Hybrid Search

**决策**：Qdrant Hybrid Search（向量 + BM25，RRF 融合打分），熔断降级到 SQL Server CONTAINS。

**支撑**：
- 33 号裁定 2（语义检索）
- 需求 FR-013~FR-016（Qdrant 双模）

**架构含义**：
- 主模式：Hybrid（非互斥切换，消除降级质量断崖）
- Payload 强制 tenant_id 过滤
- 熔断降级：Qdrant 不可用 → CONTAINS（召回率 SLA≥60%）
- 熔断恢复：5min 健康检查自动切回
- 向量更新：增量重建（Channel 推送）

## 3.3 数据流架构

### 3.3.1 指标全链路数据流

```
业务人员 Studio
  ↓ 创建/修改 MetricIR
METRIC_IR_DEFINITION（草稿）
  ↓ 仿真
SimulateMetricAsync → L3 预聚合对比
  ↓ 发布
METRIC_IR_DEFINITION（已发布）
  ↓ Channel 推送
MetricIRVectorSyncWorker
  ↓ 向量化
Qdrant（向量 + BM25）
  ↓ 编译
CompileGateway → DashboardIR 单卡
  ↓ 渲染
前端 Vue3 组件
```

### 3.3.2 查询链路数据流

```
用户/Agent
  ↓ NL 或 MQL
DataQueryGateway
  ↓ Step1: 意图识别（规则 80% + LLM 20%）
  ↓ Step2: PII 脱敏
  ↓ Step3: MQL 生成
  ↓ Step4: 安全校验（白名单）
  ↓ Step5: SQL 生成（MqlTranslator）
  ↓ Step6: 执行 + 格式化
QueryResult（data + total + interpretation）
```

### 3.3.3 CDC 同步数据流

```
L1 MES 源表
  ↓ Change Tracking 检测变更
SyncEngineService（P0 30s / P1 5min / P2 凌晨）
  ↓ 拉取变更批次
SchemaGovernor 确认 L2 Schema 已就绪
  ↓ 写入 L2 分析库
AggregationJob 增量预聚合
  ↓ 更新水位线
DATA_SYNC_TASK
  ↓ 异常处理
ALERT_LOG + 降级策略
```
