## 一、总纲：我们为何而战

在审阅全部四份战略情报后，我看到了一个拥有**118个动态API服务**、**成熟的工作流引擎**、**67个组件映射**、**15步中间件管线**的工业级低代码平台。同时，我也看到了它的真相：**AI能力为零**，正面临“小白AI”在简单CRUD领域的降维打击。

然而，这正是我们的历史机遇。因为企业软件的真正价值不在“生成CRUD”，而在**管理复杂的业务规则**。这正是JNPF的基因——自研7态状态机、租户隔离、数据权限、Outbox事件驱动、模块化单体架构。我们的护城河，不是重复造轮子，而是**为这套工业级的骨骼，注入AI的灵魂，并让它学会自我进化**。

本计划将指挥我们从一艘坚固的帆船，升级为一艘具备AI导航、自我修复和进化能力的星际战舰。整个过程将始终保障“降智逃生”基本盘，并分三个阶段实现终极愿景。

### 阶段一：顾问式AI开发范式（第13-32周）

**战略目标**：实现“顾问式AI”，让AI成为开发者/架构师的决策合伙人。人类始终在环路中，AI降智可无缝降级为专家模式。

#### 1.1 核心智能体构建

我们将基于阶段零的IR和DKEE，构建四个顾问智能体：

| 智能体             | 依赖                                    | 核心能力                                              | 用户交互方式    |
| ------------------ | --------------------------------------- | ----------------------------------------------------- | --------------- |
| **需求分析师**     | DKEE + LLM网关                          | 将自然语言需求转化为带aiHints的领域模型、用户故事地图 | 对话工作台      |
| **架构师**         | EAB（从知识图谱导出）+ 架构骨架知识     | 基于当前架构约束给出技术选型建议，生成架构描述IR      | 对话+架构图预览 |
| **UI/UX设计师**    | 设计DNA（组件映射+设计规范）            | 根据需求生成高保真页面IR，自动推荐组件配置            | 对话+实时预览   |
| **数据与后端专家** | 实体关系知识 + 基础契约（多租户、审计） | 生成数据模型IR，自动注入基础架构约束                  | 对话+ER图预览   |

**实现方式**：
- 在JNPF管理后台增加“AI开发工作台”入口。
- 每个智能体都是一个独立模块，通过统一的`AiSessionService`管理对话状态和上下文（基于IR和DKEE）。
- 智能体输出均为IR（我们阶段零定义的格式），确保与人类手动设计同构。

#### 1.2 人类在环与“降智逃生”

**关键设计**：所有AI生成的IR，都必须经过**业务规则配置中心**的人类审核。这里是解决“AI不懂业务逻辑”死穴的接口。

- **业务规则配置中心**：在现有工作流和表单配置之上，构建可视化决策表/决策树编辑器。AI可以根据需求**初步生成规则结构**（如条件分支），但人类专家必须精修、确认，尤其是涉及金额、审批级别等核心业务逻辑。
- **无AI专家模式**：当大模型API失败或质量过低时，系统自动切换到手工作业模式。所有对话驱动的步骤，退化为可视化的表单设计、架构图拖拽、规则编辑器。两者产生的IR完全同构，保证业务不中断。
- **DKEE V1.0进化**：记录所有人类在配置中心做出的规则修改、模型调整，自动更新知识图谱（版本化）。这是知识进化的起点。

#### 1.3 阶段一交付物

- `jnpf-ai-advisor` 版本：AI工作台可用，四个智能体可针对“智能更衣柜”等种子领域给出建议。
- DKEE包含至少100个实体、50条业务规则、所有组件映射关系。
- 业务规则配置中心上线，支持决策表和决策树。
- 无AI专家模式完整可用。

**里程碑**：第20周，AI工作台首个智能体（需求分析师）内测；第28周，四个智能体联调；第32周，正式发布。

### 阶段二：自博弈进化闭环（第33-52周）

**战略目标**：实现“领域自博弈进化引擎”，让平台在选定领域（如智能更衣柜、智慧工地）通过自我对抗自动提升业务正确性，形成不可逾越的护城河。

#### 2.1 自博弈引擎架构

基于AlphaZero思想，在沙箱环境中运行三个智能体：

| 角色           | 职责                                                         | 技术实现                                                     |
| -------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **需求攻击者** | 从DKEE和领域模式中生成海量、对抗性需求场景（正常、异常、矛盾需求） | LLM + 知识图谱随机游走，温度参数控制创造性                   |
| **系统构建者** | 即阶段一的顾问式AI，自动接收需求并生成完整系统（后端+前端），部署至沙箱 | 调用阶段一智能体，自动化执行，生成代码并部署到Docker容器     |
| **对抗性判官** | 根据需求意图和领域知识，生成深度业务测试用例，执行结果判定（语义验证，不仅仅是API断言） | 基于DKEE的业务规则逻辑断言，例如“VIP订单在任何插单场景下是否绝对优先” |

**循环流程**：
1. 攻击者生成一批需求 → 构建者生成系统 → 判官测试 → 发现缺陷。
2. 判官生成缺陷报告 → 构建者分析并修改IR/知识图谱 → 重新部署 → 判官再次测试。
3. 循环直至通过率达标或人类介入。
4. **自动进化**：成功修复的规则和模式，被DKEE提炼为新的领域模式节点，附上通过测试的证明。关键规则变更需人类审核合入主分支。

**沙箱环境**：利用我们单体Docker的30秒快速启动优势，每个测试场景启动一个完整JNPF实例+测试数据库，测试完即销毁。支持并发跑多个场景。

#### 2.2 领域知识图谱自动增长

- 每次自博弈成功解决的缺陷，其解决方案（新的约束、新的模式）被自动抽象为知识图谱节点，并与现有知识关联。
- 平台将拥有“智能更衣柜”、“智能MES”等领域的超级知识图谱，这些图谱是经过千万次对抗验证的，远非静态文档可比。

#### 2.3 阶段二交付物

- 自博弈引擎V1.0，支持“智能更衣柜”领域的全自动对抗训练。
- 经过至少10,000次自博弈循环的领域知识图谱，包含已验证的业务模式。
- 深度生成式测试与自修复引擎：可生成业务测试用例，并能对简单缺陷自动提出修复建议。
- 无AI模式依然可用，因为自博弈只增强知识图谱，不破坏原有开发模式。

**里程碑**：第40周，沙箱环境与判官引擎完成；第48周，自博弈闭环跑通；第52周，发布进化版。

## 四、护城河构建路线图

我们的护城河是两个相互增强的系统，它们将让模仿者望尘莫及：

1. **领域知识自动进化引擎（DKEE）**  
   - **阶段零**：手工构建种子。  
   - **阶段一**：记录人类修改，自动版本化。  
   - **阶段二**：自博弈自动提炼新模式。  
   - **最终形态**：越用越聪明，客户数据隔离但模式共享，形成网络效应。

2. **深度生成式测试与自修复引擎**  
   - **阶段二**：与自博弈判官合一，提供业务逻辑级别的语义测试。  
   - **未来**：可为客户私有化部署的自进化提供测试支持。

**竞争壁垒**：后来者可以抄袭界面、抄袭代码生成器，但无法抄袭一个经过数亿次业务对抗验证的活知识图谱。这是“行业智能”的原子弹。

## 五、关键风险与缓解

| 风险                           | 概率 | 影响 | 缓解措施                                                     |
| ------------------------------ | ---- | ---- | ------------------------------------------------------------ |
| AI大模型“降智”或API中断        | 中   | 高   | 无AI专家模式完全独立，保证核心开发能力不受损                 |
| 安全漏洞未及时修复导致生产事故 | 高   | 极高 | 阶段零优先修复3个CRITICAL，后续持续扫描                      |
| 团队对AI原生开发模式不适应     | 中   | 中   | 从顾问式AI开始，人类始终在环，渐进过渡                       |
| 竞品先发优势                   | 低   | 高   | 我们聚焦“业务规则推理”和“自博弈验证”的无人区，建立绝对壁垒   |
| 自博弈引擎开发难度超预期       | 中   | 高   | 最小闭环先行：先用脚本模拟攻击者，手工更新知识图谱，验证可行性后再全自动 |
