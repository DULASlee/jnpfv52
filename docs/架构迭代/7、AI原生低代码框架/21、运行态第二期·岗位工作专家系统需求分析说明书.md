# 第一章 · 文档概述

## 1.1 编写目的

本说明书是 JNPF 运行态智能层第二期的**正式需求文档**，目的是：

1. **统一认知**——将分散在 33 号白皮书、36 号施工计划中的需求描述收敛为一份**单一真源**
2. **明确边界**——清晰区分"目标二（本期）"与"目标三/四（后续）"，避免研发越界
3. **驱动后续**——为架构设计说明书、详细设计说明书提供需求层输入
4. **验收对齐**——为 M-P1 里程碑提供可验证的需求条目

## 1.2 系统范围与边界

### 1.2.1 系统定义

**运行态第二期（岗位工作专家）**是在第一期 L5 数据湖之上，交付 **AgentIR Studio**（`PersonaIR.scope = role`），使业务人员**零代码**配置 ≥3 **岗位工作专家**（计划员 / 质检 / 设备员），实现 NL 问数、指标解读、离散阈值预警；智能层级为**战术层**，只管本岗、不跨模块统摄。

| 项 | 内容 |
|----|------|
| **里程碑** | **M-P1** |
| **工期** | **6 周**（R2-S0~S5） |
| **租户规模** | 0–20 租户（ARCH-001） |
| **数据域** | **离散** MetricIR；**禁止** TimeSeriesIR / 波形 |

**验收金句**：随机业务人员 **脱离开发人员**，完成 **1 个新指标 + 1 个岗位 Agent + 1 条预警**；Agent 答的 `oee` = MetricIR 预聚合 = DashboardIR 单卡，**误差 0**。

### 1.2.2 本期做

| # | 交付物 | IR / 组件 | 说明 |
|---|--------|-----------|------|
| P1 | **AgentIR** 持久化 + **AgentIR Studio** | PersonaIR + SkillIR + KnowledgeIR | 零代码配置岗位 Agent |
| P2 | **SkillIR** 挂载 **data-mcp + report-mcp** | 问数 + 出图 | MCP 工具挂载 |
| P3 | **AlertRuleIR Studio** + 编译为运行时 Job | Hangfire · 引用 `MetricIR.code` | 离散阈值预警 |
| P4 | NL→MQL→图表 **端到端** | 规则 80% + 主模型（裁定8） | 问数完整链路 |
| P5 | ≥3 **岗位** Agent 由**业务人员**配置 | 计划员 · 质量 · 设备 | 岗位模板 |
| P6 | **Agent Widget** 编译挂载 | 既有 MES 菜单 / 工作台槽位 | 嵌入 MES |
| P7 | 早报错峰预计算 + Sentinel 租户 QPS | 08:00 峰值可控 | 性能优化 |

### 1.2.3 本期不做（明确排除）

| 排除项 | 归属 | 理由 |
|--------|------|------|
| `PersonaIR.scope = enterprise` 企业应用专家 | **37 号第三期** | 目标二仅岗位级 |
| semantic 整页驾驶舱 / 主动跨模块巡检 | **37 号第三期** | 需要 enterprise Agent |
| timeseries-mcp / OPC UA / InfluxDB | **38 号第四期** | 离散/时序双轨 |
| `ChiefOfStaffService` / `WorkbenchAgent` | **禁止** | 33 号约束三 |
| 手写 AI 助手 Vue 作为交付物 | **禁止** | 33 号约束三 |
| 独立 `JNPF.AgentRuntime` modularity | **禁止** | IR + CompileGateway |
| 4 级专用 NL 分类器微服务 | **禁止** | 裁定8：规则 + 主模型 |

### 1.2.4 与第一期的关系

```
第一期（M-G1）→ 第二期（M-P1）→ 第三期（M-P2）→ 第四期（M-P4）
```

| 第一期交付物 | 第二期复用方式 | 说明 |
|-------------|---------------|------|
| **MetricIR** | AgentIR 引用 MetricIR.code | allowedMetricCodes 白名单 |
| **data-mcp** | Agent 通过 SkillIR 调用 | MCP 协议复用 |
| **DataQueryGateway** | data-mcp 代理至 DQG | 查询链路复用 |
| **Qdrant** | KnowledgeIR 检索 | 知识索引复用 |
| **LLM Gateway** | Agent 推理调用 | LLM 网关复用 |
| **Hangfire** | AlertRuleIR Job 注册 | 任务调度复用 |
| **CompileGateway** | 新增 agent-widget / alert-job 编译目标 | 扩展而非新建 |

**依赖顺序**：第一期 M-G1 完成后方可启动第二期。

### 1.2.5 与第三期的关系

第二期交付岗位 Agent（`scope=role`），第三期在此基础上交付企业应用专家（`scope=enterprise`）：

| 能力 | 第二期（岗位） | 第三期（企业） |
|------|----------------|----------------|
| 问数范围 | `allowedMetricCodes` 白名单 | 跨模块离散联合 |
| 预警 | 本岗 MetricIR 阈值 | 全厂主动巡检 |
| 统摄 | ❌ | 调度各岗 Agent |
| 驾驶舱 | Widget | semantic 整页 |

# 第二章 · 业务背景与产品定位

## 2.1 行业现状与痛点

### 2.1.1 数据智能的第二层跃迁

第一期解决了**指标口径统一**的问题（MetricIR + MQL），但业务人员仍面临：

| 痛点 | 现状（第一期后） | 第二期解决 |
|------|-----------------|-----------|
| **问数靠打字** | 业务人员需手动输入 MQL 查询 | NL 问数：说人话出图表 |
| **预警靠人盯** | 需人工定期检查指标值 | AlertRuleIR 自动预警推送 |
| **知识不沉淀** | 老师傅经验在脑子里 | KnowledgeIR 结构化沉淀 |
| **AI 是外挂** | AI 功能独立于业务系统 | Agent Widget 嵌入 MES |
| **配置靠开发** | 指标/预警配置需开发协助 | Studio 零代码配置 |

### 2.1.2 岗位工作专家的正确范式

2026 年制造业岗位智能的共识路线：**每个岗位一个懂行数的 AI 同事**。JNPF 运行态第二期走这条路，并叠加差异化：

1. **造车间非造车厢**——平台提供 AgentIR Studio，业务人员零代码配置岗位 Agent
2. **AI-off 零事故**——切断 LLM/Qdrant/MCP 后，AlertRuleIR Job 仍正常运行
3. **口径误差 0**——Agent 答的 oee = MetricIR 预聚合 = DashboardIR 单卡

## 2.2 产品定位

### 2.2.1 一句话定位

**JNPF 运行态第二期是 MES 的"岗位 AI 同事"——在 L5 数据湖之上，交付 AgentIR Studio，使业务人员零代码配置 ≥3 岗位工作专家，实现 NL 问数、指标解读、离散阈值预警。**

### 2.2.2 目标客户

| 客户类型 | 典型场景 | 价值主张 |
|---------|---------|----------|
| **制造企业生产部门** | 计划员需要快速了解 OEE、在制工单 | 岗位 Agent 随时问数 |
| **制造企业质量部门** | 质量工程师需要监控良率、待质检数 | 自动预警推送 |
| **制造企业设备部门** | 设备管理员需要监控故障、停机 | 阈值到了会推人 |

### 2.2.3 与友商对比

| 维度 | 传统 BI 对话 | 独立 AI 助手 | **JNPF 运行态第二期** |
|------|-------------|-------------|----------------------|
| 与 MES 集成 | 需定制对接 | 独立部署 | **原生嵌入** MES 菜单 |
| 指标口径 | 各算各的 | 需手动配置 | **MetricIR 统一** |
| 预警能力 | ❌ | 部分支持 | **AlertRuleIR Job** |

| 配置门槛 | 需开发 | 需开发 | **业务人员零代码** |

# 第三章 · 用户角色与场景

## 3.1 角色总览

运行态第二期涉及 **4 类角色**：

| 角色 | 中文名 | 主要操作 | 路由前缀 |
|------|--------|----------|----------|
| **生产计划员** | 生产计划员 | NL 问数、查看 OEE、在制工单 | Agent Widget |
| **质量工程师** | 质量工程师 | NL 问数、查看良率、待质检数 | Agent Widget |
| **设备管理员** | 设备管理员 | NL 问数、查看故障、停机时长 | Agent Widget |
| **业务配置员** | 业务配置员 | AgentIR Studio 配置 Agent、AlertRuleIR 配置预警 | `/studio/*` |

## 3.2 角色详细说明

### 3.2.1 生产计划员

- **典型用户**：生产经理、车间主任
- **技能门槛**：懂生产排程、懂 OEE 概念
- **核心场景**：
  - NL 问数：「一车间今天 OEE 多少？」→ Agent 返回数值 + 趋势图
  - 指标解读：「OEE 怎么算的？」→ Agent 返回口径公式
  - 预警接收：OEE < 0.85 → 站内信推送

### 3.2.2 质量工程师

- **典型用户**：质检主管、质量经理
- **技能门槛**：懂质检流程、懂良率概念
- **核心场景**：
  - NL 问数：「待质检有多少？」→ Agent 返回数值
  - 趋势分析：「本周良率趋势？」→ Agent 返回折线图
  - 预警接收：良率 < 0.95 → 站内信推送

### 3.2.3 设备管理员

- **典型用户**：设备主管、维修工程师
- **技能门槛**：懂设备台账、懂停机处理
- **核心场景**：
  - NL 问数：「设备故障几次？」→ Agent 返回数值
  - 口径解释：「平均修复时间怎么算？」→ Agent 返回公式
  - 预警接收：故障次数 > 5 → 站内信推送

### 3.2.4 业务配置员

- **典型用户**：业务经理、IT 管理员
- **技能门槛**：懂业务指标含义，不懂代码
- **核心场景**：
  - AgentIR Studio：零代码配置岗位 Agent（Persona + Skill + Knowledge）

# 第五章 · 核心业务流程

## 5.1 Agent 问数完整链路

```
用户问句（如「一车间今天 OEE 多少？」）
  ↓
Agent Widget
  ↓ 传递问句 + PersonaIR + SkillIR
AgentRuntimeOrchestrator.RunAsync
  ↓
1. 加载 PersonaIR.systemPrompt
  ↓
2. 加载 SkillIR[] → 动态注入 MCP 工具描述
  ↓
3. 加载 KnowledgeIR[] → Qdrant 检索相关知识
  ↓
4. 组装 Prompt（system + knowledge + user）
  ↓
5. 路由：规则引擎（80%）/ LLM（20%）
  ↓
6. 解析输出 → 调用 data-mcp.query_metrics
  ↓
7. DataQueryGateway 返回 data + total
  ↓
8. 调用 report-mcp.render_chart → ECharts option
  ↓
9. Agent Widget 渲染：数值 + 趋势图 + 文字解读
```

## 5.2 预警触发链路

```
AlertRuleIR Job 定时执行（cron 调度）
  ↓
查询 MetricIR.code 预聚合值
  ↓
条件检查（如 oee < 0.85）
  ↓ 触发
写入 BASE_ALERT_FIRE_LOG
  ↓
推送通知（站内信 / 邮件 / webhook）
  ↓
接收人收到预警
```

## 5.3 Agent 配置链路

```
业务配置员 → AgentIR Studio
  ↓
配置 PersonaIR（scope/roleCode/systemPrompt/allowedMetricCodes）
  ↓
配置 SkillIR（data-mcp + report-mcp 工具选择）
  ↓
配置 KnowledgeIR（知识节点选择）
  ↓
仿真预览（模拟问答测试）
  ↓
发布（草稿→已发布）
  ↓
CompileGateway 编译为 agent-widget
  ↓
挂载到 MES 菜单/工作台
```

## 5.4 预警配置链路

```
业务配置员 → AlertRuleIR Studio
  ↓
配置 metricCode（从 MetricIR 列表选择）
  ↓
配置 condition（op + value + window）
  ↓
配置 schedule（cron 表达式）
  ↓
配置 channels + recipients
  ↓
发布（草稿→已发布）
  ↓
CompileGateway 编译为 alert-job
  ↓
Hangfire Job 注册成功
```

## 5.5 NL 四级降级路径

```
正常:   NL → 规则模板 → LLM(可选) → MQL → DataQueryGateway → 预聚合
降级一: NL → 规则模板 → MQL → SQL（LLM 不可用）
降级二: NL → MetricIR 全量元数据注入 → LLM（Qdrant 不可用）
降级三: MQL → 分析库只读副本（主分析库过载）
```
