### B-02：stale 状态无法从 stage3/4/5 进入，且只能回到 stage1

**怎么改**：全阶段覆盖 stale + 双向恢复。

具体：
- 每个阶段定义超时：
  - stage1/stage2：7 天 → stale
  - stage3：3 天 → stale（已有）
  - stage4：7 天 → stale（沙箱部署后用户不验收）
  - stage5：14 天 → stale（交付后用户不下载/不部署）
- stale 恢复路径：
  - `stale --> stageN`：回到进入 stale 前的阶段，不是强制回 stage1
  - 新增 `stale --> abandoned`：30 天无响应自动终止（或用户主动放弃）

**谁来改**：首席架构师（文档）+ 后端工程师（PipelineEngineService 状态机扩展）
**什么时候改**：P0，文档今天修，代码本周内修（需要新增 StaleMonitorService 定时任务，见 I-13）

### I-01：blocked 状态缺少"放弃"路径（abandoned 终止态）

**怎么改**：增加 `abandoned` 终止态。

具体：
- 状态图新增：`blocked --> abandoned: 用户主动放弃`
- `abandoned` 为终态，不可恢复，保留数据用于审计
- UI 上在 blocked 状态的流水线卡片增加"放弃"按钮（二次确认弹窗）

**谁来改**：前端工程师（UI）+ 后端工程师（状态机 + 权限校验：只有创建者或管理员可放弃）
**什么时候改**：P1，可以延后到阶段五并行。但 blocked 状态的 UI 需要预留按钮位置，今天定接口。

### I-02：stage2→stage3 开发者否决后流程未定义

**怎么改**：定义"否决 → 修改 → 重审"闭环。

具体：
- 开发者点击"否决" → 必须填写否决原因（必填）→ 系统通知业务专家
- 业务专家修改需求/架构 → 重新提交 → 开发者收到通知 → 可再次评审
- 最多 3 轮否决，第 3 轮自动升级到管理员仲裁
- 状态流转：`stage2 --> stage2: 开发者否决 → 修改后重审`（自环，不是回退）

**谁来改**：首席架构师（流程定义）+ 后端工程师（消息通知 + 计数器）+ 前端工程师（评审 UI）
**什么时候改**：P1，阶段五并行。stage2→3 的开发者评审是"可选"功能，不影响核心闭环。

### I-03：stage4→stage5 审批标准未定义

**怎么改**：定义量化阈值。

具体：
- 沙箱健康检查通过（HTTP 200 + /health 返回 `{"status":"ok"}`）
- 自动化测试通过率 ≥ 90%（如果有测试）
- 编译 0 error（已有）
- 管理员/创始人审批时看到：测试报告摘要 + 沙箱 URL + 代码 diff

**谁来改**：后端工程师（SandboxDeploymentService 健康检查 + 测试报告生成）
**什么时候改**：P1，阶段五并行。stage4→5 的审批门禁可以先做"人工判断"，阈值后补。

### I-05：blocked 通知未包含触发操作的业务专家本人

### I-06：AI 顾问对话模式流程缺失

**怎么改**：新增 §4.9 对话模式状态机，明确与流水线的衔接。

具体：
- 对话模式是"辅助"不是"替代"流水线
- 用户在 AiChatPanel.vue 的对话不产生流水线记录，只产生 `draft_ir` 本地存储
- 用户可以选择"将对话结果提交到流水线" → 创建新流水线，stage1 预填充对话结果
- 对话模式无状态机，只有会话上下文（max 10 轮），超轮后提示"是否生成正式需求"

**谁来改**：首席架构师（§4.9 新增）+ 前端工程师（AiChatPanel.vue）+ 后端工程师（会话上下文 API）
**什么时候改**：P1，阶段五并行。对话模式是开发者工具，不影响业务专家的核心闭环。
