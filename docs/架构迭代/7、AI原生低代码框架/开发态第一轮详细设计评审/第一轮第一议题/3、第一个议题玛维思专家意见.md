## 我的补充预案（议题 1 · 8 项）

### B-01（stage3→stage4 确认矛盾）
KIMI 的方案 OK。我补接口层：
- **怎么改**：不要给每个阶段写不同的 confirm 接口，**复用同一接口** `POST /api/pipeline/{id}/stages/{stageName}/confirm`，请求体只一个 `{ "decision": "approve|reject", "reason": "..." }`，stageName 作为路径参数。这样 B-01、I-02、I-05 的"确认"都走同一个端点，文档干净，测试也好写。
- **谁来改**：后端工程师统一实现，前端按 stageName 路由
- **什么时候改**：P0，今天定接口签名（避免后面反复改）

### B-02（stale 全阶段覆盖）
KIMI 方向对。我**强烈主张把 I-13（我提的 stale 触发数据流）并入 B-02 一起改**——否则 stale 状态是个幽灵。
- **怎么改**：
  - 新增 `StaleMonitorService`（Hangfire 定时任务，每小时扫一次 `BASE_AI_PIPELINE`，按 `F_MODIFY_TIME + F_CURRENT_STAGE` 判定）
  - 触发后写 `BASE_AI_PIPELINE_MESSAGE`（system 角色）+ SignalR 推送给创建者 + 租户管理员
  - 新增表字段 `F_STALE_FROM_STAGE`（记录从哪个阶段进入 stale，用于 resume 时自动回填 targetStage）
  - 30 天无响应 → 自动 abandoned
- **接口补**：GET `/api/pipeline/stale`（管理员视图）+ POST `/api/pipeline/{id}/resume`（targetStage 由后端从 `F_STALE_FROM_STAGE` 自动填，不让用户瞎选）
- **谁来改**：首席架构师（流程图 + DDL）+ 后端工程师（StaleMonitorService + Hangfire 注册 + 接口）
- **什么时候改**：P0，**必须跟 B-02 同步出方案**，文档今天定，代码本周

### I-01（blocked → abandoned）
KIMI 的"abandoned 终止态"方向对。我补数据层：
- **怎么改**：`BASE_AI_PIPELINE` 加 3 列：`F_ABANDONED_AT`、`F_ABANDONED_BY`、`F_ABANDON_REASON`；`BASE_IR_VERSION` 在 abandoned 时全部转 `archived` 状态（不删，只读）
- **接口**：POST `/api/pipeline/{id}/abandon`，body `{ "reason": "..." }`，权限校验：仅创建者或租户管理员（**不是平台管理员**，除非创始人）
- **谁来改**：后端工程师（DDL + 状态机 + 权限）
- **什么时候改**：P1，但接口契约**今天定**（影响 §5 完整性）

### I-02（stage2→stage3 开发者否决）
KIMI 的"3 轮升级"机制 OK。我补表结构：
- **怎么改**：`BASE_AI_PIPELINE_MESSAGE` 加 3 列：`F_REVIEW_DECISION`（agree/reject）、`F_REVIEW_REASON`、`F_REVIEW_ROUND`；同时 `BASE_AI_PIPELINE` 加 `F_REJECT_COUNT`（流水线级累计）
- **接口**：复用 B-01 的通用 confirm 接口，加 `decision: "reject"` 即可，**不需要新接口**
- **谁来改**：首席架构师（流程定义）+ 后端工程师（DDL + 通知 + 计数器）
- **什么时候改**：P1，阶段五并行。文档今天定。

### I-03（stage4→stage5 审批标准）
KIMI 的量化阈值方向对。我**强烈建议可配置化**：
- **怎么改**：不要硬编码 90%。`BASE_AI_PIPELINE` 加 `F_APPROVAL_RULES JSON`（默认 `{ "minPassRate": 0.9, "requiredHealthCheck": true, "compileZeroError": true }`），租户级可覆盖。这样后面调阈值不动代码
- **接口补**：GET `/api/pipeline/{id}/approval-summary`，返回 `{ "thresholds": {...}, "actual": {...}, "passed": true|false }`
- **谁来改**：后端工程师（DDL + 配置接口）+ 前端工程师（审批页展示阈值 vs 实际）
- **什么时候改**：P1，阶段五并行

### I-04（增量修改盲盒确认）
KIMI 的 preview-rollback 方向对。我补响应字段契约：
- **怎么改**：响应必须包含三个关键字段，否则预览就是糊弄：
  1. `affectedNodes`: 影响节点详情列表（含节点 ID + 类型 + 改动描述）
  2. `affectedScope`: 影响范围标签数组（如 `["ModuleDefinition", "APIEndpoint"]`）
  3. `estimatedDurationSeconds`: 预计耗时（秒）
  4. `warnings`: 风险提示数组（如 `["将清除沙箱测试数据"]`）
- **谁来改**：后端工程师（依赖图计算 + 响应 schema）+ 前端工程师（预览 UI 卡片）
- **什么时候改**：P1，阶段五并行。**接口契约今天必须定**，不然前端 PipelineManager.vue 起不来
