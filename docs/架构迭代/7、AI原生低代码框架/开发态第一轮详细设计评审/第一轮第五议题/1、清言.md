```
修正前（错误）：
  6个Agent全部并行启动 → DocumentMerger合并
修正后（正确）：

    ApiDesignAgent   ──┘

**③ 消息流修正**
| 原图消息流（错误）               | 修正后消息流                                                 |
| -------------------------------- | ------------------------------------------------------------ |
| Orchestrator直接发指令给6个Agent | Orchestrator → 批次1 → `IntermediateCheck` → 批次2 → Merger  |

| **④ 时序图关键时间点标注**       |                                                              |
```
T0   Orchestrator.DispatchBatch1()

T2   IntermediateCheck() —— 校验批次1输出

     校验失败 → 重试失败Agent（最多2次）→ 仍失败 → blocked
T4   批次2全部完成（预计 20-40s）
T5   DocumentMerger.Merge()

## 🔴 B-11：图7-7降级链与实现不一致

**① 降级链修正**
```

**② 网关名称修正**
| 原图名称（错误）                       | 修正后名称                                                |

| **③ 降级触发条件定义（当前文档缺失）** |                                                           |
| 触发条件                               | 降级动作                                                  |
| ---------                              | ---------                                                 |

ALTER TABLE BASE_AI_CALL_LOG ADD F_ORIGINAL_MODEL NVARCHAR(50);  -- 原始请求模型
ALTER TABLE BASE_AI_CALL_LOG ADD F_ACTUAL_MODEL NVARCHAR(50);    -- 实际执行模型
ALTER TABLE BASE_AI_CALL_LOG ADD F_FALLBACK_REASON NVARCHAR(200); -- 降级原因
```
**谁来改**：首席架构师（§7图7-7重绘）+ 后端工程师（`LlmGatewayService`降级逻辑 + DDL）

## 🟡 I-14：阶段2→3门禁要求业务专家看ER图
**优先级：P1（重要）——影响业务专家的核心体验**
### 怎么改
**核心问题**：业务专家不是技术人员，看ER图、API定义等技术产物认知负担过高。但开发者又需要确认技术细节。
**解决方案：拆分为两步确认，两种视图**
**① 双视图设计**
| 视图               | 受众     | 内容                                                  | 确认动作           |
| ------------------ | -------- | ----------------------------------------------------- | ------------------ |
| **业务语言版**     | 业务专家 | 需求摘要 + 业务流程图（BPMN） + 功能清单 + 页面线框图 | 确认"业务语义正确" |
| **技术语言版**     | 开发者   | ER图 + API定义 + 数据模型 + 组件树                    | 确认"技术实现可行" |
| **② 两步确认流程** |          |                                                       |                    |
```
Stage2完成 → 生成双视图产物：
Step 1：业务专家确认（门禁1）
  展示：业务语言版
  问题："这些功能是否符合您的需求？"
  操作：approve / reject（需填原因）
  通过条件：业务专家 approve
Step 2：开发者确认（门禁2）  
  展示：技术语言版
  问题："技术架构是否可行？有无遗漏？"
  操作：approve / reject（需填原因，复用议题1通用confirm接口）
  通过条件：开发者 approve
  否决处理：3轮升级机制（议题1 I-02已裁决）
两个门禁都通过 → 进入Stage3
```
**③ 双视图产物映射（与议题2 B-07 NodeType对齐）**
| 业务语言版产物           | 来源Agent             | 技术语言版产物    | 来源Agent             |
| ------------------------ | --------------------- | ----------------- | --------------------- |
| 功能清单（表格）         | FunctionalModuleAgent | 模块依赖图        | FunctionalModuleAgent |
| 业务流程图（BPMN）       | BusinessProcessAgent  | API序列图         | ApiDesignAgent        |
| 页面线框图               | UIDesignAgent         | 组件树 + 页面布局 | UIDesignAgent         |
| 数据实体列表（业务名）   | DatabaseAgent         | ER图 + DDL        | DatabaseAgent         |
| 角色权限矩阵（业务描述） | PermissionAgent       | 权限配置JSON      | PermissionAgent       |
| **④ 接口契约补充**       |                       |                   |                       |
```yaml
端点: GET /api/pipeline/{id}/artifacts/{stage}?view=business|technical
权限: 
  - view=business: 业务专家可访问
  - view=technical: 开发者/管理员可访问
鉴权: JWT + 角色权限
响应:
  {
    "code": 200,
    "data": {
      "view": "business",
      "stage": "architecture",
      "documents": [
        { "type": "function_list", "format": "table", "url": "..." },
        { "type": "bpmn", "format": "svg", "url": "..." },
        { "type": "wireframe", "format": "svg", "url": "..." }
      ]
    }
  }
```
**谁来改**：首席架构师（§4.1门禁流程修正）+ 前端工程师（双视图渲染 + 两步确认UI）+ 后端工程师（视图过滤逻辑）
**什么时候改**：P1，阶段五并行。但**双视图产物映射表今天定**（影响Agent输出格式）
