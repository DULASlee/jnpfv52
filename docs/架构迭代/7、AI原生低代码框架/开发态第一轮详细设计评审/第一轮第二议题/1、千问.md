### 🔴 B-07：视图注册表与后端 6 SubAgent 不匹配

- **优先级：P0（阻断）**
- **怎么改**：修正 `AgentViewRegistry`（视图注册表），使其与后端实际的 6 个 SubAgent（Business, Domain, API, Database, UI, Test）一一对应。删除文档中已废弃的 Agent 名称，同步更新交互流程图。
- **谁来改**：首席架构师（修正文档 §3.2.5b），后端工程师（核对 `SubAgentFactory` 实现）。
- **什么时候改**：P0，会后立即修正，2小时内完成文档同步。

### 🔴 B-08：智能体依赖关系未精确定义输入输出

- **优先级：P0（阻断）**
- **怎么改**：在 §3.2.5a 中明确定义每个 Agent 的输入输出契约（Schema）。特别是 Batch 2（Code Generation）必须明确依赖 Batch 1（IR Generation）的 `IR_JSON` 和 `Schema_Version`，并增加校验点。
- **谁来改**：首席架构师（定义契约 Schema），后端工程师（实现参数校验）。
- **什么时候改**：P0，今天必须定稿，否则下游 Agent 无法编码。

### 🔴 B-09：DocumentMerger 合并后无二次校验

- **优先级：P0（阻断）**
- **怎么改**：在 `DocumentMerger` 服务合并 IR 后，强制插入一个“校验链”拦截器。流程为：`cleanSchema`（清洗） → `validateIR`（IR 结构校验） → `vue-tsc`（前端类型检查）。任一环节失败，中断流水线并报错。
- **谁来改**：后端工程师（实现校验链逻辑）。
- **什么时候改**：P0，今天修，代码明天必须提测。

### 🟡 I-07：批次 2 在批次 1 部分失败时的降级机制未定义

- **优先级：P1（重要）**
- **怎么改**：定义“部分成功”降级策略。例如：如果 Database Agent 失败，但 API Agent 成功，系统应允许开发者下载已生成的 API 代码，而不是全盘重试。在状态机中增加 `partial_success` 临时状态（仅用于展示）。
- **谁来改**：首席架构师（定义策略），后端工程师（实现分支逻辑）。
- **什么时候改**：P1，阶段五并行开发。

### 🟡 I-08：知识注入 AOP 模式存在 Prompt 污染风险

- **优先级：P1（重要）**
- **怎么改**：在知识注入 AOP 切面中，增加 `EABCompliancePrecheck`（EAB 合规预检）。在注入知识片段前，检查该片段是否包含与 EAB（企业架构基线）冲突的关键词或规则。冲突则拒绝注入并告警。
- **谁来改**：后端工程师（实现预检逻辑）。
- **什么时候改**：P1，阶段五并行。但预检规则库今天先定个初版。
