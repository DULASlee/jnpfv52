### B-08：输入输出契约定义

**微调点**：
- 批次2的依赖规则采用清言方案（批次1任一Agent失败 → 批次2全部跳过），但增加例外：
  - **BusinessProcessAgent失败时，允许批次2启动**（标记 `softDependencyWarning`），其他5个Agent失败则直接阻断。

**执行细则**：

1. **契约Schema必须包含以下4字段**（玛维思补充）：
   - 输入：JSON Schema + 数据源 + 上游依赖Agent列表
   - 输出：JSON Schema + 落点表 + 下游消费者
   - 校验点：`cleanSchema` / `validateIR` / `vue-tsc` 三选哪些
   - 失败码枚举：`schema_violation` / `version_mismatch` / `empty_output`

2. **全局版本常量**：
   - 新增 `IR_SCHEMA_VERSION`（放在 `core/ir/ir-version.ts`），所有Agent启动时校验版本一致性

3. **中间校验**：
   - 批次1完成后、批次2启动前，强制执行中间校验：验证 `modules`、`tables`、`processes` 不为空且schema合法
   - 失败 → 阻断批次2并返回 `validation_failure`

4. **6 SubAgent输入输出Schema（强制锁定）**：

**批次1（并行，无前置依赖）**
- **FunctionalModuleAgent**：`Input: { requirement, domain, eab }` → `Output: { modules, moduleRelations }`
- **BusinessProcessAgent**：`Input: { requirement, domain, modules }` → `Output: { processes, processModuleMapping }`
- **DatabaseAgent**：`Input: { requirement, domain, modules }` → `Output: { tables, relations, dataSources }`

**批次2（强制依赖批次1，并行）**
- **UIDesignAgent**：`Input: { modules, tables, processes }` → `Output: { pages, components }`
- **PermissionAgent**：`Input: { modules, tables, processes }` → `Output: { roles, permissionMatrix }`
- **ApiDesignAgent**：`Input: { modules, tables, processes }` → `Output: { endpoints, dataContracts }`

**责任人**：首席架构师（定Schema）+ 后端（实现校验逻辑 + 依赖注入）
**截止时间**：Schema定义今天18:00前锁定，校验代码明天提测。

### B-09：DocumentMerger二次校验

**微调点**：
- `vue-tsc` 失败**不进review态，而是进入blocked态**（与议题1决议严格对齐）。
- 理由：review是人工介入态（如I-02否决），类型错误属于系统级阻断，需走议题1定义的 `blocked → stale → abandoned` 流程。

**执行细则**：

1. **三级校验分级处理**（完全采用清言B-09-R1~R3，仅修正vue-tsc失败处理）：

| 校验环节        | 失败性质                                    | 处理策略                | 重试次数        |
| --------------- | ------------------------------------------- | ----------------------- | --------------- |
| `cleanSchema()` | 清洗问题（多余字段、格式错误）              | 自动修复后重试          | 3次（指数退避） |
| `validateIR()`  | 结构错误（必填字段缺失、引用断裂）          | 回退到指定Agent重新生成 | 2次             |
| `vue-tsc`       | 类型错误（组件引用不存在、Props类型不匹配） | **直接进入blocked态**   | 0次             |

2. **校验链执行顺序**：`cleanSchema → validateIR → vue-tsc`，不可跳过、不可调序

3. **失败记录**：
   - 每步失败写入 `BASE_AI_PIPELINE_MESSAGE`（`F_ROLE='system'`），内容含 `{type:'validation_failure', step, error, agent}`
   - 触发议题1的熔断机制（连续3次失败 → blocked）

4. **vue-tsc失败时，IR版本快照仍需保存**（标记 `status: invalid`），供开发者手动排查

**责任人**：后端工程师（校验链编排 + 错误定位 + 熔断集成）
**截止时间**：校验逻辑今天定稿，代码明天必须提测。
