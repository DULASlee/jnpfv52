### B-06（SSE 事件 Schema 缺失）
清言说缺，前端起不来。我提议**完整事件类型枚举**：

```typescript
// src/types/pipeline-sse.ts
export type PipelineSSEEventType =
  | 'stage_changed'      // 阶段切换（含 stage from/to）
  | 'phase_started'      // 阶段开始
  | 'phase_progress'     // 进度更新（含 percent）
  | 'agent_thought'      // Agent 思考过程（含 agent, thought）
  | 'agent_warning'      // Agent 警告（含 warning）
  | 'checkpoint'         // 检查点（含 checkpoint_id）
  | 'timeout_alert'      // 超时告警（含 soft/hard）
  | 'retrying'           // 重试中（含 attempt, maxAttempts）
  | 'blocked'            // 熔断（含 reason, failureCount）
  | 'failed'             // 失败（含 error）
  | 'completed'          // 完成（含 artifacts）
  | 'abandoned'          // 已放弃（含 reason）
  | 'ping';              // 心跳（30s 一次）

export interface PipelineSSEEvent {
  type: PipelineSSEEventType;
  timestamp: string;        // ISO 8601
  pipelineId: string;
  stage: string;
  data: Record<string, any>;
  requestId: string;        // 幂等去重
}

export interface PipelineSSEConnection {
  url: string;              // GET /api/pipeline/{id}/events
  reconnectStrategy: {
    maxAttempts: number;    // 默认 5
    initialDelayMs: number; // 默认 1000
    backoffMultiplier: number; // 默认 2
  };
  resumeFromEventId?: string; // 断线重连续传锚点
}
```

**关键设计**：
- `requestId` 字段做幂等去重（前端渲染时去重）
- `ping` 30s 一次心跳（防止代理超时断连）
- `resumeFromEventId` 支持断线重连续传（必填项，否则前端掉线就丢消息）

## 我主张的"今天必须定"的 3 个协调原则

会前请清言把这 3 条作为接口设计的硬约束，跟我议题 1 锁定的 6 个接口对一遍：

### 原则 1：**禁止重复端点**
