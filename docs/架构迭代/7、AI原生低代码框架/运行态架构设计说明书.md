# 第一章 · 文档概述

## 1.1 编写目的

本说明书是 JNPF 运行态智能层在**架构层面**的四期整体单一真源。它承接《33 号白皮书》的六大约束 + 十二大裁定，为各期详细设计提供架构级决策依据。

**与 33 号白皮书的关系**：
- 33 号白皮书 = **宪法**（靶心、目标、约束、裁定）
- 本说明书 = **架构设计**（为什么这么做、边界在哪）
- 各期详细设计 = **工程实现**（怎么做）

**与各期施工计划的关系**：
- 35 号（第一期）· 36 号（第二期）· 37 号（第三期）· 38 号（第四期）= **施工排期**
- 本说明书 = **架构约束**（各期施工必须遵守）

## 1.2 系统范围

**架构层范围**：
- 运行态四期整体架构框架
- IR 体系架构（MetricIR / AgentIR / AlertRuleIR / TimeSeriesIR）
- CompileGateway 统一编译架构
- MCP 工具架构（data-mcp / report-mcp / workflow-mcp / timeseries-mcp）
- 多租户隔离架构
- 数据湖分层架构（L1-L5 + 时序轨）
- LLM 路由与降级架构
- 可观测性架构

**架构层非范围**：
- 各期 Sprint 排期、DDL、代码路径（施工计划）
- 单个接口的实现细节、单个表的字段定义（详细设计说明书）
- 部署运维的具体步骤、Dockerfile（部署与运维手册）

| 约束 | 内容 | 架构含义 |
|------|------|----------|
| **约束一 · JNPF 增量生存** | AI 挂时 VisualDev/流程/权限 100% 可用 | 所有 Job 独立于 LLM；AI-off 时 CRUD/流程/Job 零 Exception |
| **约束二 · 运行态红线** | 目标定义仅 33 号第二部分 §0.4~0.7 | 各期交付物严格按施工计划 |

| **约束六 · AI-off 零事故** | 切断 LLM/Qdrant/MCP 后零 Exception | 降级切换延迟<1s；月度断电演练≥1 次 |

## 3.2 IR 体系架构

### ARC-RT-7-001 IR 单一真源

**决策**：所有 IR 的 JSON Schema 是编译的唯一输入，IR 定义必须集中管理。

**支撑**：
- 33 号约束五（IR 互通）
- 开发态 ARC-3-001（types.ts 唯一）

**架构含义**：
- MetricIR / AgentIR / AlertRuleIR / TimeSeriesIR 各有独立 JSON Schema
- CompileGateway 基于 IR Schema 编译
- IR 变更必须经版本管理（裁定 9）

### ARC-RT-7-002 双轨同构

**决策**：AI 产出与手工产出同构 IR，使用同一个 schema-cleaner + validator。

**支撑**：
- 33 号约束三（造车间非造车厢）
- 开发态 ARC-3-002

**架构含义**：
- Studio 手工配置 → IR JSON → CompileGateway
- LLM 辅助生成 → IR JSON → CompileGateway（第二期+）
- AI-off 时手工 Studio 仍可完整工作

### ARC-RT-7-003 离散/时序双轨

**决策**：MetricIR（离散）与 TimeSeriesIR（时序）独立，禁止波形写入 MetricIR 表。

**支撑**：
- 33 号 §0.7（第四期边界）
- 38 号施工计划

**架构含义**：
- 离散轨：SQL Server · MetricIR · data-mcp
- 时序轨：InfluxDB/ClickHouse · TimeSeriesIR · timeseries-mcp
- 企业应用专家通过 SkillIR 同时挂载两类 MCP

## 3.5 数据流架构

### 3.5.1 指标全链路数据流（目标一+）

```
业务人员 Studio
  ↓ 创建/修改 MetricIR
METRIC_IR_DEFINITION（草稿）
  ↓ 仿真
SimulateMetricAsync → L3 预聚合对比
  ↓ 发布
METRIC_IR_DEFINITION（已发布）
  ↓ Channel 推送
MetricIRVectorSyncWorker
  ↓ 向量化
Qdrant（向量 + BM25）
  ↓ 编译
CompileGateway → DashboardIR 单卡 / Agent Widget
```

### 3.5.2 Agent 问数数据流（目标二+）

```
用户问句
  ↓
NL 意图识别（规则 80% + LLM 20%）
  ↓ 路由标签：route:rule / route:llm
MQL JSON 生成
  ↓
```

## 10.1 性能架构

### 10.1.1 性能目标

| 指标 | 目标 | 归属期 |
|------|------|--------|
| MQL 查询 P95 | < 4s（LLM）/ < 500ms（规则） | 目标一 |
| 预聚合查询 P95 | < 200ms | 目标一 |
| CDC P0 同步延迟 | P95≤30s | 目标一 |
| Qdrant 检索 P95 | < 200ms | 目标一 |
| Agent 推理 P95 | < 3s | 目标二 |
| 企业专家协同 P95 | < 10s | 目标三 |
| 时序查询 P95 | < 500ms | 第四期 |
| 08:00 登录峰值 | 240 并发，P99≤500ms | 全期 |

### 10.1.2 性能架构决策

| 决策 | 内容 | 说明 |
|------|------|------|
| 预聚合优先 | 高频查询走 L3 | 目标一 |
| Sentinel 限流 | 全局 QPS 200，单租户 20 | 全期 |
| 07:50 预热 | DB 连接池 + LLM 连接 + Qdrant 缓存 | 全期 |
| LLM 熔断 | P95>5s → 降级规则引擎 | 目标二+ |
| Qdrant 熔断 | 不可用 → CONTAINS 降级 | 目标一+ |

## 10.2 安全架构

### 10.2.1 安全层级

| 层级 | 决策 | 来源 |
|------|------|------|
| **应用层** | JWT 鉴权 + 路由级权限 | CLAUDE.md R3 |
| **数据层** | Schema 隔离 + ITenantFilter | 裁定 1 |
| **查询层** | MQL 白名单 + 禁止 LLM 直写 SQL | 铁律 |
| **AI 层** | PII 脱敏 + Prompt Injection 检测 | 裁定 12 |
| **审计层** | AI_* 日志 5 年保留 | 约束八 |

### 10.2.2 PII 脱敏架构

```
用户输入
  ↓ PII 扫描（正则 + NER）
  ↓ 命中 → 脱敏占位 [MASKED_PHONE]
  ↓ 写 AI_PII_MASK_LOG
  ↓ 送入 LLM
```

### 10.2.3 SQL 注入防护

```
MQL JSON
  ↓ 表名白名单检查
  ↓ 列名白名单检查
  ↓ 禁止 DELETE/UPDATE/DDL
  ↓ TOP 1000 硬附加
  ↓ 生成 SQL
```

## 10.3 可用性架构

### ARC-RT-10-001 AI-off 零事故

**决策**：切断 LLM/Qdrant/MCP 后，CRUD/流程/Job/预聚合/VisualDev 零 Exception。

**支撑**：
- 33 号约束六
- 需求 NFR-A-001

**架构含义**：

| 组件失效 | 降级行为 | 用户感知 |
|----------|----------|----------|
| LLM API 不可用 | 规则引擎兜底 | 返回有限查询结果集 |
| Qdrant 不可用 | CONTAINS 全文搜索降级 | 语义搜索变精确匹配 |
| P0 同步超时 | 自动转 P1 | 数据 5min 延迟 |
| data-mcp 不可用 | Agent 无法调用 | 岗位专家对话中断 |
| AI 全部关闭 | CRUD + 流程 + Job 正常 | 驾驶舱显示静态预聚合数据 |

**度量标准**：
1. Unhandled Exception 数 = 0
2. 月度断电演练≥1 次且通过
3. 降级切换延迟 < 1s
4. 降级期间 VisualDev/CRUD/流程 P95 < 原 SLA 120%

## 10.4 可观测性架构

### ARC-RT-10-002 可观测性基线

**决策**：所有 AI 推理链路必须具备分布式追踪、指标暴露、健康检查、审计日志。

**支撑**：
- 33 号约束八

**架构含义**：

| 维度 | 实现 | 说明 |
|------|------|------|
| **分布式追踪** | OpenTelemetry ActivitySource | TraceID 贯穿 IR→MCP→LLM→DB |
| **指标暴露** | Prometheus /metrics | QPS/P95/Token/租户成本 |
| **健康检查** | /health + /ready | 存活 + 就绪 |
| **审计日志** | AI_INFERENCE_LOG / AI_PII_MASK_LOG / AI_EVAL_LOG | 5 年保留 |

### Prometheus 指标

| 指标名 | 类型 | 标签 | 说明 |
|--------|------|------|------|
| `ai_query_total` | Counter | route, tenant_id, status | 查询总数 |
| `ai_llm_latency_ms` | Histogram | model, tenant_id | LLM 延迟分布 |
| `ai_token_consumed` | Counter | model, tenant_id, direction | Token 消耗 |
| `cdc_sync延迟` | Gauge | table, priority | CDC 同步延迟 |
| `qdrant_search_latency_ms` | Histogram | tenant_id | Qdrant 检索延迟 |
| `agent推理延迟` | Histogram | agent_code, tenant_id | Agent 推理延迟 |
