# 第二章 · 部署架构总览

## 2.1 双系统部署

### 2.1.1 工作室（Baobab-Studio）部署形态

| 部署层级 | 工具 | 用途 |
|---------|------|------|
| **容器编排** | K8s（生产）+ Docker Compose（开发/测试） | 多副本调度 + 滚动更新 |
| **API 服务** | JNPF.API.Entry + JNPF.OA.API.Entry（已禁用） | .NET 8 API |
| **数据库** | SQL Server 2019+（共享实例 + per-tenant DB） | 单一 OLTP |
| **缓存** | Redis 6+ | CSRedis 客户端 |
| **消息队列** | RabbitMQ 3.8+ | 跨进程事件 |
| **前端 Web** | jnpf-web-vue3（PC / 大屏 / 移动）| Vue 3 + Ant Design Vue |

### 2.1.2 熔炉（Baobab-Foundry）部署形态

| 部署层级 | 工具 | 用途 |
|---------|------|------|
| **物理隔离** | 独立网络 + 无公网端口 | 创始人裁定 |
| **容器编排** | Docker（**沙箱**） | 不可变镜像 + 混沌注入 |
| **训练引擎** | Python asyncio / 轻量任务队列 | LLM 智能体循环 |
| **数据库** | SQL Server（独立实例 / per-tenant DB） | 因果回放池 + 知识图谱 |
| **签名通道** | HTTPS + 签名 zip | 创始人私钥签名 |

### 2.1.3 双系统通信

```
工作室 ──── HTTPS + 签名 zip ──── 熔炉
  │                                  │
  │ IrCorpus.zip (AES-256 + 公钥)    │
  │ ──────────────────────────────▶ │
  │                                  │
  │ KnowledgePatch_{v}.zip (私钥)   │
  │ ◀────────────────────────────── │
  │                                  │
```

## 2.2 部署形态选择

### 2.2.1 4 种部署形态

| 形态 | 适用场景 | 工具 | 复杂度 |
|------|---------|------|--------|
| **单机开发** | 个人开发 | Docker Compose | 低 |
| **测试环境** | CI / 手动测试 | CI Runner + Docker | 中 |
| **预生产** | 客户验收 / 压测 | K8s（小规模，1 副本） | 中 |
| **生产** | 客户真实使用 | K8s（多副本，跨可用区）| 高 |

### 2.2.2 形态决策矩阵

| 维度 | 单机开发 | 测试 | 预生产 | 生产 |
|------|---------|------|--------|------|
| K8s | ❌ | ❌ | ✅（1 副本）| ✅（多副本）|
| 跨可用区 | ❌ | ❌ | ❌ | ✅ |
| 真实数据 | ❌ | ❌ | ❌（脱敏）| ✅ |
| 监控完整度 | ❌ | ⚠️ 部分 | ⚠️ 部分 | ✅ 完整 |

## 2.3 关键部署决策

### DEC-2-001 共享 SQL Server per-tenant DB

**决策**：所有沙箱**共享一个 SQL Server 实例**，每个租户独立 DB。

**支撑**：ARC-7-001 / 风险 R1。

**部署含义**：
- 容器**不**包含 SQL Server 容器
- 沙箱销毁时 DB 保留 7 天
- 同时 ≤ 2 活跃沙箱（避免 OOM）

### DEC-2-002 熔炉物理隔离

**决策**：熔炉**物理隔离独立部署**，无公网端口。

**支撑**：ARC-7-002 / ADR-020 / AC-4。

**部署含义**：
- 通过 HTTPS + 签名 zip 与工作室通信
- 创始人私钥签名
- 不可删审计表

### DEC-2-003 多租户隔离 6 层

**决策**：L1 应用层 + L2 中间件层 + L3 ORM 层 + L4 数据库层 + L5 沙箱层 + L6 创始人层。

**支撑**：ARC-5-004 / ARC-7-001 / §9.3。

**部署含义**：
- 阶段六第 2 周 `MultiTenancy=true` 必须生效
- 越权测试 10 条用例进 CI

# 第四章 · 配置管理与密钥

## 4.1 配置分层

### 4.1.1 配置优先级

```
环境变量（最高）
  ↓
appsettings.{Environment}.json
  ↓
appsettings.json（最低）
```

### 4.1.2 配置内容矩阵

| 配置项 | 来源 | 注入方式 | 敏感度 |
|--------|------|----------|--------|
| **SQL Server 连接串** | 环境变量 | K8s Secret | ⚠️ 敏感 |
| **Redis 连接串** | 环境变量 | K8s Secret | ⚠️ 敏感 |
| **RabbitMQ 连接串** | 环境变量 | K8s Secret | ⚠️ 敏感 |
| **JWT 密钥** | 环境变量 | 密钥管理服务 | 🔴 极敏感 |
| **大模型 API Key** | 环境变量 | 密钥管理服务 | 🔴 极敏感 |
| **创始人 TOTP 密钥** | 环境变量 | 密钥管理服务 | 🔴 极敏感 |
| **租户 ID** | JWT 携带 | 自动 | 非敏感 |
| **多租户开关** | appsettings | 配置 | 非敏感 |

### 4.1.3 ⚠️ 配置不入仓（CLAUDE.md R + F-0）

**强制规则**：
- 所有连接串、API Key、JWT 密钥 **不入仓**
- 通过环境变量 + 密钥管理服务注入
- `.gitignore` 必须排除 `appsettings.*.local.json`
- `ConnectionStrings.json`（**已 gitignored**）

## 4.2 密钥管理

### 4.2.1 JWT 密钥（**不轮换**，用户偏好 UP-2）

| 维度 | 决策 |
|------|------|
| **存储** | 密钥管理服务（不轮换） |
| **注入** | 环境变量 `JWT_SIGNING_KEY` |
| **轮换** | **不轮换**（走密钥管理流程，创始人裁定） |
| **审计** | 任何密钥访问记录不可删审计 |

### 4.2.2 大模型 API Key（6 供应商）

| 供应商 | 环境变量 | 用途 |
|--------|---------|------|
| DeepSeek | `DEEPSEEK_API_KEY` | 主供应商 |
| 通义千问 | `TONGYI_API_KEY` | 备 1 |
| OpenAI | `OPENAI_API_KEY` | 备 2 |
| Ollama | `OLLAMA_API_BASE`（无需 Key）| 本地模型 |
| 智谱 | `ZHIPU_API_KEY` | 备 3 |
| 月之暗面 | `MOONSHOT_API_KEY` | 备 4 |

### 4.2.3 创始人 TOTP 密钥

| 维度 | 决策 |
|------|------|
| **存储** | 密钥管理服务 |
| **生成** | 创始人本人 Google Authenticator |

# 第八章 · 故障手册

## 8.1 故障响应流程

```
告警触发 → 自动分级（warning / critical）
  ↓
warning：邮件 + IM 群通知 → 运维工程师处理
  ↓
critical：电话 + 短信 + IM → 运维 + 架构师 + 创始人（必要时）
  ↓

  ↓
应急响应（按 Runbook 执行）
  ↓
恢复验证
  ↓
事后复盘（24 小时内）
```

## 8.2 10 类常见故障

### 故障 1：API 5xx 错误率突增

**症状**：API 5xx 错误率 > 1%

**可能原因**：
1. 数据库连接池耗尽
2. Redis / RabbitMQ 不可达
3. 大模型 API 全挂（无降级）
4. K8s 节点 OOM

**应急响应**：
1. 检查 K8s 节点状态
2. 检查数据库连接池：`SELECT * FROM sys.dm_exec_connections`
3. 检查 Redis / RabbitMQ 健康
4. 检查大模型降级链状态

**恢复流程**：
- K8s 节点 → 重启 / 扩容
- 数据库 → 重启连接池 + 检查慢查询
- 大模型 → 触发手动降级（见 §10 Runbook）

### 故障 2：数据库连接失败

**症状**：API 报 "数据库连接失败"

**可能原因**：
1. SQL Server 实例宕机
2. 网络分区
3. 连接串错误
4. 连接池耗尽

**应急响应**：
1. 检查 SQL Server 健康
2. 检查网络（`ping sqlserver`）
3. 检查连接串（环境变量）
4. 检查连接池配置

**恢复流程**：
- SQL Server 宕机 → 切换主从 → 故障转移
- 网络分区 → 等待恢复 / 切换网络
- 连接串错误 → 修正环境变量 → 重启 API

### 故障 3：AI 全供应商失败

**症状**：所有 6 个大模型供应商不可达

**可能原因**：
1. 网络问题（无法访问外网）
2. 供应商 API 故障（区域性）
3. API Key 全部失效

**应急响应**：
1. **自动**：FallbackLLMGateway 5 级降级链启动 → 切换到 Ollama（本地）
2. **自动**：Ollama 也不可用 → 进入"无 AI 专家模式"（IR 转 Schema 逃生舱）
3. **人工**：运维检查网络 + API Key

**恢复流程**：
- 网络恢复 → 自动恢复（无人工干预）
- API Key 失效 → 运维更新环境变量 → 重启 API

### 故障 4：沙箱创建失败

**症状**：沙箱创建失败率 > 30%

**可能原因**：
1. Docker 守护进程故障
2. SQL Server 连接失败（创建 DB）
3. 资源耗尽（CPU / 内存 / 磁盘）
4. SemaphoreSlim 死锁

**应急响应**：
1. 检查 Docker 健康
2. 检查 SQL Server 连接
3. 检查资源使用率
4. 强制清理过期沙箱（> 30s）

**恢复流程**：
- Docker 故障 → 重启 Docker → 清理容器
- 资源耗尽 → 扩容 + 清理
- 死锁 → 重启 SandboxScheduler

### 故障 5：JWT 鉴权失败

**症状**：用户登录后立即 401

**可能原因**：
1. JWT 密钥变更（**用户偏好不轮换**，不常见）
2. JwtHandler 中间件未启动
3. JWT 配置错误
4. 时间漂移（Token 过期）

**应急响应**：
1. 检查 JwtHandler 健康（`/api/health`）
2. 检查 JWT 配置（环境变量）
3. 检查系统时间（NTP 同步）
4. 检查 BASE_FOUNDER_AUTH_LOG（是否有密钥变更）

**恢复流程**：
- 中间件未启动 → 重启 API
- 配置错误 → 修正环境变量
- 时间漂移 → NTP 同步

### 故障 6：越权访问告警

**症状**：ALERT_LOG 中出现越权访问尝试

**可能原因**：
1. 客户端 bug（未携带 tenantId）
2. 越权测试用例被错误触发
3. 攻击尝试

**应急响应**：
1. 检查告警详情（F_USER_ID / F_TENANT_ID）
2. 判断是 bug 还是攻击
3. 必要时临时封禁用户
4. 通知创始人

**恢复流程**：
- Bug → 修复客户端 → 重新部署
- 攻击 → 拉黑 IP → 通知安全团队

### 故障 7：创始人 TOTP 锁定

**症状**：创始人无法登录创始人菜单

**可能原因**：
1. TOTP 设备丢失
2. TOTP 密钥错误
3. 错误次数超限（锁定 5 分钟）

**应急响应**：
1. **不通过电话或短信重置**（安全原则）
2. 创始人本人到场 + 备用 TOTP 设备
3. 必要时走密钥管理流程

**恢复流程**：
- 设备丢失 → 启用备用设备
- 密钥错误 → 重新生成 TOTP 密钥（密钥管理流程）
- 锁定 → 等待 5 分钟自动解锁

### 故障 8：知识补丁签名验证失败

**症状**：KnowledgePatchService 拒绝补丁

**可能原因**：
1. 创始人私钥错误（补丁生成端）
2. 公钥错误（补丁接收端）
3. 网络传输损坏

**应急响应**：
1. 检查创始人私钥完整性
2. 检查公钥配置
3. 检查网络（重新下载）
4. 必要时回滚到旧版知识图谱

**恢复流程**：
- 私钥错误 → 创始人重新签名
- 公钥错误 → 修正配置
- 传输损坏 → 重新传输

### 故障 9：熔炉断联

**症状**：工作室无法访问熔炉 API

**可能原因**：
1. 熔炉网络故障
2. 熔炉 API 故障
3. X-Founder-Token 失效

**应急响应**：
1. 检查熔炉健康（创始人菜单转发）
2. 检查 X-Founder-Token
3. 检查网络（HTTPS 连通性）

**恢复流程**：
- 熔炉故障 → 创始人通知熔炉运维
- Token 失效 → 重新 TOTP 验证
- 网络故障 → 等待恢复

### 故障 10：CDN / 前端加载失败

**症状**：用户报告页面加载失败

**可能原因**：
1. CDN 节点故障
2. 前端构建失败
3. 资源路径错误
4. 浏览器兼容问题

**应急响应**：
1. 检查 CDN 节点状态
2. 检查前端构建产物
3. 检查资源路径
4. 检查浏览器兼容性矩阵

**恢复流程**：
- CDN 故障 → 切换 CDN 节点
- 构建失败 → 回滚构建
- 路径错误 → 修正路径重新部署

## 8.3 应急升级流程

### 8.3.1 升级触发条件

| 条件 | 升级到 |
|------|--------|

| critical 告警 5 分钟未解决 | 创始人介入 |


# 第九章 · 创始人应急

## 9.1 创始人菜单应急操作

### 9.1.1 紧急禁用 AI

**场景**：AI 行为异常，需要立即关闭全平台 AI 调用

**操作**：
1. 创始人菜单 → 「系统级开关」
2. 切换 `AI_ENABLED = false`
3. 全平台 AI 调用立即停止
4. 走"无 AI 专家模式"（IR 转 Schema 逃生舱）
5. 操作记录 BASE_FOUNDER_AUTH_LOG

### 9.1.2 紧急禁用沙箱

**场景**：沙箱异常（资源耗尽 / 安全事件）

**操作**：
1. 创始人菜单 → 「沙箱控制」
2. 强制销毁所有活跃沙箱
3. 暂停沙箱调度器
4. 操作记录 BASE_FOUNDER_AUTH_LOG

### 9.1.3 紧急回滚知识图谱

**场景**：知识补丁有问题，需要回滚

**操作**：
1. 创始人菜单 → 「知识图谱审核」
2. 选择回滚版本（90 天内任意版本）
3. 执行回滚
4. 自动备份当前版本
5. 写入 BASE_FOUNDER_AUTH_LOG

## 9.2 知识补丁回滚

### 9.2.1 回滚决策树

```
知识补丁异常 → 评估影响范围
  ↓
影响 1 个租户 → 仅回滚该租户（临时标记知识为 deprecated）
  ↓
影响多个租户 → 全平台回滚
  ↓
影响创始人治理（熔炉侧）→ 暂停熔炉自博弈 + 全平台回滚
```

### 9.2.2 回滚操作

```sql
-- 1. 备份当前（回滚前的状态）
SELECT * INTO KNOWLEDGE_BACKUP_BEFORE_ROLLBACK_$(timestamp)
FROM BASE_KNOWLEDGE_NODE WHERE F_IS_DELETED = 0;

-- 2. 标记问题版本为 deprecated
UPDATE BASE_KNOWLEDGE_NODE
SET F_STATUS = 'deprecated'
WHERE F_VERSION = $(problem_version);

-- 3. 记录创始人操作
INSERT INTO BASE_FOUNDER_AUTH_LOG (...)
VALUES ('rollback_knowledge', @ProblemVersion, 'success', ...);
```

### 9.2.3 回滚后验证

- 健康检查（知识图谱 API）
- 业务功能测试（受影响租户）
- 监控告警（无异常）

## 9.3 熔炉断联应急

### 9.3.1 断联场景

| 场景 | 影响 | 应急 |
|------|------|------|
| 熔炉网络中断 | 无法推送 IrCorpus / 拉取 KnowledgePatch | 暂停自博弈 + 等待恢复 |
| 熔炉 API 故障 | 同上 | 通知熔炉运维 |
| 创始人 Token 失效 | 无法访问熔炉 | 重新 TOTP 验证 |

### 9.3.2 应急操作

- 工作室**不内嵌**训练引擎（ADR-020）
- 熔炉断联不影响工作室核心功能
- 仅影响：知识图谱更新、模型与 Prompt 配置推送

### 9.3.3 恢复流程

```
1. 熔炉恢复 → 创始人重新连接
2. 补发未发送的知识补丁（如有积压）
3. 验证知识图谱一致性
4. 写入 BASE_FOUNDER_AUTH_LOG
```

### 9.4.2 应急联系人

| 角色 | 联系方式 |
|------|----------|

| 运维 lead | 内部通讯录 |
| 架构师 | 内部通讯录 |
| 安全团队 | 内部通讯录 |
