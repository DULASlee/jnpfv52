## 新流程全景

```
用户提交需求（文档/图片/文字）
    │
    ▼
Stage 0：SA门控（材料合格性预检）
    │ 合格 ▼                              ✗ 不合格 → 具体反馈原因 → 用户补充
Stage 1：需求分析师（多轮对话，需求原子化）
    │
    ▼
Stage 2：SA九步分析（结构化需求分析，9步×7重校验）
    │ 输出《需求分析说明书》→ 用户预览/下载/确认
    ▼
Stage 3：架构设计（技术栈/部署架构/非功能性需求）
    │ 输出《系统架构设计说明书》→ 用户确认
    ▼
Stage 4：总体设计（子Agent并行 → 完整详细设计）
    │ 输出《系统总体设计说明书》→ 用户确认
    ▼
Stage 5：开发（代码生成）
    │
    ▼
Stage 6：编译部署 → 沙箱 + 源码下载
```

#### 1.1 提交需求

**路由**：`/studio/ai/submit-requirement`

**功能说明**：用户提交原始需求材料，经过SA门控 → 多轮对话 → SA九步 → 架构设计 → 总体设计 → 开发 → 部署，最终获得完整系统。

**关联功能模块**：

| 模块                                    | 说明                                                         | 所在阶段   |
| --------------------------------------- | ------------------------------------------------------------ | ---------- |
| **材料上传组件**                        | 支持文档附件（PDF/Word/最多10个）+ 图片附件（支持OCR解析为文字）+ 用户输入框文本输入 | Stage 0 前 |
| **文件解析服务**                        | 文档解析（PDF/Word → 纯文本）+ 图片OCR（图片 → 文字）+ 多文件合并为统一需求文本 | Stage 0 前 |
| **SA门控模块**                          | 调用LLM分析原始需求材料是否合格：能否提取出≥1个业务模块的业务事件、业务对象、数据、业务流程、实体关系、数据库表、UI元素；不合格时给出**具体缺失项反馈**（如"缺少业务流程描述""未识别到任何业务事件""未发现数据实体定义"），而非笼统的"不合格" | Stage 0    |
| **AI对话面板 (AIChatPanel)**            | SSE流式对话，支持多轮追问直到需求原子化；支持消息中嵌入IR预览、文档片段 | Stage 1    |
| **阶段进度条 (StageProgress)**          | 7阶段进度展示（门控→需求→SA分析→架构→设计→开发→部署），当前阶段高亮，已完成阶段可回看 | 全程       |
| **阶段确认对话框 (StageConfirmDialog)** | 每阶段完成后展示产出预览，用户选择"通过/需要修改/回退"       | Stage 2~5  |
| **SA步骤浏览器**                        | SA九步每步的产出数据可视化浏览（Context图、DFD、流程图、数据字典、PSPEC、判定表、ER图、状态机、UI原型），用户可逐步查看 | Stage 2    |
| **文档预览与下载**                      | 三份核心文档（需求分析说明书、架构设计说明书、总体设计说明书）的在线预览（Markdown渲染）+ PDF下载 | Stage 2~4  |
| **技术栈选择器**                        | 架构设计阶段，用户选择/确认技术栈（Java/C#/Go/Rust/Python）、部署形态（微服务/模块化单体）、是否需要外接数据接口等 | Stage 3    |

**关键组件清单**：
