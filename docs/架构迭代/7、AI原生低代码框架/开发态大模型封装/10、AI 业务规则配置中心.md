## 核心:判定表编辑器(DecisionTableEditor.tsx)

**这是整个前端最值钱的部分**——把"AI 生成的业务规则"变成"人类可编辑、可审、可学的界面"。

### 关键设计

1. **可视化表格布局**:
   - 条件作为列(可编辑阈值)
   - 规则作为行(可切换 ✓/✗)
   - 动作可下拉选择

2. **修改来源可视化**:
   - 🟢 **绿色单元格** = AI 生成,未修改
   - 🟡 **黄色单元格** = 人类已修改
   - 🔴 **红色** = Validator 失败

3. **Diff 预览**:
   - 保存前显示"哪几行哪几列"被改了
   - 防止误操作

4. **ChangeTracker 追踪**:
   - 每次修改进 buffer
   - 保存时批量提交
   - 失败可 discard

5. **DKEE 自动触发**:
   - 保存 = 自动通知后端 DKEE 学习
   - 无需人工干预

## DKEE 自动学习闭环

```
┌──────────────────────────────────────────────────────┐
│  前端:用户改判定表 → ChangeTracker.record()           │
└───────────────────┬──────────────────────────────────┘
                    ↓
┌──────────────────────────────────────────────────────┐
│  前端:用户点保存 → changeApi.record() + tableApi.update│
└───────────────────┬──────────────────────────────────┘
                    ↓
┌──────────────────────────────────────────────────────┐
│  后端:写 sa_decision_table + 写 change_log            │
└───────────────────┬──────────────────────────────────┘
                    ↓
┌──────────────────────────────────────────────────────┐
│  后端:DKEEFacade.extractAndScore(industry)            │
│  跨项目聚合 → 提炼 Pattern → kg_pattern               │
└───────────────────┬──────────────────────────────────┘
                    ↓
┌──────────────────────────────────────────────────────┐
│  下次跑 SA:KG Pattern 注入 LLM context                │
│  LLM 跑出更准的判定表                                  │
└──────────────────────────────────────────────────────┘
```
