## JNPF AI原生MES岗位专家：三期落地施工方案

### 第一期：数据中台/数据湖（4周）
> **目标**：让JNPF从一个“功能平台”变成一个“数据平台”，让AI有米下锅。**第4周结束时，客户MES里的所有数据（工单、设备、质检、人员）必须能以标准化的方式被查询和聚合。**

**核心任务：**

1.  **统一数据查询服务 (Data Query Service)**
    *   **做什么**：封装一个标准的`data-mcp` MCP Server，对外暴露统一的SQL查询和聚合接口。
    *   **为什么快**：不搞复杂的数仓建模，就用SqlSugar + SQL Server，把MES的核心表（工单、报工、质检、设备状态、人员）注册为可查询的“数据实体”。
    *   **交付物**：一个标准的`POST /api/data/query`接口，接收自然语言转成的查询条件，返回结构化数据。
    *   **客户感知**：第2周就能演示：“帮我查一下3号机今天的OEE”，AI通过这个服务返回真实数据，而不是写死回复。

2.  **元数据字典 (Metadata Dictionary)**
    *   **做什么**：建一个`BASE_META_ENTITY`和`BASE_META_FIELD`表，把“工单表叫WORK_ORDER，良品率字段是YIELD_RATE，关联设备表是EQUIPMENT”这些信息结构化存下来。
    *   **AI化**：这个字典直接注入到LLM的System Prompt里，让AI能听懂“良品率”这个业务术语，并自动映射到`YIELD_RATE`字段。
    *   **交付物**：一个元数据管理界面，业务专家可以在线补全字段的中文注释和业务含义。

3.  **轻量级数据湖 (One Big Table for AI)**
    *   **做什么**：建一张`MES_AI_WIDE_TABLE`，每天ETL一次，把核心业务数据打宽、合并。这是给AI用的“预计算食材”，避免每次查询都跨表关联。
    *   **为什么快**：用JNPF已有的定时任务引擎做ETL，零额外成本。
    *   **交付物**：一张宽表，包含工单、设备、人员、物料的核心字段，以及“是否超期”、“OEE是否异常”等派生标签。

**本期验收标准：** 用自然语言问“昨天哪个车间良品率最低”，AI能准确调用`data-mcp`，从数据湖或数据查询服务中查出结果，返回给前端。

### 第二期：AI化流程/表单/报表引擎（4周）
> **目标**：把JNPF现有的三大引擎（流程、表单、报表）都装上“AI神经”，让它们能听懂人话，能自动干活。**第8周结束时，客户必须能“一句话发起流程”、“一句话生成报表”、“一句话填单”。**

**核心任务：**

1.  **AI化流程引擎 (Workflow-MCP)**
    *   **做什么**：封装`workflow-mcp`，把“启动流程、查询待办、审批单据”变成AI可调用的工具。
    *   **场景实现**：用户说“帮我发起一个设备报修流程，3号机，漏油”，AI解析意图→调用`data-mcp`确认设备和用户身份→调用`workflow-mcp`启动报修单，并自动填上设备编号和报修人。
    *   **交付物**：一个能通过自然语言发起3个核心流程（报修、请料、质检）的演示。

2.  **AI化表单引擎 (Form-MCP)**
    *   **做什么**：封装`form-mcp`，支持“智能填单”。结合长期记忆，AI记住张总经常填的“车间”，下次自动预填。
    *   **场景实现**：生成排程表时，AI自动调出生产排程表单，把工单号、计划日期等字段填好，只让张总最后审核。
    *   **交付物**：一个“一键填充”的表单助手，覆盖排程、质检报告等高频表单。

3.  **AI化报表引擎 (Report-MCP)**
    *   **做什么**：封装`report-mcp`，实现清言设计中的“一句话报表”。
    *   **场景实现**：用户说“看下本周各线体产量趋势”，AI自动选择折线图，调用`data-mcp`取数，渲染为`DashboardIR`，并在工作台直接展示。
    *   **交付物**：基于现有大屏引擎，实现至少3种图表（趋势、对比、占比）的自然语言生成。

**本期验收标准：** 客户MES的用户，可以完全通过工作台的AI对话框，用自然语言完成“发起报修”、“查产量”、“填排程单”这三个端到端闭环。

### 第三期：岗位专家/总管家（4周）
> **目标**：基于前两期打好的数据和引擎地基，正式组装出“车间主任张总”的智慧总管。**第12周结束时，客户打开MES，看到的就不再是功能菜单，而是一个主动汇报、能听指令、能自动执行任务的AI驾驶舱。**

**核心任务：**

1.  **智慧总管装配器 (Agent Assembler)**
    *   **做什么**：利用我们之前设想的`AgentIR`概念，但不是开发复杂的编译器，而是**先用一个配置化界面**，快速拼装出张总的专属管家。
    *   **配置项**：选择“MES车间主任”人设 → 勾选“工作台汇总”、“报表生成”、“排程助手”等技能（就是前两期做好的MCP工具包） → 导入这个车间的业务规则（VIP订单优先、设备故障响应流程）。
    *   **交付物**：一个管理后台，可以像搭积木一样，给不同岗位生成不同的AI助手。

2.  **主动感知与推送引擎**
    *   **做什么**：一个后台`Scheduler`，每天早上8点自动运行：调用`data-mcp`采集异常数据 → 调用工作台Agent生成简报 → 推送到张总工作台首页。
    *   **AI化**：简报不是死板的列表，而是“张总，早上好。今天重点关注：3号机昨晚OEE降至85%，已低于阈值；VIP工单#PO-2401即将超期，建议优先排产。”
    *   **交付物**：一个可配置的“AI早报”卡片，嵌入MES工作台首页。

3.  **人机协同闭环**
    *   **做什么**：给所有AI生成的结果（排程草稿、报表、审批意见）加上“一键采纳”、“一键驳回”、“修改后执行”的按钮。所有采纳/驳回行为，自动存入`DKEE`，作为领域知识进化的养料。
    *   **交付物**：在工作台对话流中，AI的输出不再是纯文本，而是包含可交互按钮的富媒体卡片。

**本期验收标准：** 张总早上8点登录MES，AI工作台自动弹出当日工作简报，他看完后说“按VIP优先，重排下周计划”，AI自动生成新排程并推送给他确认，他点“采纳”后，新工单自动下发到各班组长的JNPF移动端。
