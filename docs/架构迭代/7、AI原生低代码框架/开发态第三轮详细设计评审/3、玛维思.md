## 二、§9.3.1 多租户 6 层隔离机制 🟡 3 个漏洞

### ✅ 已有 6 层

L1 JWT / L2 TenantMiddleware / L3 ITenantFilter / L4 per-tenant DB / L5 Docker 隔离 / L6 FounderGuard

### 🟡 漏洞

**V-1. 缺 L7：API 网关层**
没有 API Gateway 限流、IP 黑名单、WAF。建议补：
- 限流：每租户 QPS 上限（如 100 QPS）
- IP 黑名单：连续失败 10 次拉黑 5 分钟
- WAF：SQL 注入、XXE 攻击拦截

**V-2. L5 沙箱层不完整**
"Docker 容器物理隔离"只说了容器间，没说**网络隔离**。建议明确：
- 沙箱用独立 Docker network（`docker network create --internal`）
- 沙箱默认**只能访问自己的 DB**，不能访问 master DB
- 沙箱 A 不能 ping 沙箱 B

**V-3. L6 创始人层逻辑模糊**
§9.3.1 写"FounderGuard + 平台级租户 ID"，但：
- 创始人是否可以做"普通业务操作"（如审批流水线）？
- 创始人越权是"合法越权"还是"需要审计的特权操作"？
- 创始人操作是否触发 BASE_FOUNDER_AUTH_LOG？

建议补一节 **§9.4.4 创始人越权边界**：
- 合法越权：审阅任意租户流水线、查看任意租户 AI 审计、签发 KnowledgePatch
- 受限越权：修改任意租户业务数据 → 必须二次 TOTP
- 不可越权：删除任意租户业务数据 → 必须创始人+另一个创始人双签

### 越权测试 10 条 🟡 2 个补强

§9.3.2 的 10 条都是合理的，但**缺两类关键测试**：

| 缺失                      | 场景                                                         |
| ------------------------- | ------------------------------------------------------------ |
| **T-11 创始人合法越权**   | 创始人查看 tenant_001 数据 → 200 + 写 BASE_FOUNDER_AUTH_LOG  |
| **T-12 创始人受限越权**   | 创始人修改 tenant_001 数据 → 必须二次 TOTP，无则 403         |
| **T-13 租户禁用后访问**   | 租户被禁用后，旧 JWT 访问 → 401                              |
| **T-14 跨租户流水线协作** | 业务专家 A（tenant_001）邀请业务专家 B（tenant_002）评审 → 应允许（B 角色 = 临时评审） |

### 🟡 交互性问题

**I-1. 缺 SSE 断线重连 UI**
§8.3.2 列出 8 种事件类型的颜色和行为，但**断线后用户只能看到事件流中断，没有"正在重连"的视觉提示**。建议：

**I-4. PipelineManager.vue 三栏布局在小屏挤压**
280px（左）+ flex:1（中）+ 360px（右）= 最小 640px+ 不含间距。**md 断点（≥768px）勉强可用，sm 断点（≥576px）会挤压**。建议：

- sm 断点：左栏折叠为图标条，中栏占满，右栏抽屉式
