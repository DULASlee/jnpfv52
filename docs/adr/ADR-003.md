# ADR-003: TenantContext 解析 — AsyncLocal + 静态访问点

**状态:** Final
**日期:** 2026-05
**阶段:** Stage 2

## 决策内容

使用 `AsyncLocal<TenantInfo>` 在异步调用链中传播租户信息，通过静态属性 `TenantContext.Current` 提供全局访问点。

## 理由

`DataExecuting` 委托是 SqlSugar 内部回调，运行在 DI 容器外部，无法通过构造函数注入获取租户信息。`AsyncLocal` 天然随 `async/await` 上下文流转，`static Current` 提供零依赖访问方式，解决了 SqlSugar 回调中填充 `TenantId` 的难题。

## 备选方案

| 方案 | 优点 | 缺点 | 为何不选 |
|---|---|---|---|
| HttpContext.Items 存储 | .NET 原生支持 | DataExecuting 中可能无 HttpContext（后台任务、消息队列） | 非 HTTP 场景失效 |
| ThreadLocal | 简单 | async/await 线程切换时丢失上下文 | 不兼容异步编程模型 |

## 后果

**正面:** HTTP 和非 HTTP 场景通用，异步安全。
**负面:** `static` 访问点增加全局状态，单元测试需手动设置/清理。

## 验证结果

HTTP 请求、EventBus 消息处理、定时任务三种场景 TenantId 传播正常。
