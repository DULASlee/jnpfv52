# ADR-008: Outbox 分发策略 — SQL Server 行级锁

**状态:** Final
**日期:** 2026-06
**阶段:** Stage 5

## 决策内容

Outbox 消息分发使用 SQL Server 的 `UPDLOCK` + `READPAST` 行级锁提示，在事务内完成状态更新，防止多实例重复分发。

## 理由

多实例部署时，多个 Outbox Dispatcher 可能同时读取同一批待发送消息。`UPDLOCK` 在读取时加更新锁阻止并发读取，`READPAST` 跳过已锁行，事务包裹状态更新与消息发送保证原子性。任何一个实例宕机，锁自动释放，消息不会丢失。

## 备选方案

| 方案 | 优点 | 缺点 | 为何不选 |
|---|---|---|---|
| Redis 分布式锁 | 跨数据库，通用性强 | 引入额外基础设施，锁超时处理复杂 | JNPF 未强依赖 Redis，增加运维负担 |
| 乐观锁（Version 字段） | 无锁等待 | 高并发时大量更新冲突重试 | Outbox 场景更适合悲观锁 |

## 后果

**正面:** 无重复分发，实例宕机自动恢复，不依赖外部组件。
**负面:** 绑定 SQL Server 特定语法，换数据库需改实现；`UPDLOCK` 有轻微性能开销。

## 验证结果

多实例并发分发测试通过，无重复发送，单实例宕机后其余实例正常接管。
