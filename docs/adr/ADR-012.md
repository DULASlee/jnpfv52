# ADR-012: Updateable/Deleteable 全局租户保护 — Safe* 方法

**状态:** Final
**日期:** 2026-06
**阶段:** Stage 4

## 决策内容

仓储提供 `SafeUpdateAsync`、`SafeDeleteAsync`、`SafeInsertAsync` 等 Safe* 方法，强制在 WHERE 子句中包含 `TenantId` 条件。直接调用 `UpdateAsync`/`DeleteAsync` 触发 ADR-012 守卫，记录 WARNING 日志。

## 理由

SqlSugar 的 `ITenantFilter` 仅对 `Queryable` 自动生效，`Updateable`/`Deleteable` 的 WHERE 不自动追加租户条件。一次疏忽就可能导致全租户数据被修改或删除。Safe* 方法在框架层强制巡检，将运行时风险变为编译期或日志可见的守卫。

## 备选方案

| 方案 | 优点 | 缺点 | 为何不选 |
|---|---|---|---|
| 仅靠开发规范约束 | 零实现成本 | 人总会犯错，一次遗漏 = 跨租户数据破坏 | 不可靠 |
| SqlSugar 自定义 Aop 全局拦截 | 对开发者透明 | 无法区分有意全表操作和无意遗漏；Aop 中修改 SQL 风险高 | 语义不精确，误判风险大 |

## 后果

**正面:** 写操作租户安全从"靠人记"变为"框架强制"，数据隔离防线加固。
**负面:** 直接 SqlSugar 写操作被拦截，老代码需迁移到 Safe* 方法。

## 验证结果

SafeUpdateAsync 生成的 SQL 含 TenantId；直接 UpdateAsync 触发 WARNING 日志。
