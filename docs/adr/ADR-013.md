# ADR-013: 非 HTTP 入口租户上下文传播 — EventBus + 定时任务

**状态:** Final
**日期:** 2026-05
**阶段:** Stage 2

## 决策内容

EventBus 消息在 Header 中携带 `tenant_id`，消费端通过 `TenantPropagationFilter` 恢复 `TenantContext`。定时任务使用 `FallbackTenantResolver` 确定目标租户。

## 理由

非 HTTP 入口（消息队列、后台任务）没有 HttpContext，无法通过 JWT/Header/QueryString 解析租户。消息头携带租户 ID 是跨进程传播的自然方式；定时任务通常属于特定租户或系统级，通过回退解析器明确指定。

## 备选方案

| 方案 | 优点 | 缺点 | 为何不选 |
|---|---|---|---|
| 消息体嵌入 tenant_id | 实现简单 | 业务消息与基础设施字段混合，违反关注点分离 | 污染业务模型 |
| 全局默认租户 | 零配置 | 所有后台任务共享同一租户，无法区分 | 不满足多租户隔离 |

## 后果

**正面:** HTTP 和非 HTTP 场景租户传播统一，消息队列和定时任务正确隔离。
**负面:** 所有 EventBus 消息发送/消费需遵循 Header 携带 tenant_id 约定。

## 验证结果

EventBus Channel 和 RabbitMQ 模式租户传播测试通过。
