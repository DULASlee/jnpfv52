# ADR-002: DataExecuting 实现 — 统一委托替代 Aop 直接赋值

**状态:** Final
**日期:** 2026-05
**阶段:** Stage 0

## 决策内容

使用 `ConfigureGlobalDataExecuting` 注册统一的审计字段填充委托，替代直接对 `DataExecuting =` 赋值的方式。

## 理由

直接赋值 `DataExecuting =` 容易被后续代码或模块覆盖，导致审计字段静默丢失。通过 `ConfigureGlobalDataExecuting` 统一注册入口，框架控制执行顺序，防止意外覆写，并集中管理 CreateTime/CreateUserId/TenantId 等审计字段的自动填充逻辑。

## 备选方案

| 方案 | 优点 | 缺点 | 为何不选 |
|---|---|---|---|
| 直接赋值 DataExecuting = | 极简，一行代码 | 多模块注册时后注册覆盖先生效，无合并机制 | 覆盖风险不可接受 |
| Aop.OnLogExecuting 事件 | 粒度细，可按操作类型处理 | 需手动区分 Insert/Update，代码分散 | 不如委托方式语义清晰 |

## 后果

**正面:** 审计字段填充统一、可预测、不可覆盖。
**负面:** 引入框架约定，新开发者需理解 ConfigureGlobalDataExecuting 用法。

## 验证结果

编译通过，Insert/Update 操作审计字段自动填充正常。
