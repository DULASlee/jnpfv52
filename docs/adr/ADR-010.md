# ADR-010: 业务冻结 + 热修复通道

**状态:** Final
**日期:** 2026-05
**阶段:** Stage 1

## 决策内容

在业务冻结期（如发版前、大促期间），仅允许通过专属热修复通道提交修复，非关键变更自动延期至解冻后。

## 理由

冻结期减少变更风险，保护生产稳定性。热修复通道确保紧急 Bug 不被阻塞，但需额外审批和测试。此策略在 DevOps 流程层面强制代码变更纪律，防止"最后一刻引入新功能"导致的线上事故。

## 备选方案

| 方案 | 优点 | 缺点 | 为何不选 |
|---|---|---|---|
| 完全禁止变更 | 最安全 | 紧急 Bug 无法修复，影响业务 | 不可行，线上问题不能等 |
| 无冻结期 | 开发自由 | 大促/发版前变更频繁，事故风险高 | 与稳定性目标冲突 |

## 后果

**正面:** 生产稳定性提升，紧急修复有受控管道。
**负面:** 开发节奏受约束，热修复通道审批增加延迟。

## 验证结果

Git 分支保护规则和 CI 检查已配置，冻结期非热修复 PR 自动拦截。
