# ADR-009: API 契约不可变性 — Service 方法签名不可重命名

**状态:** Final
**日期:** 2026-05
**阶段:** 所有阶段

## 决策内容

实现 `IDynamicApiController` 的 Service 类中，所有 `public` 方法的方法名不可重命名，重命名即变更 API 路由。

## 理由

JNPF 的 `DynamicApiController` 根据 `{ClassName}/{MethodName}` 自动生成 API 路由。方法重命名会导致路由变更，前端所有调用返回 404，工作流节点绑定断裂。此约束为框架硬性规则，贯穿所有开发阶段。

## 备选方案

| 方案 | 优点 | 缺点 | 为何不选 |
|---|---|---|---|
| 手动配置 Route 特性 | 方法名自由，路由稳定 | 每个方法需手写 `[Route]`，生产力低 | 违背 DynamicApiController 零配置初衷 |
| 中间件映射表做重定向 | 兼容旧路由 | 增加运维复杂度，映射表维护成本高 | 治标不治本，不如强制不可改名 |

## 后果

**正面:** API 路由永远稳定可预测，前端调用不会因重命名断裂。
**负面:** 方法名须在首次发布时慎重命名，后续无法用 IDE 重构改名（除非同步更新所有调用方）。

## 验证结果

代码审查规则中已加入 ADR-009 检查项，禁止无关联前端修改的 Service 方法重命名。
