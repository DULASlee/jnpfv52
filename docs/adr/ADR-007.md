# ADR-007: Repository 构造函数目标 — ≤5 行

**状态:** Final
**日期:** 2026-05/06
**阶段:** Stage 4

## 决策内容

`ISqlSugarRepository` 的构造函数保持极简（≤5 行），仅做 DI 注入赋值，复杂初始化逻辑下沉到 `IDbContextProvider` 内部。

## 理由

仓储构造函数在每次请求中频繁调用（Scoped 实例化）。复杂逻辑放在构造函数中影响可读性、测试性和启动性能。将租户解析、连接字符串选择、过滤器配置等逻辑集中到 `DbContextProvider`，仓储只持有注入的依赖引用。

## 备选方案

| 方案 | 优点 | 缺点 | 为何不选 |
|---|---|---|---|
| 构造函数内完成所有初始化 | 单文件内即可理解全貌 | 构造函数臃肿（20+ 行），多仓储重复代码 | 违反单一职责，难测试 |
| 工厂模式创建仓储 | 灵活控制创建过程 | 引入额外抽象层，框架复杂度增加 | 过度设计，DI 容器已够用 |

## 后果

**正面:** 构造函数可读性强，逻辑集中、易维护。
**负面:** 初始化逻辑分散在 Provider 中，新人需跳转理解。

## 验证结果

编译通过；所有仓储构造函数 ≤5 行验证通过。
