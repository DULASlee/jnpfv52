# AI Engineering Operating System

## Master Design Specification v1.0

### AI Engineering OS — Governance × AgentOS × Engineering Intelligence

---

# 0. 文档定位

本文档是 **AI Engineering Operating System（以下简称 AI Engineering OS）** 的总设计规格、阶段施工蓝图和验收基线。

本文档的第一目标不是描述“我们想做什么”，而是保证：

> **任何能力水平一般的 AI 工程师，只要严格按照本文档从 Phase 0 逐阶段执行，都不会因为执行到前几步后遗忘整体目标、错误缩小范围、错误替换核心能力、通过删除功能获得测试绿色，或者将模拟闭环误报为真实工程闭环。**

本文档同时作为：

* Architecture Baseline
* Phase Roadmap
* Implementation Contract
* Acceptance Contract
* AgentOS Evolution Contract
* Engineering Governance Contract

使用原则：

> **阶段未通过 Gate，不得宣布该阶段完成。**
>
> **后续阶段不得以“先实现简单版本”为理由删除本规格要求的核心能力。**
>
> **任何降级、Skip、Mock 替代、功能删除、弱化测试、放弃真实 Build 等行为，都必须被视为 Gate Failure，而不是实现策略。**

# 1. 系统最终目标

AI Engineering OS 的最终目标：

> **把不同能力水平的 AI Agent，约束在统一的工程治理、认知、执行、验证和证据体系中，使弱 Agent 不容易遗漏关键工程思考，使强 Agent 能够充分发挥自主能力，同时所有 Agent 都必须对真实工程结果负责。**


# 3. 核心设计原则

## IRON-01 — Expert Is a Real Agent

Expert Agent 必须拥有：

```text
Identity
State
Lifecycle
Task
Skills
Context
Capability
Evidence
```

不能把 Expert 实现成一个 Prompt。

---

## IRON-02 — Runtime Must Not Own Domain Intelligence

AgentOS Runtime 不得理解：

```text
JNPF
FlowCommentService
具体业务流程
具体领域规则
具体重构策略
```

Runtime 只负责：

```text
Lifecycle
State
Execution
Capability
Policy
Security
Evidence
Coordination
```

领域智能属于 Expert。

---

## IRON-03 — Expert Must Not Bypass Runtime

Expert 不得直接绕过 Runtime 调用：

```text
File API
Process
Shell
Build
Test
Git
External Service
```

必须：

```text
Expert
 ↓
AgentOS Runtime
 ↓
Capability
 ↓
Tool / MCP / Provider
```

---

## IRON-04 — No Function Loss for Green

禁止通过以下方式获取“成功”：

```text
删除功能
删除业务逻辑
删除事件
删除 API
降低 Assertion
Skip Test
取消真实 Build
全部 Mock
硬编码结果
空实现
注释代替核心功能
缩小验证范围
改变测试使其适应错误代码
```

---

## IRON-05 — Governance Must Be Executable

关键工程规则不能只存在于：

```text
Markdown
Prompt
Skill
Agent Memory
```

必须能够转换成：

```text
Machine Policy
Runtime Gate
Hook
State Constraint
```

---

## IRON-06 — Completion Must Be Evidence-Backed

Agent 不得仅凭自己的总结宣布：

```text
Completed
```

完成状态必须由：

```text
Runtime State
+
Required Evidence
+
Gate Evaluation
```

共同决定。

---

## IRON-07 — Governance Sovereignty

工程治理唯一权威：

```text
AI Engineering Control Plane
```

第三方：

```text
Skill
MCP
Memory
Plugin
Prompt
Framework
Agent
```

不得覆盖项目：

```text
Rules
Policies
Contracts
Gates
Completion Criteria
```

---

## IRON-08 — External Capability Isolation

外部工具可以提供：

```text
Capability
```

但不得拥有：

```text
Governance Authority
```

例如 Serena 可以：

```text
Search Symbol
Find Reference
Navigate Code
```

但不能：

```text
决定 Phase Complete
关闭 Gate
修改 Policy
删除 Evidence Requirement
```

---

## IRON-09 — Single Authoritative Skill Registry

项目必须只有一个权威 Skill Registry。

外部 Skill 可以：

```text
吸收
参考
迁移
改写
```

但不得形成第二套平级工程治理体系。

---

## IRON-10 — Real Engineering Over Synthetic Success

真实能力必须使用真实证据证明：

```text
Real Mutation
Real Diff
Real Build
Real Test
Real Workflow
Real Side Effect
Real Review
```

模拟结果只能作为辅助证据，不得代替关键工程证据。
