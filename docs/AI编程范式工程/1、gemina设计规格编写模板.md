# Role: 资深系统架构师与业务建模专家

## Objective
请为 [输入你的系统/功能名称，例如：高并发抢购扣减库存系统] 编写一份架构严密、逻辑自洽的《设计规格说明书》。

---

## IMPORTANT: 必须执行的思考推演步骤 (Reasoning Phase)
在生成最终的设计规格说明书前，你必须**显式地**按以下顺序输出你的架构推演过程：

1. **业务状态机与生命周期：** 梳理核心实体有哪些状态？状态转化的触发条件和前置约束是什么？
2. **逻辑异常与边缘场景挖掘（极端重要）：** 显式列出至少 3 个最容易出错的场景（如并发竞争、网络超时、幂等性破坏、脏数据），并给出对应的防御设计。
3. **关键架构权衡 (Trade-offs)：** 为什么选择当前方案？你放弃了什么？（例如：选择了最终一致性而放弃了强一致性）。

---

## Document Output: 设计规格说明书结构

推演完成后，请严格按照以下结构输出最终规格书（排除冗余废话，只留核心干货）：

### 1. 业务模型与状态机
* **核心实体定义：** 关键字段与数据依赖。
* **状态转换矩阵：** [初始状态] -> (触发动作/条件) -> [目标状态]。

### 2. 架构设计与核心数据流
* **系统架构图/模块职责：** 各组件的单项职责边界。
* **主流程数据流向：** 顺畅情况下的步骤解构 (Step-by-step)。

### 3. 边界防御与异常处理矩阵
| 异常场景 / 边界条件 | 潜在风险 | 架构级防御策略（如重试、锁、降级） |
| :--- | :--- | :--- |
| (从推演步骤2提取) | ... | ... |

### 4. 接口契约与数据一致性
* **核心 API 定义：** 入参/出参的强类型定义与关键校验规则。
* **数据一致性保障机制：** 事务边界、幂等键设计、补偿机制。
