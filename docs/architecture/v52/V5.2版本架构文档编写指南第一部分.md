## 一、v5.2 与 v3.6 架构差异速查（编写者必读）

编写任何章节前须通读本表。**v5.2 并非简单改端口**——启动模型、API 暴露方式、表名、配置拆分均有结构性差异。

### 1.1 结构性差异

| 维度 | v3.6（常见写法） | v5.2（本仓库实测） | 编写影响 |
|------|------------------|-------------------|----------|
| **宿主项目** | 单一 Web 入口 | **`application/JNPF.API.Entry`**（另有 `JNPF.OA.API.Entry`） | **保留** `JNPF.API.Entry` 项目名；禁止写成已移除 |
| **启动入口** | `Program.cs` + `Startup.cs` | **`Program.cs` → `Serve.Run()`** + **`Startup : AppStartup`** 并存 | 须写双入口协作，不可写「仅 Serve.Run、无 Startup」 |
| **API 暴露** | 手写 Controller | Service 实现 **`IDynamicApiController`**，由 **`DynamicApiControllerApplicationModelConvention`** 生成 Controller | 文档引用 `OAuthService.Login`，禁止 `AccountController` |
| **分层** | Controller → Application → Repository | **`modularity/*/*Service` → `ISqlSugarRepository<T>`** | 无 `BaseController` / `BaseService` / `BaseRepository` |
| **主配置** | 单文件 `appsettings.json` | **`appsettings.json`（仅扫描目录）+ `Configurations/*.json`** | 配置解读须按分文件 + Options 类 |
| **统一响应** | `Result<T>` 等 | **`RESTfulResult<T>`** + `RESTfulResultProvider` | 异常链写 FriendlyException + UnifyResult |
| **对象映射** | AutoMapper（常见） | **Mapster** | 技术栈表勿写 AutoMapper |
| **用户上下文** | `UserContext` / AsyncLocal | **`IUserManager`** + `App.User` Claims | 登录后读用户信息走 UserManager |

### 1.2 数据与命名

| 维度 | v3.6 | v5.2 | 编写影响 |
|------|------|------|----------|
| **系统表前缀** | `sys_*` | **`BASE_*`**（如 **BASE_USER**、**BASE_MODULE**） | 全文禁止 sys_* |
| **菜单/按钮表** | `sys_menu` / `sys_button` | **BASE_MODULE** / **BASE_MODULE_BUTTON** | 勿写成 BASE_MENU / BASE_BUTTON |
| **字段列名** | 多种风格 | 实体多为 **`F_` 前缀**（如 `F_ACCOUNT`、`F_REAL_NAME`） | 表结构须对照 Entity `[SugarColumn]` |
| **大屏表** | — | **`BLADE_VISUAL_*`**（独立模块，非 BASE_*） | 大屏专章勿混用 BASE_ 表 |
| **低代码运行表** | — | **`BASE_VISUAL_DEV`** + 动态 **`mt{ID}`** | 与 BLADE 大屏体系分离（见操作手册） |

DDL 基线：实体 `[SugarTable]` in `modularity/**/*.Entitys/`；初始化脚本参考 `web/jnpf_sundial_init.sql`（以实体为准）。

### 1.3 部署与端口（v5.2 迁移验证环境）

**架构文档与操作手册须采用下列端口**（团队 v5.2 联调实测），**不得**将下列内容写成 v3.6 的 `:5000` 直连后端：

| 服务 | v5.2 地址 | 源码/配置依据 |
|------|-----------|---------------|
| 后端 API | **`http://localhost:30000`** | 迁移验证；`dotnet run --project application/JNPF.API.Entry/...` |
| 主 WEB dev | **`http://localhost:3100`** | `jnpf-web-vue3/.env` → `VITE_PORT=3100` |
| 前端 API 代理 | **`/dev` → `http://localhost:30000`** | `jnpf-web-vue3/.env.development` → `VITE_PROXY` |
| WebSocket | **`ws://localhost:30000`** | 同上 `VITE_GLOB_WEBSOCKET_URL` |
| 数字大屏 | **`http://localhost:8100/DataV/`** | `jnpf-web-datascreen-vue3/vite.config.js` port 8100 |
| UniApp H5 | **`http://localhost:3800`** | 迁移 proxy 脚本 |
| 报表 dev | **`/reportDev` → `:32000`** | `.env.development` `VITE_PROXY` 第二项 |

> **⚠ 仓库陷阱**：`application/JNPF.API.Entry/Properties/launchSettings.json` 仍含 `http://localhost:5000`（模板残留）。**架构文档描述运行时拓扑时一律用 `:30000`**，并可在部署章注明「launchSettings 与迁移环境不一致，以实际启动参数为准」。

### 1.4 模块装载（Entry 引用）

`JNPF.API.Entry.csproj` 直接引用的业务模块（编写模块地图时以此为准）：

`JNPF.OAuth`、`JNPF.Systems`、`JNPF.VisualDev`、`JNPF.WorkFlow`、`JNPF.CodeGen`、`JNPF.Message`、`JNPF.TaskScheduler`、`JNPF.Apps`、`JNPF.Extend`、`JNPF.ZxDev`、`JNPF.InteAssistant`

**未**默认引用：`JNPF.VisualData`（数字大屏，`modularity/visualdata/`，API 前缀 `/api/blade-visual/`）。若文档涉及大屏，须单独说明宿主引用或部署方式。

### 1.5 四层目录（替代 v3.6 Api/Application/Core）

```
application/     → Web 宿主（JNPF.API.Entry）
modularity/      → 业务 *Service（IDynamicApiController）
modularity/common/ → JNPF.Common、JNPF.Common.Core（Filter/Manager）
framework/       → JNPF 内核 + Extras（SqlSugar/JWT/Mapster）
infrastructure/  → EventBus、WebSockets 等插件
```

## 二、通用编写铁律（违反任何一条，该文档判定为不合格）

完整条文见 [`ARCHITECTURE_DOC_RULES.md`](../ARCHITECTURE_DOC_RULES.md)。以下为 **v5.2 穿透原则示例**（须替换旧版 AccountController 示例）。

### 【铁律1 · 穿透原则】

```
✗ 禁止："系统采用 JWT 认证，通过 Token 验证用户身份"

✗ 禁止（v3.6 路径）："POST /api/account/login → AccountController → JwtHelper"

✓ 必须（v5.2 实测）：
  前端 POST /api/oauth/Login（form-urlencoded）
  → 动态 API 路由到 OAuthService.Login(LoginInput input)
     （modularity/oauth/JNPF.OAuth/OAuthService.cs:690）
  → ISqlSugarRepository<UserEntity> 查 **BASE_USER**（F_ACCOUNT / F_PASSWORD）
  → JWTEncryption 签发 Token（framework/.../JWTEncryption.cs）
  → 过期分钟数来自 Configurations/JWT.json → JWTSettings.ExpiredTime（示例 1440）
  → JwtHandler（application/JNPF.API.Entry/Handlers/JwtHandler.cs）Pipeline 校验与续期
  → 业务代码通过 IUserManager 读取当前用户 Claims
```

**v5.2 特别约束：**

- Service 类标记 **`IDynamicApiController`**（接口），非方法上的 `[DynamicApiController]` 特性
- 路由来自 `[Route("api/[controller]")]` + `[ApiDescriptionSettings]` + 方法 Verb
- 无法确认时标注 **【待源码验证】**

### 【铁律2 · 数据锚定原则】

- 系统权限核心表示例：**BASE_USER**、**BASE_ROLE**、**BASE_MODULE**、**BASE_MODULE_BUTTON**、**BASE_AUTHORIZE**、**BASE_ORGANIZE**
- 字段以 Entity 的 `[SugarColumn(ColumnName = "F_...")]` 为准
- 每模块 ≥ 2 张表；纯前端模块须写消费的 API 及后端表

### 【铁律3 · 图表强制原则】

| 场景 | 图表 |
|------|------|
| 多步骤流程 | Mermaid `flowchart` |
| 多组件交互 | Mermaid `sequenceDiagram` |
| 数据模型 | Mermaid `erDiagram` |
| 架构层次 | Mermaid `graph` |

图须编号（图2-1）、标注类名/方法名/表名。

### 【铁律4 · 可验证原则】

- 路径相对于仓库根 `d:\JNPF-v52\backend`
- 业务代码在 **`modularity/`**、框架在 **`framework/`**，禁止写 v3.6 的 `jnpf-server/.../Services/` 等虚构根路径
- 不确定时使用：`【待源码验证：…需在 modularity/ 或 framework/ 下确认】`

### 【铁律5 · 禁止空泛原则】

禁止「系统支持…」「主要包括…」等无代码锚点的句式（见 ARCHITECTURE_DOC_RULES §铁律5）。

### 【铁律6 · 版本纯净原则】（v5.2 新增）

**绝对禁止：**

- 从 [`archive/pre-v52-rewrite/`](../archive/pre-v52-rewrite/) **复制粘贴**正文到 `v52/`
- 在 v5.2 正文中写 v3.6 部署拓扑（尤其 **`localhost:5000` 作为联调 API**）

**完成后全文搜索污染词**（出现即须修正或说明为「历史对比」）：

| 污染词 / 错误写法 | v5.2 正确写法 |
|-------------------|---------------|
| `POST /api/account/login` | `POST /api/oauth/Login` |
| `AccountController` | `OAuthService` |
| `JwtHelper.GenerateToken` | `JWTEncryption`（Encrypt / AutoRefreshToken 等） |
| `sys_user` / `sys_menu` / `sys_button` | **BASE_USER** / **BASE_MODULE** / **BASE_MODULE_BUTTON** |
| `BASE_MENU` / `BASE_BUTTON` | **BASE_MODULE** / **BASE_MODULE_BUTTON** |
| `Configurations/jwt.json` | **`Configurations/JWT.json`**（节名 `JWTSettings`） |
| 「无 Startup.cs」 | **`Startup : AppStartup` 与 `Serve.Run()` 并存** |
| 「已移除 JNPF.API.Entry」 | **宿主项目仍为 `JNPF.API.Entry`** |
| 前端 proxy → `:5000` | **`/dev` → `:30000`** |
| `[DynamicApiController]` 打在方法上 | 类实现 **`IDynamicApiController`** |

**允许出现 `:5000` 的唯一情况**：明确标注为「`launchSettings.json` 模板残留，非迁移环境」，且同段给出 `:30000` 正确值。

## 四、深度自检清单（每章完成后）

### 通用自检

- [ ] 至少一条端到端调用链（含文件路径 + 类 + 方法）
- [ ] ≥ 2 张核心表及关键字段（**BASE_*** / **BLADE_***）
- [ ] ≥ 1 张编号 Mermaid 图
- [ ] 扩展点或设计局限
- [ ] 不确定处已标【待源码验证】

### v5.2 专项自检

- [ ] 联调拓扑为 **:30000 / :3100**，非 `:5000` 直连
- [ ] 登录链为 **OAuthService.Login**，非 AccountController
- [ ] API 层描述为 **IDynamicApiController + 动态 Controller**
- [ ] 启动描述为 **Serve.Run + Startup(AppStartup)**，非二选一错误
- [ ] 配置来自 **Configurations/*.json** + Options 类
- [ ] 表名/列名与 Entity 一致（**BASE_***、**F_***）
- [ ] 文档头完整；未从 archive 粘贴段落
