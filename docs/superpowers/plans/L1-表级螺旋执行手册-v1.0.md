## 3. 单表 SOP（五步细化）

每张表一个目录：`.claude/evidence/backend-refactor/l1/{table_name}/`，四件套归档于此。

**① 观察 → 事实卡**（七项，模板随手册附录）：列清单（INFORMATION_SCHEMA 实测）/ 索引现状（含碎片率）/ 物理外键与逻辑关系 / 引用代码位置（Serena 符号检索 + 文本扫描双通道）/ 读写方模块 / 行数与关键列分布（最长值、NULL 占比、枚举值域实况）/ 事务边界与已知慢查询。

**② 判断 → 行动台账**（每条标注 A/B/C 级）：
- **A 级·预授权直接做**：覆盖索引设计、复合列序调整、过滤索引、低选择性索引清理、碎片治理、填充因子、压缩、隐式转换消除（改查询端）；N+1 消除、列表投影化、批量写入、异步化、深分页改游标式、软删过滤补齐、裸 SQL 参数化修复、事务剔除外部调用；
- **B 级·证据批审**（先体检后动手）：UNIQUE（查重零重复才准加）、NOT NULL+DEFAULT、CHECK（先违规扫描）、rowversion 加列、计算列、默认值下沉、枚举值统一（UPDATE 前备份快照）、导航属性增删；
- **C 级·人工裁决**（攒批上会）：ALTER COLUMN 语义类型变更、MAX 缩容、多值字段拆关联表、级联策略变更、NVARCHAR→VARCHAR、时区统一、一切主键策略变动。

**③ 行动**：A 级随做随 PR；B 级每表一个 PR 附数据体检报告；C 级起草迁移+回滚脚本进裁决队列。所有结构变更走编号迁移脚本，禁止手工 ALTER。

**④ 验证（三条硬杠）**：考卷全绿；本表 CRUD 接口快照比对一致（§4）；性能动作附前后实测对比（§5 协议），拿不出对比数据不得声称有效。

**⑤ 归档**：事实卡 + 台账 + 验证记录 + 遗留问题清单（B/C 未决项滚动下批）。

## 4. 接口快照录制与比对（五项前置之三）

- **录制**：沿用现有工具链——`scripts/lib/jnpf-auth.mjs` 取 token，`scripts/jnpf-api.mjs` 调该表的 CRUD 接口，把请求参数与响应体原样存为 `tests/characterization/fixtures/{table}/*.json`；
- **比对**：重放同请求，diff 存档响应；时间戳/JWT 类易变字段列入白名单忽略；
- **达标线**："有保存、可回放"——任意人任何时候重放脚本都能得到与 fixture 一致的结果（白名单字段除外）；
- 观察步顺手录制，行动步之后重放比对，不一致即熔断回退。

## 5. 性能对比最小协议（五项前置之四后半）

同一数据库、同一数据量、同一查询参数；预热执行 1 次（丢弃）；正式连续执行 **3 次取中位数**；开启 `SET STATISTICS IO/TIME ON`，输出文本存档（必要时另存 .sqlplan）；测量期间无其他负载。收益声明必须引用存档文件编号——没有存档号的收益数字一律无效。

## 6. C 级裁决会机制（五项前置之二）

- **组成**：人工裁决人（架构最终决定权）＋ 后端负责人 ＋ DBA 角色（可兼任）＋ AI 工程师（呈报证据）；涉业务语义时邀业务方；
- **决策四维度量化**：数据风险（是否可能丢数据/不可回滚）／回滚成本（分钟级/小时级/天级）／实测收益（引用 §5 存档）／行为影响面（命中考卷"核心冻结层"直接否决）；
- **规则**：逐条裁 过 / 改 / 否。否决项自动降级为"仅 A 级维护"，写入遗留清单；同一事项两次会议未决 → 默认挂起留驻现状，不阻塞批次推进；
- **节奏**：每两周一次批量呈报；紧急项可单条加急。

## 7. 熔断阈值（五项前置之五）

| 触发条件 | 动作 |
|---|---|
| B 级查重：重复率 >1% 或重复行 >100 | 该表暂停，转专项治理，移出当前批次 |
| CHECK 违规扫描：命中 >50 行或占比 >0.5% | 同上 |
| MAX 缩容目标 < 现存最大长度 | 直接否决该列缩容项（无需上会） |
| 发现跨模块写入方（与档案不符） | 升级多模块议题，转 C 级裁决会 |
| 快照比对不一致 / 考卷红 | 回退最近标签，全线停，根因闭环才续（既有铁律） |

熔断只停出事的表，不拖累批次内其他表。

## 8. 红线自动化现状（五项前置之七的答复）

R4 租户过滤、R7 SQL 参数化**已是 L0 写入钩子**（guard-tenant-filter.mjs / guard-sql-injection.mjs，test-hooks 28 用例覆盖），AI 产出即时拦截，人工提交过 .githooks/pre-commit。手册不重复造轮子；唯一补充要求：凡涉及全局过滤器调整的 PR，必须附 ToSql() 实际输出验证（红线 R4 陷阱 13）。

## 9. 批次节奏与爬坡路线

首批 5 张（本手册 §2）→ 复盘 PASS → 常规每周一批 5–8 张（周一排序取头部、周五 B 级评审、隔周 C 级裁决会）→ 爬坡顺序：日志流水 → 单模块私有业务表 → 共享读热表（字典/消息）→ flow_\* 与 visualdev 核心。
