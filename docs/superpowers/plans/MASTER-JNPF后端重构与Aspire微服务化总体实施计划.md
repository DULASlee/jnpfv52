## 4. Task 卡模板（九段格式）

```text
Task-{圈}.{序号}-{对象名}
├── Objective      ：一句话目标（如"base_sys_log 完成表级五步螺旋"）
├── Scope          ：该对象边界 + "不碰"清单
├── Preconditions  ：前置（考卷就绪 / 上游事实卡存在）
├── Evidence       ：观察步采集的事实（结构/引用/调用路径）
├── Implementation ：判断结论 + 行动 diff（逐条标注 可逆/触发不可逆清单）
├── Verification   ：考卷结果 + 对象级行为测试（索引变更附性能对比）
├── Regression     ：回归面声明
├── Artifacts      ：事实卡/建议清单/diff/报告的存放路径
└── Gate           ：是否命中不可逆清单——未命中=PR 证据放行；命中=STOP 等人工
```

## 5. 治理细则

**两份清单（定义见总规格 §10）**：
- 不可逆清单（删除数据/拆并表/改外键约束/改公开 API 签名/删表删文件/服务下线）→ STOP 等人工；
- 预授权清单（加删索引/标废弃/提方法/敛调用/模块内移动/内部重命名/补测试）→ 直接执行，PR 证据放行。

**复核分级**：圈内任务 AI 自检 + 证据留档，抽查不全批；每圈出口人工复盘会（PASS/调整/扩围 三选一）；首批 10–20 张后强制方法论复盘。

**时间盒**：每个复盘会限定议题与结论，不允许开放式打磨；单表五步循环若超过一个工作日仍未收敛，说明判断步出了问题——回退到观察步重采事实。

## 6. 失败预案

① 后圈发现前圈判断错 → 按波次标签回退 + 更新事实卡再前进；
② 考卷大面积红 → 全线停、退最近标签、根因闭环后才续；
③ 模块始终过不了独立启动测试 → 登记留驻单体，写入评估表存档（有效产出）。

## 7. 完成定义（引自总规格 §11）

最小成功 = 157 事实卡全覆盖 + 核心聚合完成第二圈 + 全模块持有事实卡与评估表 + 单体稳定跑在 Aspire + 考卷持续全绿。
完整成功 = 具备条件的候选完成独立部署并稳定运行 + 确需者完成数据隔离。
任何一圈之后停下都留下更干净、可发布、可验证的系统——不存在烂尾状态。
