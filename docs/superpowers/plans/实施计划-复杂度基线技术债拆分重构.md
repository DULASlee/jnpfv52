## 0. 通用施工协议（每方法五步，逐步门禁）

| 步 | 动作 | 门禁（不达标不进入下一步） |
|----|------|--------------------------|
| S1 | **特征用例前置**：按规格 §2 该方法的不变量清单+保护缺口表，补齐全分支特征用例（含全部怪异项），对**当前实现**跑绿并锁定为金标准 | 新增用例全绿；用例与不变量清单一一编号对应 |
| S2 | **拆分**：按规格 §2 该方法的职责边界表抽取子方法；门面保持原签名逐字委托；怪异行为注释标注不变量编号 | 全解构建 0 错 |
| S3 | **等价验证**：S1 特征集 + 既有测试全量 + 签名契约断言全绿；查询链路方法补跑路由快照 zero diff | 逐字一致，零跳过 |
| S4 | **基线销账**：移除 `complexity-baseline.json` 该条目；清除方法 `// TODO: CCxx…` 注释；`TECH-DEBT.md` 对应行标记销账 | `/p:CI_BUILD=true` 0 错（无豁免通过 = 目标实证） |
| S5 | **提交**：严格按规格 §4 提交边界（4 类文件，禁混入清单） | 提交前 `git status / diff --stat / diff --name-only` 三查 |

**失败处置**（规格 §4 回滚边界）：F1 用例错→修用例不修实现；F2 等价失败→丢弃工作区或 `git revert` 单提交；F3 目标不达→继续拆分，禁止重登基线绕过，不可达则停工报批。

**提交消息格式**：`refactor(D1): <类.方法> 拆分（CC<旧>→门面<新>，子方法≤<n>；基线销账）`
