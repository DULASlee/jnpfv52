## 1. 项目背景

### 1.1 为什么要做

我们在 `.claude/skills/generic-class-refactor-expert/` 已沉淀**通用类级重构专家 v6.0**（含 18 个 references + Golden Examples 1-4 + L2 类级螺旋 SOP）。这个 skill 在 JNPF 项目内部是有效的，但有 3 个结构性限制：

1. **JNPF 锁定**：references / 决策范式中频繁出现 SqlSugar / IRepository / TenantId / Foundation.Domain.* 等项目特异词，外部项目无法直接复用
2. **Skill ≠ Agent**：skill 是知识库，需要人类读 skill 文档后按 SOP 行动；Agent 是执行者，需机器可读 + 可委派
3. **不可发布**：无法对外分发，每次新项目都要重新教一遍

### 1.2 目标产物

**Universal .NET Class Refactoring Architect** —— 一个**可独立发布**的 Qoder 用户级 Subagent：

- 用户级（`~/.qoder/agents/`）跨项目可用
- 四层架构（Core / Mode / Profile / Knowledge）严格分层
- 默认仅 Audit + Verify，Execute 需显式授权
- D-13/D-14/D-19/D-25/D-26 等 10+ 道安全硬门
- 18 个 references 全量保留作为外挂知识资产
- GitHub 公开仓库，5 分钟上手

### 1.3 不在本次范围（明确）

- ❌ 不修改 `.claude/skills/generic-class-refactor-expert/`（共存策略，见 §10）
- ❌ 不实现 Phase 2 动态加载（Qoder 元数据能力 GA 后启动）
- ❌ 不重写 v6.0 的 18 个 references（迁移即可，内容不变）
- ❌ 不创建 GitHub 仓库（等本文档完成 + 用户拍板）

## 2. 目标与边界

### 2.1 Mission（来自 Section 1）

> **Universal .NET Class Refactoring Architect** 默认作为**分析与验证 Agent** 工作，在显式授权 Execute Mode 后，可进入**受控代码修改流程**。
>
> 产出"诊断 + 方案 + 风险 + 验证路径"四件套，帮助人类工程师在**行为不变**前提下，对单个 .NET 类进行**证据驱动**的优化。

### 2.2 Out of Scope（硬边界）

```
❌ 不做架构级重构决策（模块拆分 / 微服务化 / 消息队列引入）
❌ 不做表级重构（table-refactor-expert 的领地）
❌ 不做需求分析、不做业务建模
❌ 默认不直接修改代码（Execute 默认关闭，需显式授权）
❌ 不 commit / push / merge（任何时候）
❌ 不引入新框架 / 库
❌ 不脱离项目事实（必须基于可验证项目事实）
❌ 不混淆 Profile 与 Knowledge
```

### 2.3 Class Boundary Definition（Section 1 A2）

```
Primary Target:     一个主要类（fqdn）
Allowed Context:    必要上下游依赖类（显式声明）
Forbidden Expansion:
  - module_refactor
  - service_split
  - orm_migration
```

### 2.4 与 v6.0 Skill 的关系（Section 10 落地策略）

| 维度 | v6.0 Skill | 本 Agent |
|------|-----------|---------|
| 消费方 | 人类工程师读 skill 文档 | LLM 直接执行 |
| 输出 | 决策范式（Golden Example） | 四件套 Report |
| 范围 | JNPF 内部 | 任意 .NET 项目 |
| 演进 | 人类维护 | Knowledge Router + 版本管理 |

**共存策略**：v6.0 skill 保留在 `.claude/skills/`，作为**内部使用**；本 Agent 通过 Profile 加载 JNPF 特异性 + Knowledge 共用 references 实现等价能力。

## 3. 设计骨架回顾（Section 1-7 决策摘要）

### 3.1 四层架构（Section 2 锁定）

```
┌────────────────────────────────────────────┐
│ Layer 1: Core Reasoning Engine (core/) │
│ identity / principles / workflow / │
│ decision-model / quality-gates │
│ 【完全不知道任何项目 / ORM / 命名空间】 │
└─────────────────┬──────────────────────────┘
                  ↑ 注入
┌─────────────────┴──────────────────────────┐
│ Layer 2: Execution Modes (modes/) │
│ audit.md / verify.md / execute.md │
│ 【决定 Agent 行为权限 + 工具白名单】 │
└─────────────────┬──────────────────────────┘
                  ↑ 注入
┌─────────────────┴──────────────────────────┐
│ Layer 3: Project Profiles (profiles/) │
│ universal-dotnet.md (default) │
│ jnpf-sqlsugar.md / efcore-ddd.md / ... │
│ 【所有 Profile 必经 D-14 Validation Gate】 │
└─────────────────┬──────────────────────────┘
                  ↑ 按 Finding Tag
┌─────────────────┴──────────────────────────┐
│ Layer 4: Knowledge Assets (knowledge/) │
│ Engineering Principle / Pattern Library / │
│ Decision Pattern (Golden Example) │
│ 【独立版本 + 独立测试 + 独立演进 (D-12)】 │
│ 【Knowledge Router 独立逻辑组件 (C-02)】 │
└────────────────────────────────────────────┘
```

### 3.2 核心推理循环（Section 3 采纳）

```
Frame (前置定位 + 边界声明)
   ↓
[Evidence → Diagnosis → Recommendation → Verification]×N
   ↓ NEED_EVIDENCE 时重跑 Evidence
Decide (GO / DEFER / STOP / NEED_EVIDENCE)
   ↓
Report (Expert Refactoring Report)
```

**15 道关卡**：5 Step Gates + 4 横切 Hard Gates + 6 Mission 硬约束（M-01~M-06）。

### 3.3 Mode 能力矩阵（Section 4 关键点）

| 能力 | Audit | Verify | Execute |
|------|:-----:|:------:|:-------:|
| Read / Grep / Glob | ✅ | ✅ | ✅ |
| dotnet build/test/BDN | ❌ | ✅ | ✅ |
| **Apply Approved Patch**（受 Scope 限制） | ❌ | ❌ | ✅ |
| git commit/push/checkout | ❌ | ❌ | **🚫永远** |

### 3.4 Profile 关键约束（Section 5 锁定）

- D-13 单向约束：Profile 不可覆盖 Core Principles
- D-14 Validation Gate：6 步校验（Schema → Semantic → Policy）
- D-19 Risk Model / Policy Separation：Core 冻结 Risk 3 维 + 语义，Profile 仅调权重/阈值
- C-16 Risk Semantic Contract：Profile 不可改"风险语言本身"

### 3.5 Knowledge 三类资产（Section 6）

| 类别 | 含义 | 寿命 |
|------|------|------|
| **Engineering Principle** | 工程规律（10 年不变） | 长期 |
| **Pattern Library** | 典型模式（领域实践） | 中期 |
| **Decision Pattern** | 决策范式（D-18 Golden Example） | 长期 |

**D-27 ~ D-30 知识治理硬门**：Router Retrieval Only / Evidence Compatibility Contract / Golden Example Misuse Boundary / Cross-Context Validation。

### 3.6 Validation 三层架构（Section 7）

```

   ↓ PASS
Process Validation (15 Gates)
   ↓ PASS
Output Validation (Report 审计 + Claim Verifiability)
```
