### 4.1 扫描架构

```
┌─────────────────────────────────────────────────────────────┐
│                    扫描协调器 (Scanner)                      │

│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐         │
│  │ 模块扫描器  │  │ 维度扫描器  │  │ 报告生成器  │         │
│  │ (Module)    │  │ (Dimension) │  │ (Reporter)  │         │
│  └─────────────┘  └─────────────┘  └─────────────┘         │
├─────────────────────────────────────────────────────────────┤
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐         │
│  │ 文件收集器  │  │ 正则匹配器  │  │ 结果聚合器  │         │
│  │ (Collector) │  │ (Matcher)   │  │ (Aggregator)│         │
```

## 6. 检测规则实现

### 6.1 正则表达式规则

每个维度的检测规则已定义正则表达式（见扫描清单 v1.1），实现时需：

1. **预处理**：移除注释、字符串字面量
2. **匹配**：使用 `Regex.Matches` 提取候选
3. **过滤**：排除误报（如测试代码、生成代码）
4. **标注**：记录文件路径、行号、代码片段

### 6.2 语义分析规则

部分规则需要语义分析（如跨类重复代码），采用以下策略：

1. **AST 解析**：使用 Roslyn 语法树
2. **符号分析**：使用语义模型
3. **依赖图**：构建模块依赖图

### 6.3 JNPF 特定规则

维度 N（JNPF 架构合规）需要项目特定检测：

| 规则 | 检测方法 |
|------|---------|
| N1 多租户过滤 | 检查 SqlSugar 查询是否包含 TenantId 条件 |
| N2 SQL 注入 | 检查动态 SQL 拼接 |
| N3 API 权限 | 检查 IDynamicApiController 方法是否有权限声明 |
| N4 三元组 | 检查 StudioWorkspace 路径格式 |
| N5 路由合规 | 检查 ApiDescriptionSettings 特性 |
| N6 Oops 体系 | 检查异常抛出方式 |
| N7 模块边界 | 检查 using 声明 |

```markdown
# JNPF 后端类级代码审计报告 v1.0

## 扫描摘要
- 扫描时间
- 扫描范围
- 发现统计

## 维度分析
### 维度 A：资源生命周期与内存泄漏
- 发现列表
- 严重级别分布
- 修复建议

### 维度 B：...

## Top 20 最严重问题
- 问题列表
- 影响面分析
- 修复优先级

## 修复收益预估
- 量化收益
- 工作量估算

## 附录
- 扫描配置
- 检测规则清单
- 误报/漏报说明
```

### 7.2 问题条目格式

```json
{
  "id": "A-001",
  "dimension": "A",
  "severity": "P0",
  "file": "backend/modularity/system/JNPF.Systems/UsersService.cs",
  "line": 87,
  "code": "_eventBus.Subscribe<WorkflowCompletedEvent>(OnWorkflowCompleted);",
  "description": "构造函数中订阅事件，类未实现 IDisposable，事件总线是单例，导致实例永远无法 GC",
  "fix": "实现 IAsyncDisposable，在 DisposeAsync 中退订事件",
  "impact": "每次创建工作流引擎实例泄漏约 2KB，长期运行内存持续增长",
  "effort": "2h"
}
```
