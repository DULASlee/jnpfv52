# 数据访问抽象边界设计规格 v1.0（S1-P0-A）

**日期**：2026-08-25
**前置**：S1-Final 审计（P0-1：ORM 直接依赖面 403 文件）；S2 保持 BLOCKED
**阶段性质**：设计规格 + 语义分类（只读分析，不实施任何重构）
**目标**：为 S2「数据访问抽象」建立可靠的**边界地图**——明确哪些必须重构、哪些必须保护/冻结、哪些不属于 S2；禁止按文件数量机械生成重构任务。

---

## 1. 目标与边界

1. 对 403 个 ORM 直接依赖文件（`using SqlSugar`，modularity）做**语义分类**，非机械计数；
2. 区分：真正数据访问实现 / 业务查询 / 权限查询 / 基础设施 / 特殊 SQL / 允许直接 ORM；
3. 输出三类裁决：**S2 前必须重构**、**必须保护/冻结**、**不属于 S2**；
4. 本规格是 S2 设计输入，不是重构任务清单——每个类别的处置方式（重构/适配/冻结）由本规格给出边界，由后续战役按 D1 五步协议实施。

**边界**：只分析 modularity 业务面；framework/infrastructure/application 不纳入（第三方/框架边界）；不改任何代码。

### 2.3 关键事实

- **174 纯实体文件不构成数据访问耦合**（实体映射是 ORM 契约的一部分）→ 真实耦合面 **229 文件**（403-174）；
- 229 中：Service/Manager/Helper 业务文件为主（118 Service 含会话直查）——S2 改造主体；
- `DataBaseManager`（基础设施）：会话工厂 + 租户切库 + 7 种数据库方言 SQL 模板 + 条件注入链（dataRuleJson/querJson/superQueryJson/dataPermissions）——S2 核心保留面；
- 参数化纪律良好（字符串 SQL 多为方言模板/受控拼接，hook L0 守护）。

## 3. 语义分类框架

| 类 | 定义 | 判定规则 | 数量 |
|----|------|---------|-----:|
| **E 实体契约** | 纯实体声明（SugarTable/SugarColumn 特性），无查询逻辑 | 仅含实体特性；不含 Repo/Client/Queryable/Ado/RawSql | 174 |
| **R 数据访问实现** | Repository/仓储层实现（IRepository 消费），封装 ORM 操作 | 文件含 IRepository/ISqlSugarRepository 且非纯实体 | 计入 229 |
| **B 业务查询** | Service/Manager/Helper 中直接链式查询（Queryable/AsSugarClient 会话直查） | 类名 Service/Manager/Helper 且含 Queryable/Client 模式 | 118（Service 会话直查） |
| **P 权限查询** | 数据权限/条件模型构造与消费链（GetCondition*/ConditionalModel/AppendTokenStrategy） | 与 UserManager.GetCondition 链路相关 | 见 P0-B（≤10） |
| **I 基础设施** | 会话工厂/租户切库/事件总线/缓存等横切 | DataBaseManager/TenantManager 等 | ≤10 |
| **S 特殊 SQL** | Ado 原生执行、多库方言 SQL 模板、受控拼接 | .Ado.SqlQuery/GetDataTable/ExecuteCommand + 字符串 SQL 字面量 | 19 原生 + 59 字面量（部分重叠） |

> 分类以文件为主键；混合类文件（如 DataBaseManager = I+S）取**最高类别**登记并标注混合。数量为机械统计 + 抽样语义验证（DataBaseManager/PortalService/CodeGenWay 已抽样）。

## 4. 处置裁决（S2 边界）

### 4.1 S2 前必须重构（改造面，**不是**立即重构清单）

| 子面 | 对象 | 理由 | 处置 |
|------|------|------|------|
| B-P 交集 | 数据权限条件构造/消费链（路径 A+B） | 语义必须在抽象后保持（P0-B 关联） | 先特征保护（P0-B），再随 S2 适配 |
| B 核心链路 | `RunSqlCompiler.GetListQuerySql/GetQueryJson`、`DataBaseManager` 条件注入链（563-566 行） | S2 抽象的直接目标 | S2 设计期以适配器重构，特征前置 |
| B 其余 | 118 Service 会话直查 | 量大（118）但行为面分散 | **S2 设计期分层适配**（抽象接口+迁移波次），禁止机械提前拆 |

### 4.2 必须保护/冻结

| 面 | 对象 | 保护方式 |
|----|------|---------|
| I 基础设施 | DataBaseManager/TenantManager/会话工厂 | 冻结（P0-C 不变量规格固化语义）；S2 抽象保留原语义 |
| P 权限查询 | GetCondition 双路径 | P0-B 特征金标准（与 D1.5 路径 A 同款） |
| E 实体契约 | 174 实体文件 | 冻结（实体映射随 ORM 契约走，S2 不迁移） |
| S 特殊 SQL | 19 Ado + 59 方言模板 | 冻结 + 登记（多库兼容层是 S2 适配器的输入，不是改造面） |

### 4.3 不属于 S2

- E 实体契约（174）
- framework/infrastructure/application（框架/宿主/第三方边界）
- `zxdev` 模块 1 处 `$"SELECT` 插值（P3，另立）
- Entitys/Interfaces 项目中的接口定义（151 文件中的接口部分）

## 5. 与 P0-B/P0-C 的关系

| P0 | 关联 |
|----|------|
| P0-B（第二权限路径） | 本规格 B-P 交集的保护前置；路径 B 特征金标准完成后回填本规格 §4.1 |
| P0-C（租户/权限不变量） | 本规格 I 面冻结的规格化；DataBaseManager 语义 → 不变量清单 |

## 6. 实施计划（摘要，详见计划文档）

1. 本规格批准 → P0-B（第二权限路径特征保护）→ P0-C（不变量规格）→ 三 P0 齐备后**重新 S2 Readiness Review**；
2. S2 设计阶段以本规格 §4 边界图为输入产出《数据访问抽象架构规格》（适配器策略/迁移波次/接口契约）；
3. 任何改造均按 D1 五步协议（特征金标准前置），禁止机械任务化。
