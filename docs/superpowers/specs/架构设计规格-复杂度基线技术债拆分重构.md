### 2.1 ListSuperQueryInputRewriter.Rewrite（CC 84）

**位置**：`backend/modularity/visualdev/JNPF.VisualDev/Query/ListSuperQueryInputRewriter.cs`（252 行）

**现有职责**：将 VisualDev 列表高级查询入参 `superQueryJson`（设计器信封形态）改写为面向 `ConditionalModel` 的查询条款列表 JSON（数组字符串），供 `GetQueryJson` 合并进列表查询条件。

**输入/输出契约**：
- 入参：`string? superQueryJson`。信封形态 [已知]：顶层字典的**首个 KV 值**=组间逻辑（"AND"/"OR"，大小写不敏感），**末个 KV 值**=条件组列表；每组的首个 KV 值=组内逻辑，末个 KV 值=条件项列表；条件项含 `jnpfKey/field/symbol/fieldValue/format` 等键。
- 返回：`string`。空/空串输入 → `string.Empty`；无条款产出 → `"[]"`；正常 → `queryList.ToJsonStringOld()`（Newtonsoft 默认设置，枚举数值化，键名 `whereType/where/jnpfKey/field/fieldValue/ConditionalType/CSharpTypeName`）。
- 无副作用（纯函数），不触 DB/DI。

**主要复杂点**：① symbol 主 switch 11 case（~CC14）；② `in/notIn` 列表展开嵌套块（`[[`/单层双形态 × 控件特判 × 逐 id 条款 × notIn 双条款，~CC22）；③ 空值短路两支（~CC8）；④ 值形态 switch：DATE/CREATETIME/MODIFYTIME/TIME/RATE/SLIDER（~CC9）；⑤ fieldValue 归一化三分支（~CC7）；⑥ 骨架三层循环+双 whereType+firstItem+between 捕获（~CC12）；⑦ 怪异比较（~CC4）。

**行为不变量（重构必须逐条保持）**：

| # | 不变量 | 性质 |
|---|--------|------|
| I1 | 输出键名集合与枚举数值化序列化形态逐字不变（下游 `Utilities.JsonToConditionalModels` 按此解析） | 硬契约 |

| I4 | DATE 族：between 时时间戳对转日期字符串写回 between[0]/[1]，非 between 单值转换；均标注 `CSharpTypeName="datetime"`；TIME 按 `format` 格式化；RATE/SLIDER 标注 `decimal` | 行为 |

| I8 | 【怪异】`ContainsKey("fieldValue").Equals("[]")` 恒 false（bool vs string），实际等价 `!ContainsKey` —— 保真保留 | 怪异（Q1） |
| I9 | 【怪异】COMSELECT/CURRORGANIZE 展开的每个 id 追加 `"]` 字符串（半残 JSON 形态，下游按此解析）—— 保真保留 | 怪异（Q2） |

|---|--------|------|
| I1 | 8 个直映 QueryType → ConditionalType 对应关系与追加形态逐字不变 | 硬契约 |
| I2 | Between：有 between 时追加 GreaterThanOrEqual + **And** + LessThanOrEqual 双条款并返回 true；无 between 返回 false 不追加 | 行为 |
| I3 | Null：fieldType ∈ {double,int,bigint} → EqualNull，否则 IsNullOrEmpty | 行为 |
| I4 | In/NotIn：值含 `[` 时嵌套数组拍平逐 id 展开（Like/NoLike；whereType 序列规则与 Rewrite I6 同构但 logic 参数源不同）；NotIn 追加 `FieldValue="null"`（字符串）与空串两条 IsNot；返回 true | 行为+怪异（Q11） |
| I5 | 【怪异】In/NotIn 值不含 `[` 时回退追加 **Equal** 条款返回 false（语义偏移，现状如此）—— 保真 | 怪异（Q10） |
| I6 | default 分支返回 false 不追加 | 行为 |

**依赖**：`SqlSugar.ConditionalType/WhereType`、`QueryType`（JNPF.Common.Enums）。无 DI/DB。**注意：位于多租户数据权限核心链路，回归权重最高。**

## 3. 跨方法机制：路由 zero-diff 与行为不变的保持方式

1. **特征前置原则**：每方法重构前先把「当前实现的全分支输出」捕获为金标准用例（含怪异分支）；重构只做结构搬移，断言逐字比对。任何比对失败 = 结构搬移引入了语义偏移，立即回退（见计划 §0 失败分类）。
2. **签名薄门面**：公共入口签名逐字不变 → 8 处调用方零 diff → 编译产物调用面不变。
3. **路由快照联动**：Rewrite/Bind 位于 `api/visualdev` 查询链路，每方法验收时重跑 `JNPF.Startup.Benchmarks --mode routes --filter "api/visualdev"` 与 `s0` 基线比对，要求 zero diff（不修改基线）。
4. **全量回归联动**：每方法验收跑所属测试项目全量（VisualDev 218 / Common 套件）+ 全解 `/p:CI_BUILD=true`。
5. **序列化层锁定**：涉及 JSON 输出形态的比对一律用 `ToJsonStringOld()` 原文（与生产链路同一序列化器），避免序列化器差异造成的假阳性。

## 4. 提交边界与回滚边界（逐方法统一）

**提交边界**（每方法恰好一个提交，R5）：
- 仅含 4 类文件：① 该方法源文件（拆分）；② 对应测试文件（新增特征用例）；③ `complexity-baseline.json`（移除该条目）；④ `.claude/TECH-DEBT.md`（对应行销账标记）。
- 禁止混入：其他方法文件、会话噪声（`.session-*.json`/`mistake-log.md`）、DLL 化战役文件、`.agents/`、S1 证据文件。
- 消息格式：`refactor(D1): <类.方法> 拆分（CC<旧>→门面<新>，子方法≤<n>；基线销账）`。

**回滚边界**（三类失败，三种处置）：

| 失败类 | 场景 | 处置 | 边界 |
|--------|------|------|------|
| F1 | S1 特征用例在当前实现上失败 | 属夹具/用例构造错误（实现即金标准） | 修用例不修实现；未提交，无回滚成本 |
| F2 | S3 等价验证失败（拆分引入语义偏移） | 未提交 → 丢弃工作区变更；已提交 → `git revert <单提交>` | 基线条目与代码同提交变更，revert 自洽恢复冻结态 |
| F3 | S4 销账后 CI 仍报 JNPF009（目标未达） | 继续拆分直至达标；**禁止**以重登基线/放宽目标绕过 | 若确无法达标 → 停止，走规格偏差登记报批，不擅自放宽 |

**中间态无 CI 破窗**：重构期间基线条目保持冻结值不动，直到该方法 S3 全绿才在 S4 同一提交内销账。
