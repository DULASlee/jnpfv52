**姊妹文档**：《总体实施计划》（`docs/superpowers/plans/MASTER-JNPF后端重构与Aspire微服务化总体实施计划.md`）

## ⚡ 路线记忆卡（每次开工前必读）

> **我们不是重新设计 JNPF。我们是在现有 JNPF 上进行拆分和优化。**
>
> **主线**：摸底建安全网(S0) → 家底定稿(S1) → 表级螺旋 → 类级螺旋 → 模块级螺旋 → 服务化与 Aspire 注册 →（必要时，凭专项规格）数据隔离
>
> * 工作对象永远是具体的东西：一张表、一组类、一个模块、一个服务——不是抽象的"架构"
> * 验收靠客观证据：测试全绿、依赖图、编译通过——不靠"边界看起来清晰"
> * 模块边界从表级和类级的事实中涌现，不从设计图中猜测
> * 裁决点只在不可逆操作之前；其余工作以 PR 证据放行
> * 数据库：只读分析可以早做，结构改造必须最后
> * 不预设微服务数量；不删除未知/遗留数据；Demo/Template/Customer 数据不得污染判断
> * AI 执行一切可逆小步，人类裁决一切不可逆操作
> * 每一圈结束复盘一次；首批 10–20 张表完成后强制复盘方法论本身

## 1. 项目总目标

本项目不是重新开发一个新的 JNPF，也不是重新设计一套数据库。

### 唯一总目标

> **以现有 JNPF 后端为唯一事实基础，在保持现有业务行为、数据兼容性和平台能力连续性的前提下，通过持续重构、模块化、物理程序集拆分、契约解耦和渐进式部署隔离，最终形成以 Aspire 为运行编排基础的微服务化 JNPF 后端。**

演进路线（v2.0 改写为螺旋）：

```text
现有 JNPF
   ↓ S0 摸底与安全网（构建/测试基线 + 行为特征考卷 + 遗留登记册）
   ↓ S1 平台家底定稿（157 进入 / 132 处置冻结 + 数据所有权档案）
   ↓ 第一圈 表级螺旋（逐表：字段 / 外键 / 索引 / CRUD 收敛）
   ↓ 第二圈 类级螺旋（逐聚合：消环、合并、提公共、敛入口）
   ↓ 第三圈 模块级螺旋（逐模块：接口、数据访问隔离、独立启动验证）
   ↓ 服务化水到渠成（达标即服务，Aspire 只做注册编排）
   ↓ （必要时，凭专项规格）数据库物理隔离
```

## 2. 核心原则

### P1 不重新设计 JNPF

禁止"重新定义一个 JNPF Next Domain Model"。目标是拆分和优化现有 JNPF。

### P2 数据库：分析前置，改造殿后

数据所有权、事务边界、跨域读写的**只读分析**是模块化的输入，尽早开始；数据库的**结构改造与物理隔离**是模块成熟后的结果，最后做，且必须先有专项规格。

### P3 表名只是线索

表名可以作为初始线索，但单独的表名永远不构成领域判断依据；必须结合代码引用、数据流、所有权等多维证据。（`ext_order` ≠ Order Domain 的历史教训永久有效。）

### P4 Aspire 是注册与编排基础设施

服务化达标后由 Aspire 注册运行；它不参与"该不该拆"的判断。

### P5 边界从事实中涌现

领域模型、事务边界、模块边界不是设计出来的，是在表级和类级的事实积累中浮现的。禁止在没有事实支撑时输出"模块地图"式的猜测文档。

### P6 人机分工：可逆 vs 不可逆

AI 直接执行一切**可逆小步**（加索引、标记废弃、提取方法、收敛内部调用、移动文件、重命名符号），以 PR 中的证据放行；人类只裁决**不可逆操作**（删除数据、拆分表、改变外键约束、修改公开 API 签名、下线服务）。

```text
可逆：Evidence → Agent Action → PR 证据
不可逆：Evidence → Human Decision → Freeze → Agent Execution
```

## 3. 方法论总纲：对象驱动的五步螺旋

旧管线的根本病灶：工作在架构层面（模块地图、契约层、物理边界），而**架构层面的判断无法自我验证**——"边界清晰了吗"只能靠人的品味回答。新方法论把工作对象换成可以被机器验证的具体东西：

```text
五步螺旋：观察 → 判断 → 行动 → 验证 → 下一个对象
   观察：扫描该对象的全部事实（结构、引用、调用路径）
   判断：对照事实列建议，每条标注【证据 → 建议 → 风险级别】
   行动：只做可逆小步，产出代码 diff
   验证：回归考卷全绿 + 该对象的行为测试（索引变更另附性能对比）
   下一个：换对象，重复
```

**对象随圈升级：单张表 → 一组聚合（相关表 + 操作它们的类）→ 功能模块 → 独立服务。**

通用纪律：小步可逆；每步带 diff 与测试证据；任何时刻仓库可编译、可发布；行为特征考卷是所有圈共用的验收工具。

## 4. S0 — 摸底与安全网（一次性前置）

**做什么**：不动业务代码，建立六类基线工件（均带具体路径与版本号）：

| 工件 | 位置/形式 |
|---|---|
| Architecture Baseline | `docs/architecture/baseline/architecture-snapshot.v1.md`（项目依赖图快照 + 复杂度基线指针） |
| Build Baseline | Release 与 CI_BUILD 构建输出快照 |
| Test Baseline | 现有测试清单 + 通过率快照 |
| Runtime Baseline | 启动冒烟 + 核心 API 行为快照 |
| Compatibility Baseline | **行为特征考卷** `tests/characterization/`（≥30 条起，随后跟随手术面扩展） |
| Legacy Compatibility Registry | `docs/architecture/legacy-compatibility-registry.v1.md`（KEEP/REDEFINE/DEPRECATE/REMOVE 四态） |

**行为四分层政策**：
- 核心业务行为：冻结，考卷保护，不绿不通过；
- 边缘行为：允许调整，调整须登记；
- 未定义行为：自由处理；
- 已知 bug：走修复通道，配新回归用例证明预期行为——不固化为"兼容"。

**完工标准**：六工件存在且版本化；构建/测试/工具链/hooks 校验全绿归档；考卷入 CI；冒烟快照归档。

## 5. S1 — 平台家底定稿（一次性前置，可与 S0 并行）

**做什么**：整合既有审计成果定稿，零新增考古。

**交付**：`docs/architecture/platform-asset-inventory.v1.md/.csv`（157 张平台表进入 / 132 张处置冻结表：模板打包、Demo 剥离、客户与历史归档，零删除）；**数据所有权档案**——《JNPF数据责任与模块边界映射主表》升格为逐模块档案，作为表排序与后续所有圈的输入。

**完工标准**：289 = 157 + 132 复算一致；Provenance 三态统计重跑一致；处置冻结表获人工签收。

## 6. 第一圈 — 表级螺旋

**对象与排序（防分析瘫痪）**：范围 = 157 张平台资产表。顺序按依赖深度优先：

```text
① 叶子表（不被其他表引用：日志、配置、附件类）
② 无外键表
③ 单模块独占的私有表（依据数据所有权档案）
```

首批只做 10–20 张，跑完**强制复盘**节奏与产出质量，再决定全量推进。

| 步 | 做什么 | 产出 |
|---|---|---|
| 观察 | 扫描该表：字段定义、外键关系、索引现状、所有引用它的代码（CRUD 路径） | 表级事实卡 |
| 判断 | 字段冗余/废弃？外键合理？索引缺失或重复？CRUD 是否都经过正确的类？ | 优化建议清单（每条：证据 → 建议 → 风险级别） |
| 行动 | 加索引 / 标记废弃字段 / 补正外键 / 提取公共 CRUD 方法（**不删数据、不拆表**） | 代码 diff + 迁移脚本 |
| 验证 | 考卷全绿 + 该表 CRUD 行为测试（+ 性能对比） | 测试报告 |

**优化边界（防止"优化"变成无限工程）**：

- **字段**：只标记废弃、修正类型错误、补充缺失约束。不新增字段、不改含义、不合并。
- **外键**：只为有代码证据的强依赖补物理外键；移除无代码引用且无数据的冗余外键。不改业务含义。
- **索引**：只按 CRUD 代码里真实的 WHERE 条件补索引；移除重复索引。不为想象中的查询建索引。
- **CRUD**：只收敛路径、提取公共方法。不改变业务行为。

**本圈的真正产出**（比"表变好了"更重要）：① 157 张事实卡全集——此前只有清单，没有事实；② 表级 CRUD 路径显式化——谁读写这张表一目了然；③ 公共 CRUD 方法沉淀——Repository/Service 雏形；④ 经外键与代码引用双重精确化的表间依赖——后续所有圈的地基。

## 7. 第二圈 — 类级螺旋

**对象**：聚合 = 一组内聚的表 + 操作它们的类。表级螺旋完成后，类与表的映射自然浮现，操作单元随之升级。

| 步 | 做什么 | 产出 |
|---|---|---|
| 观察 | 哪些类共同操作哪几张表？类之间怎么调用？有没有循环依赖？ | 聚合边界图（类 → 表 → 类调用关系） |
| 判断 | 哪些类在做同一件事（应合并）？哪些做得太多（应拆分）？哪些公共逻辑散落多处（应提取接口/基类）？ | 重构建议清单 |
| 行动 | 提取公共类/方法/接口、消除循环引用、收敛 CRUD 入口 | 代码 diff |
| 验证 | 考卷 + 依赖环检测 + 架构测试 | 测试报告 |

**本圈真正产出**：干净的聚合边界图与调用结构。**领域模型与事务边界在这里浮现**——这是与旧管线"第二阶段凭空画模块地图"的本质区别：边界不再是被设计的猜测，而是被事实支撑的结论。

## 8. 第三圈 — 模块级螺旋

**对象**：功能模块（由一组聚合组成）。此时拥有的不是猜出来的边界，而是事实支撑的边界。

| 步 | 做什么 | 产出 |
|---|---|---|
| 观察 | 这个模块对外暴露了什么？谁调用它？启动时需要什么？事务边界在哪里？ | 模块事实卡 |
| 判断 | 它能独立运行吗？数据能独立吗？调用方能通过接口通信吗？ | 服务化评估表——答案不是"能/不能"，而是"缺什么" |
| 行动 | 定义接口、隔离数据访问、消除静态依赖 | 代码 diff |
| 验证 | **独立启动测试** + 行为回归 | 测试报告 |

**服务化标准的涌现**：「这个模块能否在不修改任何调用方代码的情况下独立启动运行」——答案来自事实，不需要人拍脑袋裁决。

## 9. 终点层 — 服务化与 Aspire 注册

某模块第三圈完成后，若满足：**独立启动测试通过 + 数据独立 + 调用方已走接口 + 回归全绿**——它在事实上已经是服务。Aspire 在这里的工作只剩**把它注册进运行环境**，不存在"要不要服务化"的重大设计决策。未达标的模块继续留在模块化单体中——合法结论，随事实变化可重评。

**数据库物理隔离**：仅对确需独立库的服务执行；先出《数据隔离专项规格》（双写机制、历史数据搬迁、新旧库并存期读取策略、cutover 与回退方案），十问（谁拥有/谁写/生命周期/事务/谁读/跨域访问/迁移/回滚/旧数据/失败恢复）逐项回答后方可动工。

## 10. 治理层

**裁决点 = 不可逆操作清单**（此前必须人工确认）：
删除数据；拆分/合并表；改变外键约束；修改公开 API 签名；删除表或文件；服务下线。

**预授权清单**（直接执行，PR 中展示证据即可）：
加/删索引；标记废弃；提取公共方法；收敛内部调用；模块内移动文件；重命名内部符号；补充测试。

**复核分级与时间盒**：圈内任务 AI 自检 + 证据留档（抽查不全批）；每圈出口开人工复盘会，议题与结论限定三选一（PASS / 调整 / 扩围），不允许开放式打磨；首批 10–20 张表完成后强制方法论复盘。

**失败预案**：
① 后面的圈发现前面的判断错了 → 按波次 git 标签回退，更新事实卡后再前进；
② 考卷大面积变红 → 全线停、回退到最近标签、根因分析闭环后才准继续；
③ 某模块始终无法通过独立启动测试 → 正式登记留驻单体，写入评估表存档——这也是有效产出。

**八禁（v2.0 措辞）**：
1. 禁止无专项规格重新设计数据库结构；
2. 禁止"创建新的 JNPF Next Domain Model"式重写；
3. 禁止为了微服务而拆微服务；
4. 禁止因为用了 Aspire 就预设 N 个服务；
5. 表名只能作为初始线索，禁止单独作为领域判断依据；
6. 未经人工裁决与备份验证，禁止删除任何存在数据的表；
7. 禁止照抄遗留实现缺陷；正确业务规则必须保留行为、实现允许重写；已登记移除的怪癖不复刻；
8. 禁止一次性完成 Monolith → Microservices。

## 11. 完成定义

- **最小成功**：157 张事实卡全覆盖；核心聚合完成第二圈；全部模块持有事实卡与服务化评估表；系统以模块化单体形态稳定运行于 Aspire；考卷持续全绿。
- **完整成功**：评估表判定"具备条件"的候选全部完成独立部署并稳定运行；确需者的数据隔离完成并通过影子验证。
- 工程在任何一圈之后停下，都留下一个比之前更干净、可发布、可验证的系统——**不存在烂尾状态**。
