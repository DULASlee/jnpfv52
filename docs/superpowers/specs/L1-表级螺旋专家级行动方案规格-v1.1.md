## 0. 文档定位、技术栈与边界裁决

### 0.1 与 L1 执行手册的关系

| 文档 | 职责 |
|---|---|
| **L1 执行手册**（plans/） | 排序算法、批次节奏、五步流程、A/B/C 分级定义、熔断阈值（§7）、C 级裁决会（§6）、性能协议（§5）、快照协议（§4） |
| **本规格**（specs/） | 每个维度的技术专项定义、SqlSugar 落地手段、触发条件、分级映射、产出物模板 |

**裁决规则**：本规格不拥有独立的风险定级权。所有专项的 A/B/C 级以手册 §3② 为唯一源；本规格逐条映射（§7 汇总表），映射存疑时以手册原文为准并在复盘会提出修订。

### 0.2 与 MASTER「优化边界」红线的对齐（关键裁决）

MASTER 规格 §6 规定表级螺旋字段边界为"只标记废弃、修正类型错误、补充缺失约束；**不新增字段**、不改含义、不合并"。本规格中以下动作与"不新增字段"存在张力，裁决如下：

| 动作 | 裁决依据 | 执行条件 |
|---|---|---|
| ROWVERSION 并发列（C4） | 手册 §3② 已裁为 **B 级**，即 MASTER 边界的预授权例外 | 数据体检报告 + 每表一个 PR |
| 持久化计算列（C6） | 手册 §3② 已裁为 **B 级** | 同上 |
| 多值字段拆分关联表（B4） | 手册 §3② 已裁为 **C 级** | 上裁决会，迁移+回滚脚本先行 |
| 查找表新建（B5） | 手册 §3② 未列 → **映射为 C 级**（新增表超出 B 级授权面） | 上裁决会 |
| 大表归档表（F3） | 新增表 + 数据搬迁 → **C 级** | 上裁决会 |

**除上表五项例外，一律不得新增字段/列/表**。所有结构变更走编号迁移脚本，禁止手工 ALTER（手册 §3③）。

### 0.3 收益声明纪律（硬规则）

> 引用手册 §5：**没有存档号的收益数字一律无效**。

- 本规格所有示例中的性能数字仅为格式演示，标注 `（待实测）`；
- 正式产出物中收益栏必须填 `§5 存档 #N`（STATISTICS IO/TIME 文本存档编号或 .sqlplan 文件名）；
- 未实测的收益声明在验证步（手册 §3④）直接判不合格。

## 1. 判断步决策表：事实卡 → 触发条件 → 技术专项

观察步产出七项事实卡（手册 §3①），判断步按下表选中专项，产出行动台账（每条标 A/B/C 级）：

| 事实卡项 | 观察信号 | 触发专项 |
|---|---|---|
| ① 列清单（INFORMATION_SCHEMA 实测） | 类型与语义不符 / NULL 泛滥 / MAX 超长 / 大小写拼写变体 | B1–B8 |
| ② 索引现状＋碎片率 | 缺索引 / 低选择性 / 列序不匹配 / CONVERT_IMPLICIT / 碎片>30% | A1–A8 |
| ③ 物理外键与逻辑关系 | 代码手动删子表 / 无 FK 但总同事务出现 | C4、C5、E5 |
| ④ 引用代码位置（Serena+文本双通道） | 循环查询 / 全实体加载 / OFFSET 深页 / 同步阻塞 | D1–D8 |
| ⑤ 读写方模块 | 多写者 / 缺租户过滤查询 / 全局过滤改动 | F2、手册 §7 熔断第 4 行 |
| ⑥ 行数与关键列分布 | 重复率 / 值域违规 / 行数>10 万无归档 | C1、C2、F3、B3 |
| ⑦ 事务边界与慢查询 | 事务包裹 HTTP/文件 I/O / 缺失事务 / 执行计划劣化 | D4、D1、F4 |

**反向裁决同样合法**：判断步结论可以是"本表不做任何行动"。例：`base_api_log` 首批发现为只写不读僵尸表 → 重构索引无收益，行动台账应为"归档策略评估（C 级）+ 索引仅做低选择性清理（A 级）"，而非强行套用全部维度。

## 2. 维度 A：索引策略深度重构（8 项）

| # | 技术 | 具体做法（SqlSugar/SQL Server） | 触发条件 | 级 | 前置体检/熔断 |
|---|---|---|---|---|---|
| A1 | 覆盖索引设计 | 分析高频查询（事实卡④+慢查询日志），建 `(过滤列…) INCLUDE (投影列…)`，消除 Key Lookup | 高频查询回表代价高 | A | 无 |
| A2 | 复合索引列序优化 | 按选择性（Cardinality）与查询模式重排列序；等值列在前、范围列在后 | 现有列序与查询不匹配 | A | 无 |
| A3 | 过滤索引 | `CREATE INDEX … WHERE F_tenant_id = @x AND is_delete = 0` 类小热集 | 90% 行从不被查询 | A | 注意参数快照需同形谓词命中 |
| A4 | 索引选择性评估与清理 | 唯一值/总行数 <0.1 且无覆盖用途 → 删除 | 低效索引存在 | A | 无 |
| A5 | 隐式转换消除 | **改查询端**（SqlSugar 参数类型对齐列类型；实体属性类型修正后再生成 SQL）；执行计划 CONVERT_IMPLICIT 为证据 | 计划含 CONVERT_IMPLICIT | A（查询端）/ **C**（改列即 ALTER COLUMN） | 无 |
| A6 | 碎片化治理 | 碎片>30% → REORGANIZE；>50% 且低峰窗口 → REBUILD；写入维护作业 | 事实卡②碎片率 | A | 大表 REBUILD 须评估锁窗口 |
| A7 | 填充因子调优 | 高频写入表 FILLFACTOR 70–90，减少页分裂 | 页分裂计数高 | A | 无 |
| A8 | 索引压缩 | 大表（>100 万行）启用 PAGE 压缩（需 Enterprise 版；先验版本） | 行数大且压缩收益明显 | A | 收益须 §5 实测（CPU 换 I/O，可能负收益） |

## 3. 维度 B：字段级深度优化（8 项）

| # | 技术 | 具体做法 | 触发条件 | 级 | 前置体检/熔断 |
|---|---|---|---|---|---|
| B1 | 类型语义修正 | varchar('true'/'false')→BIT、日期字符串→DATETIME2、金额 FLOAT→DECIMAL(18,4)。**属 ALTER COLUMN 语义类型变更** | 类型与数据语义不匹配 | **C** | 值域 100% 可转换实测报告 + 回滚脚本 |
| B2 | NOT NULL + DEFAULT | 逐列判定 NULL 语义（"未知"保留 NULL / "漏填"补约束） | 插入必带固定值 | B | NULL 存量清洗方案先批 |
| B3 | 长度策略 | NVARCHAR(MAX) 实测长度分布后改精确长度 | MAX 但实际 ≤ 若干 KB | **C**（MAX 缩容） | 熔断：缩容目标 < 现存最大长度 → 直接否决（手册 §7） |
| B4 | 消除多值字段 | 逗号分隔值（如 base_schedule_log 的重复星期/月份字段，首批已证实违反 1NF）→ 拆关联表 | 频繁 LIKE '%v%' / STRING_SPLIT | **C** | 拆表=新增表，走裁决会 |
| B5 | 枚举标准化 | 拼写变体统一（UPDATE）→ B 级；改为数值枚举/查找表 → 涉 ALTER COLUMN + 新增表 → C 级 | 同字段多变体同义 | 统一=B / 换类型=C | UPDATE 前备份快照（手册 §3②） |
| B6 | Unicode 策略 | NVARCHAR→VARCHAR（全 ASCII 列） | 内容 100% ASCII 实测 | **C** | 存量非 ASCII 行扫描为零 |
| B7 | 时区语义显式化 | 同表混用本地/UTC → 统一策略（DATETIMEOFFSET 变更即 B1） | 事实卡①时间列抽查 | **C** | 存量数据换算脚本 + 回滚 |
| B8 | 软删除与查询对齐 | 盘点 `is_delete`/`F_DELETE_MARK` 全访问点，漏过滤清单化并补齐 | 有软删标记但存在未过滤查询 | A | 补齐属 A 级；若借道改全局过滤器 → 见 E3（C） |

## 4. 维度 C：约束与数据完整性（6 项）

| # | 技术 | 具体做法 | 触发条件 | 级 | 前置体检/熔断 |
|---|---|---|---|---|---|
| C1 | 业务唯一性约束 | "查重再插入"模式 → `CREATE UNIQUE INDEX`。先全表查重 | 代码有 SELECT-then-INSERT 防竞态 | B | **UNIQUE 先查重零重复才准加；重复率>1% 或 >100 行 → 熔断转专项（手册 §7）** |
| C2 | CHECK 约束 | 值域校验下沉（状态 BETWEEN、金额>=0） | ORM 大量 if 值域判断 | B | 违规扫描 >50 行或 >0.5% → 熔断 |
| C3 | 乐观并发控制 | 加 `ROWVERSION` 列；SqlSugar 侧 `SugarColumn(IsEnableUpdateVersionValidation=true)` 或更新语句 WHERE 带版本 | 读-改-写无并发保护 | B | 新列允许 NULL 过渡再回填 |
| C4 | 级联策略审计 | 每个 FK 的 ON DELETE 行为核对：代码手动删子表 → 评估 CASCADE/SET NULL | 删除主表前手动删多表 | **C** | 存量孤儿行清零后才准加 FK+CASCADE |
| C5 | 默认值下沉 | 常量插入值改 DB DEFAULT，SqlSugar 实体列标注可省略 | 多次 INSERT 重复常量 | B | 与 B2 合并执行 |
| C6 | 计算列 | 高频派生值（JSON 子属性等）建持久化计算列+索引 | WHERE 频繁用派生值 | B | §0.2 例外项；JSON 解析函数须确定性 |

## 5. 维度 D：CRUD 路径深度重构（8 项）

| # | 技术 | SqlSugar 落地做法 | 触发条件 | 级 |
|---|---|---|---|---|
| D1 | N+1 消除 | 循环 `Queryable<T>().Where().First()` → `LeftJoin` 单查询或 `Where(x=>ids.Contains(x.Id))` 批量；`Includes()` 的多跳子查询改显式 JOIN | 代码审查/慢查询发现循环单查 | A |
| D2 | 投影查询 | `.Select<TDto>(x => new TDto{…})` 只取所需列，配合 A1 覆盖索引 | 列表页加载全列 | A |
| D3 | 批量操作 | 循环单行 Insert → `InsertRange` + `Fastest<T>().BulkCopy()`；循环 Update → `Updateable().SetColumns(表达式).Where()` 集合成批 | 导入/批处理场景 | A |
| D4 | 事务边界精化 | `USETran` 块内剔除 HTTP/文件 I/O/LLM 调用；缺失事务的多表写补齐；隔离级调整单列评估 | 事务含外部调用/部分成功 | A（剔除/补事务）/ B（改隔离级） |
| D5 | 参数化审计 | 裸 SQL 全量盘点。**已由 L0 钩子 guard-sql-injection.mjs 硬拦**（手册 §8），本节仅管存量：`Ado.GetDataTable($"…{value}")` 拼接 → `SqlSugarFilterable`/`SqlParameter[]` | 存量拼接（钩子前遗留） | A |
| D6 | 分页策略 | OFFSET/FETCH 深页 → Keyset（`WHERE id > @lastId ORDER BY id` 游标式）；SqlSugar `ToPageList` 深页场景改造 | 深分页响应慢 | A |
| D7 | 异步化 | 数据访问改 `ToListAsync/FirstAsync/ExecuteCommandAsync`，释放线程池 | 高频表仍同步阻塞 | A |
| D8 | 大结果集护栏 | ~~AsNoTracking~~（v1.0 术语错误，SqlSugar 无变更跟踪，不适用）。替代专项：无界 `ToList()` 盘点加分页上限；禁 `ToDataTable()` 全表拉取；导出走 `Fastest` 流式 | 无界查询存在 | A |

## 6. 维度 E：ORM 映射质量重构（5 项，SqlSugar 校正版）

| # | 技术 | SqlSugar 落地做法 | 触发条件 | 级 |
|---|---|---|---|---|
| E1 | 导航属性审计 | `[Navigation]` 属性使用情况盘点：从未使用 → 移除；滥用 `Includes()` 造成多跳子查询 → 改显式 JOIN（D1） | 定义未用 / Includes 高开销 | B（增删，手册 §3②） |
| E2 | 值与类型映射 | 枚举属性 SqlSugar 原生映射 int/string；JSON 列用 `IsJson = true`；消除字符串手拼枚举比较 | 属性是 string 但语义是枚举 | B（配合 B5） |
| E3 | 全局查询过滤器 | 软删/多租户过滤统一挂 SqlSugar `GlobalQueryFilter`；JNPF 现由 `SqlSugarFilter`/`ITenantFilter` 体系承载。**改动全局过滤器 = 全域行为变更**：PR 必须附 `ToSql()` 实际输出（手册 §8 红线 R4 陷阱 13） | 大量查询手写重复 WHERE | **C**（全局改动上会）；单查询补过滤 → B8（A） |
| E4 | 客户端生命周期 | ISqlSugarClient 注册核查：必须 Scoped/按请求；发现 Singleton 共享或跨线程复用 → 修复 | DI 注册表扫描（F1 工具顺带） | A（查）/ B（改注册） |
| E5 | 实体-schema 漂移 | `[SugarTable]`/`[SugarColumn]` 声明 vs INFORMATION_SCHEMA 实测比对（活案例：首批 PROCESSED_EVENT 建表名与运行时实体 SYS_PROCESSED_EVENT 不一致） | 注解与实际列缺失/多余/类型不符 | A（查产清单）/ B（改注解）/ **C**（改 DB 列） |

## 7. 维度 F：SqlSugar / 低代码平台专属专项（5 项，v1.1 新增）

通用 DBA 手册没有、但对 JNPF 最能改变系统质量的一项：

| # | 技术 | 具体做法 | 触发条件 | 级 |
|---|---|---|---|---|
| F1 | CodeFirst-schema 漂移检测工具 | 脚本遍历 `EntityClassName.*Entity.cs` 的 SugarTable 注解 vs DB sys.tables/columns，输出漂移清单入事实卡；**每表观察步必跑** | L1 常态化能力 | A（纯读） |
| F2 | ITenantFilter 挂靠点验证 | 该表全部查询逐点验证租户过滤生效（ToSql 证据存档）。活案例：首批 base_print_log R4 租户陷阱 | 事实卡⑤ | A（查）/ 补单点过滤=A / 动全局过滤器=C（E3） |
| F3 | 大表归档 / 分区策略 | 日志流水表（首批核心发现：BASE_SYS_LOG 12615 行**无归档机制**）制定冷热分离：归档表 + 迁移作业 + 保留窗口。L1 主战场是真痛点 | 行数增长快且无保留策略 | **C**（数据搬迁+新增表） |
| F4 | 统计信息健康核查 | AUTO_UPDATE_STATISTICS 开关核查、`STATS_DATE` 陈旧度扫描；大表（BASE_SYS_LOG 级）纳入定期 `UPDATE STATISTICS` 作业 | 计划劣化于索引存在时 | A（查）/ B（维护作业） |
| F5 | 动态表（MT_*）运行时 DDL 治理 | 低代码独有：用户建模产生的动态表如何纳入索引/约束治理——定义平台级治理边界（哪些运行时建表自动加标准索引/租户列约束），避免每表人工螺旋覆盖不到的死角 | MT_* 表访问量上升 | **C**（平台级机制） |

| 状态值域 | 代码 if 判断 | CHECK | B | 违规扫描（>50 行 → 熔断） |
| 乐观锁 | 无 ROWVERSION | 加列 + 更新 WHERE 带版本 | B（C3） | 允许 NULL 过渡 |
