## 3. DDD 实时推导器（不存储，渲染时计算）

**文件**：`Studio/DddProjection.cs`

**v2.0 核心：DDD 不再是 5 张表 + 5 个增强器，而是从 SA 产出 JSON 中实时推导的 5 个视角。**

```
推导逻辑（纯 C#，< 50ms，渲染时计算）：

视角 1 领域模型：
  输入：sa_er + sa_scope
  推导：Union-Find 聚类（外键密集→子域）+ 引用频次→核心域
  输出：{subDomains[], coreDomain} + confidence

视角 2 聚合设计：
  输入：sa_er + ai_entity_field（IsPrimaryKey）
  推导：1:N 强依赖→同聚合，PK 端=聚合根
  输出：{aggregates[], rootEntities[]} + confidence

视角 3 事件目录（简化版）：
  输入：sa_business_process + sa_dfd
  推导：BPM 节点→事件，DFD 流→输入/输出。timeline_order=null
  输出：{events[], dependencies[]} + confidence

视角 4 CQRS：
  输入：sa_pspec + sa_decision_table
  推导：改状态→Command，只读→Query，规则→前置条件
  输出：{commands[], queries[]} + confidence

视角 5 集成点（简化版）：
  输入：sa_dfd + sa_scope
  推导：SYSTEM→SYNC_API，其他→UNKNOWN
  输出：{integrationPoints[]} + confidence

全部标记 confidence，渲染到需求分析书 §3。
不写入任何物理表——是 SA 产出的"投影维度"，不是独立数据。
```

## 4. 需求分析书渲染器

**文件**：`Studio/RequirementDocumentRenderer.cs`

**纯确定性，无 LLM。每轮完整渲染（< 2 秒），不做增量优化。**

### 4.1 文档结构

```
封面（项目名/版本/日期/工程质量评分；若有则展示 PM 业务分）
1. 系统概述（sa_scope）
   1.1 系统边界 / 1.2 外部参与者 / 1.3 事件总览表
   1.4 轻量校验报告（Round 1 warnings 历史）
2. 业务事件详细分析（sa_dfd/bpm/pspec/decision_table/state_machine/ui）
3. 领域设计增强（DDD 实时推导 5 视角，含 confidence）
4. 全局数据模型（ai_entity_field，声明 3）
   4.1 全局数据字典 / 4.2 全局 ER 图
5. 一致性分析报告（sa_consistency）
6. 质量评估（sa_quality_score 工程分，含 DDD 维度）
附录
  A. 用户原始需求
  B. 三轮澄清问答完整记录（答案 MUST 进书，禁止只留 IR）
  C. PM 行业惯例补全记录
  D. 假设项详细列表（sa_assumptions，含 source_step/confidence）
末尾固定 CTA（与确认卡同一句，25 决策 10）：
  「请你确认需求分析说明书，如果同意，推进到下一工作阶段，如果不满意，请在输入框继续提出你的问题和要求。」
```

### 4.2 渲染规则

- §3 DDD 从 SA 产出 JSON 实时推导（DddProjection.cs）
- §4 数据模型从 ai_entity_field 读（声明 3）
- §4.2 ER 图从 ai_entity_field.References 推导
- DDD confidence：用户确认的标 ✓，未确认的标待确认
- **禁止**用弱提示替代固定 CTA；确认卡 hint 必须同文
- 工程分与 PM 业务分分开展示，禁止互相顶替

### 4.3 确认前续写与再渲染

用户在待确认态输入框补充需求时，由 27 **PM AmendAsync** 改 IR 后再次 Finalize；本渲染器 **全量重渲** 02。禁止本组件直接 LLM 改 Markdown。

## 5. 一致性检查器（LINQ + SQL 混合）

**文件**：`Gates/ConsistencyChecker.cs`

**第 3 轮一次性执行。**

```
规则 1 数据实体一致性（SQL）：
  sa_entity_fields VIEW 自 JOIN，同实体字段冲突 → CRITICAL/WARNING

规则 2 角色权限一致性（内存 LINQ）：
  sa_state_machine.roles_json，按 role 分组，TRIGGER+VIEW 共存 → WARNING

规则 3 流程闭环（内存 LINQ）：
  sa_dfd.flows_json，output - input = orphan → INFO

规则 4 假设项汇总（SQL）：
  sa_assumptions 未确认项去重汇总 → INFO

性能：< 250ms（15 事件）
```

## 6. 质量评分器（5 维度含 DDD）

**文件**：`Gates/QualityScoreCalculator.cs`  
**性质：工程质量分** → 写入 `sa_quality_score`。

```
综合评分 = 结构完整度×25% + 决策覆盖率×25% + 一致性×20% + 深度×15% + DDD增强×15%

DDD 增强（0-100）：
  从 DddProjection 实时推导结果计算：
  5 个视角各有数据（各 20 分），confidence < 0.5 减半

门控：综合 ≥ 60；结构 ≥ 70；无 CRITICAL
```

**与 PM 业务分关系（v2.1）：** 工程分 ≠ 交用户门槛；PM `RequirementSpecPmReviewed.score ≥ 85`（27）才交用户确认。二者不可互相顶替。

## 7. E2E 验收

### 7.1 LLM Mock 策略

```
Phase 1（Mock）：验证流程正确性，所有 LLM 返回预定义 JSON
Phase 2（真实）：真实 LLM，人工评审需求分析书
```

### 7.2 E2E 步骤

```
1. 用户提交需求（请假审批，3-5 事件）
2. S0 门控通过
3. Round 1：PM Enhance + PM 出题（MULTI/MATRIX）→ SA C# → 用户答
4. Round 2：联合精化 + PM 出题 → SA C# → 用户答
5. Round 3：PM 终审出题 → 用户答 → Finalize（投影/物化/一致性/工程分/渲染含 CTA）
6. PM ReviewSpec ≥85（或展示 gaps + 强制确认 / Amend；**无**自动再问）
7. 用户确认 或 输入框 Amend → 再 Finalize → 再评 → 再 CTA
8. 数据一致性：projection / 三元组
9. 工程质量：综合 ≥ 60 / 无 CRITICAL / 结构 ≥ 70
10. 业务交用户：PM ≥ 85；02 含固定 CTA 原文；附录 B 含答案
```

### 7.3 验收清单

```
□ 出题经 pm-skill；题型仅 MULTI/MATRIX
□ 附录 B 含澄清答案；末尾固定 CTA；确认卡同文
□ 工程分与 PM 业务分分开展示；PM≥85 才交确认
□ SA 九步 + DDD 5 视角 + 一致性/工程分
□ 前两轮零工程；Round 3 一次性保障
□ ai_entity_field 三元组完整 + 下游可消费
```
