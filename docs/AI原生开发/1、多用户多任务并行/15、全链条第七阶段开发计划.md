## 0. 阶段定位

**核心问题：** 如何**可度量**地证明 10 个 Skill 产出质量达标，并建立人工抽检与自动 Eval 闭环？

本阶段 **不写新业务 Skill**，聚焦 **Eval Pipeline + 质量治理 + 记忆遗忘**。

## 1. Eval Pipeline 四层（图 2-1）

```mermaid
flowchart LR
    E1[组件评估] --> E2[轨迹评估]
    E2 --> E3[任务完成度]
    E3 --> E4[端到端业务效果]
    E4 --> R[EvalReport IR 事件]
```

| 层 | 输入 | 输出 | LLM |
|---|---|---|---|
| L1 组件 | 单 Skill 产出 JSON Schema | pass/fail | 否 |
| L2 轨迹 | **ai_ir_events** 序列 | 冗余调用检测 | 否 |
| L3 任务 | DoD 脚本结果 | 完成率 | 否 |
| L4 业务 | 请假 E2E + Judge | 评分 0-100 | 是 fast |

**轨迹规则示例：** 同一 `skillId+runId` 内 `LlmCallStart` >3 且无 IR append → 告警 `RedundantLlmLoop`

## 2. 人工抽检

**流程：** 导师/QA 在 Studio 打开 Skill 产出 → POST `/api/studio/skills/review`  
**表 ai_skill_reviews：** F_SkillRunId、F_Score、F_Comment、F_ReviewerId  
**用途：** 校准 L4 Judge 偏差（每月 re-calibrate prompt）

---

## 3. Skill 质量排行榜

**指标（SQL 聚合）：**

```sql
-- 【示例】成功率
SELECT F_SkillId,
       SUM(CASE WHEN F_Status='completed' THEN 1 ELSE 0 END)*1.0/COUNT(*) AS success_rate,
       AVG(F_TokenConsumed) AS avg_tokens
FROM ai_skill_runs
WHERE F_StartedAt >= @since
GROUP BY F_SkillId;
```

**展示：** IR 观测台新 Tab「Skill 质量」【前端 P7-F01】

---

## 4. 记忆遗忘机制

**范围：** `ContextBuilderService` 缓存 + **ai_seed_templates** 命中历史  
**策略：** 保留分 = 访问频次 × 0.6 + 业务重要性 × 0.4；低于阈值压缩为 summary 片段  
**边界：** 不删除 **ai_ir_events**；只裁剪 Prompt 上下文

## 15. 六条质量生命线（阶段七 MUST）

| # | 维度 | 阶段七增量 |
|---|---|---|
| **1 日志** | Eval 每层 `EvalPhaseStart/Complete`；Judge 输入输出 hash 入日志（非全文） |
| **2 边界** | L1 Schema 失败不跑 L4；无 skill_run 不可 review |
| **3 性能** | Eval 异步队列；L4 Judge 单 run ≤30s |
| **4 内存** | Eval 批处理分页读 events，避免一次加载全表 |
| **5 隔离** | 质量榜按 tenant 过滤；review 不可跨 tenant |
| **6 LLM** | **仅** L4 Judge 允许 LLM；maxCalls=1 fast；禁止 Eval 绕过 Guard |

**本节核心表清单：** **ai_skill_runs**、**ai_ir_events**、**ai_skill_reviews**（新）、**ai_skill_llm_policy**

**本节关键代码路径索引：** `SkillExecutionLogger.cs`、`ContextBuilderService.cs`、`SkillLlmBudgetGuard.cs`
