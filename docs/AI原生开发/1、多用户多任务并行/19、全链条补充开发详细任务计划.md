## 0. 宪法级铁律（违反 = 该步未完成）

### 0.1 零 simulate · 零 mock

| 禁止项 | 范围 | 处置 |
|--------|------|------|
| `POST /api/studio/ir/{id}/simulate` | **产品主链、验收脚本、提交需求页** | **SUP-00**：生产环境 403；Dev 环境仅允许 `Features:IrDevTools=true` 且**不得**进入主链 E2E |
| IR 观测台「模拟 SkeletonCreated / SA×9」按钮 | 提交需求页主路径 | **移除或移入独立 DevTools 页**，主链 UI 不得出现 |
| `phase2-skills-e2e.mjs` / `phase4-green-path.mjs` / `phase4-dod-verify.mjs` 等脚本中的 simulate | 全部验收脚本 | **重写**为真实 Skill 调用链；旧脚本标注「已废弃」，**不得**作为阶段完成判据 |
| `setupIr2Locked` / `setupIr1Stable` 等 simulate 辅助函数 | `scripts/lib/phase4-api.mjs` | **删除**或仅留单元测试隔离目录，**禁止**被 E2E import |
| Skill **silent fallback**（`BuildFallbackArchitecture` 等 LLM 失败静默模板） | 产品主链 | LLM/SA 失败 → **run failed + 用户可见错误**，**禁止**无标注规则回退冒充真实产出 |
| 阶段确认只改 `CurrentStage` 不调 Skill | ConfirmStage | **已禁止**（SUP-01a） |
| 仅 append IR 事件无交付物文件 | 任意步骤 | **禁止**（SUP-01c 起强制落盘） |

**唯一例外（非产品主链）：** `backend/tests/` 下**隔离单元测试**可用内存 SQLite + 手工构造 `AppendIrEventRequest` fixture——**不得**调用 simulate HTTP API，**不得**冒充 E2E 验收。

### 0.2 三条验收铁律（逐步验，逐步过）

| 铁律 | 判定 |
|------|------|
| **真实输入** | 来自上一步 **落盘产物**（`deliverables/*` 或 IR 快照 stable）；**禁止 simulate、禁止手写假 JSON、禁止 mock 服务** |
| **真实产出** | 用户在提交需求页**能打开**（说明书 / DDL / UI 预览 / 代码目录 / 试用 URL） |
| **Skill 不空跑** | `ai_skill_runs` 有记录 + `BASE_AI_CALL_LOG` token>0（或 SA step duration>0）；只改 stage = 空跑 |

### 0.3 核心结论（根因）

前四阶段**基础设施真实可用**（IR、Skill、Orchestrator、沙箱 API 均在），但存在三条结构性缺陷：

| # | 缺陷 | 证据 |
|---|------|------|
| **C1** | 主链未焊接 | `ConfirmStageAsync` 曾只 stage+1（`PipelineEngineService.cs:99`）；**SUP-01a 已接线**，待真实 E2E 验收 |
| **C2** | 产出未落盘 | DDL/说明书只进 IR payload（`DbDesignSkillService.cs:58`）；无 `deliverables/` |
| **C3** | 主路径依赖 simulate | `phase2-skills-e2e.mjs:47`、`phase4-green-path.mjs` 的 `setupIr2Locked`；**SUP-00 必须首先消灭** |

## 0.4 架构决策（评审确认）

### Orchestrator 职责边界

| 层级 | 职责 | 不负责 |
|------|------|--------|
| **`PipelineProductOrchestrator`**（SUP-01b） | 按阶段**调度** Skill；返回 runId/任务名 | **不**读写 IR；**不**落盘交付物 |
