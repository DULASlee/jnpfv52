### 问题 5：用户输入框无第一响应 + 无智能判断 🟡 P1（新增需求）

**现状**：用户在输入框打字，前端按固定的 `handleSend` 逻辑走，没有"理解用户意图再路由"的能力。比如用户在 PM 追问等待时打"确认"，系统不知道这是"确认"还是"回答追问"。

**要求**：
- 用户任何时候在输入框打字 → 第一时间响应
- 但不盲从 —— 先经 **PM Skill 理解意图**（确认？修改？回答追问？推翻重来？），再决定路由
- 同样遵循铁律 2：意图判断交给带种子+提示词的 PM Skill，**不靠写死的关键词匹配**

### 改动 4：LLM 真流式（P4 修复）

```csharp

// systemPrompt 改为："先输出完善后的需求正文(markdown)，最后输出 ===META=== 后跟 JSON {notes}"
public async Task<RequirementEnhanceResult> EnhanceRequirementStreamAsync(
    SkillContext context,
    IReadOnlyList<PmClarificationTurn>? previousTurns,
    Func<string, CancellationToken, Task> onToken,  // 流式回调
    CancellationToken ct)
{
    var fullResponse = new StringBuilder();
    var metaBuffer = new StringBuilder();
    var inMeta = false;

    await foreach (var json in _llm.ChatStreamAsync(request))
    {
        var token = ExtractToken(json);
        if (string.IsNullOrEmpty(token)) continue;

        if (token.Contains("===META===")) { inMeta = true; continue; }
        if (inMeta) { metaBuffer.Append(token); continue; }

        fullResponse.Append(token);
        await onToken(token, ct);  // 逐 token 推 SSE → 用户看到打字

        EnhancedText = fullResponse.ToString(),
```

### 改动 5：用户输入框第一响应 + PM 智能意图判断（P5）

**后端**：新增 PM 意图判断方法（PmSkillService）

```csharp
public async Task<UserIntentResult> ClassifyUserIntentAsync(
    SkillContext context, string userInput, string currentStatus, CancellationToken ct)
{
    // PM Skill 基于 种子+提示词 判断用户输入的意图
    // currentStatus = "awaiting-clarification" | "awaiting-spec-confirm" | "idle"
```

**前端**：`handleSend` 不再固定路由，而是把用户输入发给后端，后端 PM 判断意图后路由。

### 改动 6：新流程补 Finalize（删旧流程的前置条件）⚠️ 关键缺口

**现状**：新流程 `RunPmPipelineAsync` 步骤④ `RenderSpecAndWaitConfirmAsync` 只渲染说明书等确认，**确认后什么都不做** —— 没有 PM 终评、没有 Analyst Finalize、没有 StageConfirmed、不触发架构设计。

**旧流程确认后做了什么**（要迁移）：
```
RunRoundAnalystAsync(enableFinalization:true)
  → analyst-skill 跑 Finalize
  → IR: AnalysisCompleted { finalized:true }
  → StageConfirmed → 可进入架构设计
```

**修复**：新增步骤⑤（确认后落库）


## 七、端到端验证（最终标准）

不再以"编译通过""测试绿"为完成标准。**唯一完成标准：在界面上看到新流程端到端跑通。**

```
1. 输入需求 → 门控通过 → 看到 PM 流式打字完善需求（逐 token，非卡死）
2. PM 追问 → 流式打字背景说明 + 多选/矩阵题卡片（多选有"其他"，矩阵无"其他"）
3. 用户选答案/打"其他"文本 → 提交 → PM 继续流式输出
4. 步骤②③ → thinking 区折叠显示 SA 九步拆解进度
5. 需求说明书 → 流式打字 markdown + 确认/修改按钮
6. 点"确认" → PM 终评 + Finalize → 进入架构设计阶段
7. 点"修改" + 打字反馈 → PM 理解意图 → 重跑①②③ → 新说明书
8. 全程：用户任何时候在输入框打字 → PM 第一时间理解意图并响应
9. 无骨架确认卡片、无旧三轮循环、无 UseNewPipeline 开关
```
