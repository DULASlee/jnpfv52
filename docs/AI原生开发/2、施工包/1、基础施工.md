### 二、A4 文件上传适配方案

**背景**  
`SandboxManager.UploadFilesAsync` 当前签名接收 `List<GeneratedFile>`（内存对象），但 development 阶段产物已落盘为 `generated/` 目录下的实际文件。需要一个适配层将目录文件转换为 `List<GeneratedFile>`。

**实施方案**  
在 `PipelineOrchestratorService` 内新增私有方法 `ReadGeneratedFilesFromDirectory`，不修改 `SandboxManager` 的公开接口。

**示例代码（伪码，不直接用）**
```
private List<GeneratedFile> ReadGeneratedFilesFromDirectory(string generatedDir)
{
    var files = new List<GeneratedFile>();
    foreach (var filePath in Directory.GetFiles(generatedDir, "*", SearchOption.AllDirectories))
    {
        var relativePath = Path.GetRelativePath(generatedDir, filePath);
        var content = File.ReadAllBytes(filePath);
        files.Add(new GeneratedFile { FileName = relativePath, Content = content });
    }
    return files;
}
```

**调用时机**  
流水线进入 development 阶段后，调用 `ReadGeneratedFilesFromDirectory(generatedDir)` 得到文件列表，再传递给 `_sandboxManager.UploadFilesAsync(sandboxId, files)`。

**为什么不在 `SandboxManager` 中扩展 `UploadDirectoryAsync`？**  
- `SandboxManager` 作为基础设施，保持无文件系统依赖更好。
- 仅此一处需要目录转文件，封装在业务层足够。
- 若未来多处在业务层出现同样需求，再提取为 `SandboxManager` 的辅助方法。

**工期**  
已包含在 A4 原有 1.5 人日内（目录递归及文件读取逻辑极简单）。
