# JNPF AI 原生开发平台 Phase A/B/C 完整工作总结

---

## 一、项目总体目标

在 JNPF 手工低代码平台基础上，构建一个**独立的、完整的 AI 原生低代码开发平台**。两个子系统产物物理隔离、能力相互调用、质量标准统一。AI 平台的核心差异化竞争力：需求说明书、架构设计说明书、总体详细设计说明书三阶段人类确认后，开发→测试→部署→再测试→再开发→再部署全自动闭环。

---

## 二、总体架构原则

| 原则                   | 说明                                                         |
| ---------------------- | ------------------------------------------------------------ |
| **双轨并行，物理隔离** | 手工平台产物落 `CodeGenerate/`，AI 平台产物落 `StudioWorkspace/{tenantId}/{pipelineId}/`，互不写入 |
| **三阶段人工确认**     | 需求说明书、架构设计说明书、总体详细设计说明书需人类确认，此后全自动 |
| **工具共享层**         | AI 平台可调用手工平台的 `CodeGenService` 生成代码，产物入 AI 工作区 |
| **代码同构**           | AI 生成的 Entity/Service/Controller/Vue 与手工平台产物完全同构，可读、可改、可二开 |
| **沙箱即运行时**       | Docker 沙箱提供编译验证 + 运行预览 + 自动化测试的独立环境    |
| **交付闸门**           | 开发态不自动写入主仓库，交付时打 zip 手动集成，与手工平台流程一致 |

### 4.3 B2 — 沙箱并发队列

| 任务   | 内容                                                         | 涉及文件            |
| ------ | ------------------------------------------------------------ | ------------------- |
| **B2** | 将 `SemaphoreSlim(5)` 替换为 `_activeCount + ConcurrentQueue`——并发满不抛异常，请求自动排队；后台 `ProcessQueueLoopAsync` 500ms 轮询调度；5 分钟排队超时；SSE 推送 `sandbox_queued`、`queue_position`；Dispose 清理所有排队请求 | `SandboxManager.cs` |

**并发控制模型**：
```
CreateAsync:
  if _activeCount < MaxConcurrent(5)
    → Interlocked.Increment → 创建容器 → 返回
  else
    → 入队 ConcurrentQueue → SSE sandbox_queued → TaskCompletionSource 等待

ProcessQueueLoopAsync:
  每 500ms 检查 _activeCount < 5 && 队列非空 → 取出执行
  超时 5min → TrySetCanceled → SSE sandbox_timeout

Dispose:
  while TryDequeue → TrySetCanceled → 全部清理
```

### 5.2 C2 — 完整系统代码生成（地基）

**核心目标**：AI 生成的系统从登录→菜单→页面→表单→数据→权限→字典，全链路完整可运行，不依赖手工平台做任何人工补充。

**代码生成范围（11 层产物）**：

| 层级   | 产物                  | 生成方式                | 落地位置                              |
| ------ | --------------------- | ----------------------- | ------------------------------------- |
| 数据层 | SQL 建表脚本          | 调手工 `CodeGenService` | `generated/sql/`                      |
| 数据层 | Entity 实体类         | 调手工 `CodeGenService` | `generated/Net/Models/Entity/`        |
| 数据层 | Dto 输入输出类        | 调手工 `CodeGenService` | `generated/Net/Models/Dto/`           |
| 服务层 | Service 业务逻辑      | 调手工 `CodeGenService` | `generated/Net/Controller/{表名}/`    |
| 接口层 | Controller API        | 调手工 `CodeGenService` | `generated/Net/Controller/{表名}/`    |
| 前端层 | .vue 页面文件         | 调手工 `CodeGenService` | `generated/html/PC/{表名}/`           |
| 配置层 | 菜单配置 JSON         | AI 自主生成             | `generated/config/menus.json`         |
| 配置层 | 权限配置 JSON         | AI 自主生成             | `generated/config/permissions.json`   |
| 配置层 | 字典配置 JSON         | AI 自主生成             | `generated/config/dictionaries.json`  |
| 配置层 | 组织配置 JSON（按需） | AI 自主生成             | `generated/config/organizations.json` |
| 路由层 | 前端路由注册          | AI 自主生成             | `generated/config/routes.ts`          |

**关键策略**：代码层调手工平台成熟生成器（保证同构），配置层 AI 自主生成（手工平台无对应生成器）。

**已查清的 5 个关键模糊点**：

| 模糊点                  | 结论                                                         |
| ----------------------- | ------------------------------------------------------------ |
| CodeGenService 调用方式 | DI 注入 `ITransient`，`DownloadCode(string id, DownloadCodeFormInput)` 直接调用，不走 HTTP |
| VisualDevEntity 结构    | 23 字段，3 层继承，无 TenantId，5 个必填字段                 |
| Tables/FormData JSON    | 精确 Schema——`DbTableRelationModel[]` + `FormDataModel{areasName, className[], fields[]}` |
| 临时记录清理            | `finally` 删除 + Hangfire `RecurringJob` 每日清扫 24h+ 孤立记录 |
| HTTP Context 依赖       | 零依赖——`DownloadCode` 不访问 `HttpContext`，后台调用完全安全 |

**关键约束发现**：`DownloadCode` 输出路径硬编码为 `CodeGenerate/{fileName}/`，C2 策略调整为"生成后移动"——生成 → 复制到 `StudioWorkspace/{tenantId}/{pipelineId}/generated/` → 清理临时目录，`fileName` 使用 `{pipelineId}-{timestamp}` 防并发碰撞，移动过程先复制到 `.tmp/` 再 `Directory.Move` 保证原子性。
